## What this is

An umbrella for the WS12 items after Phase 1, plus the two late WS1 clean-up items. When promoted to `plan/`, the planning agent replaces it with one ticket per item whose prerequisites are on the board, parks the rest as a new backlog ticket `debt-ws12-hygiene-later`, and deletes this file.

**Promote when** gate G1 holds, for `hygiene-silverlight-conditionals`; the rest wait on WS6 and WS9 tickets existing.

## Work items

- `hygiene-silverlight-conditionals` — remove the `#if SILVERLIGHT` branches (the plan counts 46 in 26 files). The `AllowSilverlightClients` setting is already gone: `protocol-corewcf-host-prepare` removed it, and its migration-notes entry is "done". Needs `test-harness-inprocess`.
- `hygiene-retire-web-silverlight-client-types` — the Frontend library still describes the two deleted clients: `libraries/Frontend/Documents/Register.d4` inserts `Web` and `Silverlight` rows into `ClientTypes` (old path `Libraries/Frontend/Documents/Register.d4` ~lines 291–292), and the library ships `Silverlight.NodeTypes.dnt` and `Web.NodeTypes.dnt`, which map node names to the deleted `Alphora.Dataphor.Frontend.Client.Silverlight` / `.Web` assemblies (also listed in `Setup/Files.wxs`). Remove the rows and the two documents together, with a migration-notes line: an application that reads `ClientTypes`, or a catalog rebuilt from scripts, will see two fewer client types. Left in place by `repo-delete-dead-trees` because it changes a library's catalog data and document set. No prerequisite.
- `hygiene-remove-rest-leftovers` — delete `src/engine/DAE/REST/RESTResult.cs` and `src/engine/Server/REST/RESTMarshal.cs`, their `Compile` entries in `DAE.csproj` and `Server.csproj`, and the `Newtonsoft.Json` package reference in `Server.csproj` that only `RESTMarshal.cs` needs (the project file’s own comment says so; `DAE.NativeCLI.csproj` references the package for its own reasons and keeps it). Nothing in the repository calls either type - verified 2026-11-21, the only files mentioning `RESTResult` or `RESTMarshal` are the two themselves - and their only consumer was the web prototype now parked in `legacy/`. Both types are public, so a custom C# extension could in principle call `RESTMarshal`: needs a `docs/migration-notes.md` line. Found by `test-coverage-report-tool`, which excludes the two paths from the coverage area map until they go (`tools/coverage-report/areas.json`, the `excluded` list, which names this arm) - drop that exclusion in the same change. No prerequisite.
- `hygiene-remove-dead-compiled-files` — delete three source files that are compiled and referenced by nothing, with their `Compile` entries: `src/engine/Base/IndexList.cs` (`public class IndexList`, a keyed list over a node tree) and `src/engine/Base/TemporaryStream.cs` from `Base.csproj`, and `src/engine/DAE/Streams/CopyOnWriteStream.cs` from `DAE.csproj`. Verified 2026-11-21 by `test-coverage-gap-analysis`, which found all three at 0 % over 494 coverable lines on the full instrumented run and then grepped the repository: outside each file itself, the only mention of its type anywhere is that `Compile` entry (`NativeRowIndexList` and `IndexedDictionary` are unrelated types whose names merely contain the string `IndexList`). Unlike the files `build-globbing-cleanup` lists, these three *are* compiled, so switching a project to default globbing will not drop them and no other arm owns them. All three types are public, so a custom C# extension could in principle use one: needs a `docs/migration-notes.md` line. `tools/coverage-report/areas.json` excludes the three paths from the coverage area map until they go, naming this arm - drop that exclusion in the same change. No prerequisite.
- `build-globbing-cleanup` (WS1) — delete source files no project compiles, then switch projects to default globbing. Needs `ui-dataphoria-port` and `device-connection-cleanup`, and also `library-frontend-web-leftovers`, which owns the Frontend set below. Named instances, from the `port-server-on-net10` audit of 2026-11-21 and its review, which diffed every compile list in `Dataphor.slnx` against the `.cs` files beside it: eight files in `src/engine/DAE` that `DAE.csproj` does not compile — `Runtime.Data/Index.cs`, `Runtime.Data/Scan.cs`, `Runtime.Data/TableBuffer.cs`, `Runtime.Data/TestValues.cs`, `Runtime.Data/UnimplementedTableValues.cs`, `Runtime.Instructions/GeneratorNodes.cs`, `Runtime.Instructions/TestNodes.cs` and `Runtime/DataVar.cs` — plus `src/protocol/Client/Server/ServerFactory.cs`, which `Client.csproj` does list but whose whole body sits inside a block comment, so it contributes nothing. Two library projects exclude source files as well, each with a comment in its project file naming the ticket that deletes its set: nine `System.Web` leftovers in `libraries/Frontend/Source/Frontend.Server.csproj` (`library-frontend-web-leftovers`) and six in `libraries/Connection/Source/DAE.Connection.csproj` (`device-connection-cleanup`). Delete each set before switching its own project to default globbing, not after: `Runtime.Instructions/GeneratorNodes.cs` still has `using System.Runtime.Remoting.Messaging;` and seven of the nine Frontend leftovers still use `System.Web`, neither of which exists on .NET 10, so globbing would pick up files that cannot compile.
