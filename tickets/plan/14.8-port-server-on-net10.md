## What this is

The last WS2 work item. Its scope in the plan is short — "whole server, including hosting, builds with nothing excluded; all server tests pass" — and the workstream's own closing condition is the real specification: *every engine-level and server-level test passes on .NET 10 and no code path reaches an API that throws `PlatformNotSupportedException`.*

By the time this runs, `protocol-corewcf-host` has brought the six excluded files back and `port-abandoned-session-cleanup` has settled what reclaims abandoned sessions. So this item is deliberately an audit plus a documentation correction, not new behaviour. Plan it as such: if the audit is clean, the implement ticket it emits is small, and if it is not, each finding is either fixed with its reproduction (a local, obvious defect, per the project rules) or becomes its own ticket.

## The audit

**Nothing excluded.** `src/engine/Server/Server.csproj` lists its sources explicitly and currently carries six `<!-- … until protocol-corewcf-host -->` comments plus an explanatory comment block above the compile list. Check that no exclusion comment and no excluded file remains, in that project and in the others the hosting work touched, and that every file on disk under `src/engine/Server` that should be compiled is — the project rules warn that a file on disk is not necessarily compiled, and strays exist elsewhere in the tree.

**No API that compiles and then throws.** The sweep, over `src/engine/Server`, `src/engine/DAE`, `src/protocol` and the host projects: .NET Remoting (`RemotingServices`, `Activator.GetObject`, `GetLifetimeService`, `ISponsor`, `MarshalByRefObject` used for anything beyond an inert base class), `AppDomain` creation, `Delegate.BeginInvoke`, `Thread.Abort`/`ResetAbort`, `BinaryFormatter`, CodeDom compilation, code access security attributes, `System.Web` beyond `HttpUtility`, and `ServicedComponent`. As of writing the only match in these trees is in `src/protocol/Client/Server/ServerFactory.cs`, whose entire body is inside a block comment — so the expectation is a clean sweep, and the point of running it is that the hosting work may have reintroduced something. Report what the sweep actually found, not what it was expected to find.

**No warning silenced to get there.** `Directory.Build.props` and the project files carry no `NoWarn` today. Confirm that none has appeared, and that nothing suppresses `WFDEV006`, a `SYSLIB*`, `CS0618`, `CA1416` or `NU1900`–`NU1904`. The project rules make this a hard line: on .NET 10 a removed API can compile and throw at run time, and the warning is the only notice.

**The tests pass.** Build, then run the three suite parts from the root `AGENTS.md` as separate foreground commands — never `dotnet test Dataphor.slnx` as one command, which exceeds the runner's ten-minute idle limit on a slow machine. Account for the coverage manifest: a script that now passes must have its entry flipped in the same commit, and any entry still naming a ticket that has landed is a finding.

- `docs/modernization-plan.md` — the WS2 section's "Current state" paragraph says the server compiles only once WCF hosting types are stubbed; the WS2 table's rows; the WS5 table; the known-defects table (any K-item the chain resolved); and the Appendix A spike expectations.
- `docs/architecture.md` — the "What is alive" table's last row, "Cannot survive .NET 10 as written: WCF self-hosting, COM+ transaction class, Windows service installer class".
- `AGENTS.md` — the "Converted so far" line, which says Server is converted "without its WCF service and host classes"; the "Runtime layout" paragraph's statement that `bin/` has no host and nothing runs from it; and the net-spike expectations, which name `DataphorServiceHost` as the reason the client, UI, IDE, `DAEServer` and `DAE.Service` fail to build. Re-measure the spike rather than editing that line from reasoning: `python tools/net-spike/run.py <work-dir> --smoke` with a work dir outside the repository. Several of those projects (`DAE.Client`, the UI, the IDE) will still fail for WS6 reasons, so the line needs rewriting, not deleting.
- `tools/net-spike/README.md` if it carries the same expectations.
