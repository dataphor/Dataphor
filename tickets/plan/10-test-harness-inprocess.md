## Goal

Give the project one command (`dotnet test`) that boots the Dataphor engine in-process, isolated from the machine, and runs every D4 coverage script in `tests/libraries/TestFramework.Coverage.Scripts/Documents`, each as its own NUnit test case, against a checked-in **manifest** that states what each script is expected to do. This is layer L1 of the plan's test suite and the safety net every later Phase 1 ticket verifies its work against (`port-engine-runtime-fixes`, `port-catalog-emitter-race`, `store-sqlite-concurrency`, `test-decouple-coverage-base`, `build-ci` all wait on it). It also replaces the legacy fixture, which needs SQL CE (being deleted), writes to `%ProgramData%`, reads libraries from the source tree and, through the helper library, needs a SQL Server on `localhost`.

This ticket is the one that makes the test half of **gate G1** possible. G1 (plan, "Sequencing"): *from a clean clone, `dotnet build` and `dotnet test` pass on .NET 10 with every D4 coverage script accounted for.* After this ticket every script is accounted for in the manifest (as `pass`, or as `known-failure` naming a ticket); `test-decouple-coverage-base` and `test-triage-known-failures` then replace the provisional entries with real causes.

**Server behaviour relevant to isolation:**

## Open choices for the planner

Settle each one, and record the choice and the tradeoff in the implement ticket(s).

1. **Manifest format and location.** It must be diff-friendly (one line or one small record per script), readable without tooling, and carry per script: status (`pass` | `known-failure`), for `known-failure` the ticket slug and the expected error, and optional run options (the `SecurityLibrary` implicit-transaction preamble). Candidates: a text or JSON file beside the test project (`tests/DAE.Server.Tests/`), or beside the scripts in `tests/libraries/TestFramework.Coverage.Scripts/` (that folder is a library and gets copied into the layout). Recommended: beside the test project, so the layout carries only the library.
2. **How expected errors are matched.** Options: D4 error code (six digits; the first three are the source prefix listed in `Error Message Prefix Codes.txt`, under `Dataphor/` before the move) where the exception carries one; exception type plus a message substring; a regular expression. Never the full message text. Define what happens when a `known-failure` script **passes** (recommended: the run fails, so the manifest is corrected — otherwise fixes go unnoticed) and when it fails **with a different error** (the run fails). State how a matched expected failure is reported so it stays visible and counted in `dotnet test` output (for example the NUnit `Warning` or `Inconclusive` outcome with the slug in the message) without breaking the run.
3. **How a test case identifies the script.** Default: one NUnit case per script name via `TestCaseSource`, test name = script name. The source must enumerate the script files in the layout's copy of `TestFramework.Coverage.Scripts/Documents` and the manifest; a file with no manifest entry and a manifest entry with no file each produce a **failing** case, and a missing or empty layout folder produces a failing case rather than zero cases. Decide how the test assembly finds `artifacts/layout/<Configuration>` at discovery time (recommended: an MSBuild-generated `AssemblyMetadata` value, so a bare `dotnet test` works with no environment variable).
4. **Server lifetime and script order.** One server per fixture with all scripts in sequence (the legacy and spike behaviour; about 1 s start plus library registration), or one per script (slow, but no interference). Scripts leave objects behind, so with a shared server results can depend on order; the spike ran them in `CoverageTest.cs` order. Pick an order, make it deterministic, and decide whether the acceptance check also runs once in reverse to expose interference.
5. **Library directories.** Copy the needed libraries from the layout into the fixture's temp directory (what the spike does; costs a copy, guarantees the layout is never written) versus `LibraryDirectories = "<temp>\libraries;<layout>\Libraries"` with the temp directory first so `General/` lands there (cheaper, but `.d4l` rewrites by library operators would hit the layout). Recommended: copy. Name which libraries the fixture needs; today that is the closure listed above, and `MSSQLDevice` drops out after `test-decouple-coverage-base`.
6. **Logging.** Disable engine logging in the fixture (`LoggingEnabled = false`) to keep the Windows event log untouched when elevated, versus keeping the instance log file for diagnosing failures and stopping only the event-log writes (a server code change: name the site and whether it is a setting). Recommended: disabled by default, with an opt-in switch (environment variable) for diagnosis.
7. **NUnit package versions** under central package management: NUnit 4 (then `Common.Tests` needs `ClassicAssert`, a mechanical edit) or NUnit 3.14 (no edit, older line); matching `NUnit3TestAdapter` and `Microsoft.NET.Test.Sdk`.
8. **Reproducing the spike first as the acceptance check.** Recommended yes: before adding the 59 never-run scripts, run the same 76 with the same options as the spike and confirm 62 pass and the same 14 fail for the same reasons; a difference is investigated (K1/K10 not yet landed, order, stack size) before the manifest is written. Then run the 59 and record them.
9. **Project shape.** Rework `tests/DAE.Server.Tests` in place (keeps history) or start a new project and delete the old one. Recommended: in place, deleting `CoverageTest.cs`'s hand-written methods in favour of the data-driven source.
10. **Catalog store connection string.** The spike's (`Journal Mode=WAL;BusyTimeout=30000`) or the store's default. Recommended: the spike's, so the baseline matches; `store-sqlite-concurrency` revisits it.
