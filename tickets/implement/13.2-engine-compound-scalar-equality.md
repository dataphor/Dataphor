## Defect

A scalar type with one representation of several properties and no equality operator of its own gets a generated `iEqual` implemented by `System.CompoundScalarEqualNode` (`src/engine/DAE/Compiling/Compiler.cs` about line 5280). `CompoundScalarEqualNode.DetermineDataType` (`src/engine/DAE/Runtime.Instructions/RowComparisonNodes.cs` line 261) pushes the left operand's row as `new Symbol(Keywords.Left, …)` but the right operand's row as `new Symbol(String.Empty, …)`. The expression it then compiles, `Compiler.BuildRowEqualExpression(plan, Keywords.Left, Keywords.Right, …)`, refers to `right.<property>`, which cannot resolve:

```
if not(Degrees(10, 5, 12.4) = Degrees(10, 5, 12.4)) then raise Error("eq");
-- CompilerException: Unknown identifier "right.Degrees".
```

The same class's `InternalBindingTraversal` (line 319) and the sibling `RowEqualNode` (line 75) already push `Keywords.Right`. Tag `v3.1` has the same line, so this never worked on 3.1; fixing it only makes rejected code compile, so no migration note is needed.

## Fix (verified in the fix stage)

Line 261, under `#if USENAMEDROWVARIABLES`: `new Symbol(String.Empty, …)` → `new Symbol(Keywords.Right, …)`. With only that change, `dotnet test tests/DAE.Server.Tests --filter Name=Types.Coordinate` reports the script as unexpectedly passing, so the whole script runs, including line 69 (`Degrees.AsString(…) = Degrees(…)`) and the nested `Coordinate` type whose equality calls the inner `Degrees` equality. The property-named-like-the-type case (`Degrees.Degrees`) resolves correctly. The fix-stage experiment was reverted; the file is unchanged on disk.

There is no compound-scalar compare or sort node: only equality is generated for compound types (grep `CompoundScalar` under `src/engine`), so nothing else shares the defect.

Because `Types.Coordinate` passes end to end and exercises the failing line, it is the reproduction test; no new coverage script is needed.

Source hygiene: the file is UTF-8 without a byte-order mark, with CRLF line endings and tabs. Edit it with the Edit tool; a `sed -i` edit converted it to LF in the fix stage.
