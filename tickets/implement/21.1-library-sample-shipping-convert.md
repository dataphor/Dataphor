## What this is

`samples/Sample.Shipping` is the one sample library with C# of its own: `Source/Shipping.csproj`, three source files (`Coordinate.cs`, `Domains.cs`, `Register.cs`) and an `AssemblyInfo.cs`, building `Alphora.Shipping.dll`. The project is still in the .NET Framework format, so it is not in `Dataphor.slnx`, the assembly is not built, and `tools/layout/Layout.csproj` therefore removes `samples/Sample.Shipping/Sample.Shipping.d4l` from the libraries it assembles - registering the library would fail on the missing assembly. The exclusion names this ticket.

The conversion itself is the ordinary one described in `AGENTS.md` under *Converting another project*. The project references Base, DAE, Server, the Connection library and the shared SQL device library; it has no embedded resources and no package references, and its only non-default settings are the assembly name `Alphora.Shipping` and the root namespace `Shipping`.

**What it does not do is make the sample an ordinary test case.** `Sample.Shipping.d4l` requires `MSSQLDevice` and carries `settings="'ServerName'='.';'DatabaseName'='Shipping'"`, and `Documents/Schema.MSSQLDevice.d4` creates a SQL Server device, so registering the library needs a running SQL Server either way. `tests/DAE.Server.Tests/SamplesCorpusTest.cs` holds three lists, each asserted against the tree in both directions, and today `Sample.Shipping` is in `NotInTheRuntimeLayout`. Once the build assembles it, that entry is wrong and `EverySampleIsAccountedFor` fails - which is how the conversion gets noticed - so the same change **moves the entry to `NeedsADatabaseServer`**, with a reason in the style of the two entries already there (`Sample.Forum`, `Sample.Pubs`). The comment at `NotInTheRuntimeLayout` already says this is what should happen.

`tests/DAE.Server.Tests/FormCustomizationTest.cs` has an entry for the sample too, in `LibrariesNotCarried`, whose reason reads "is not in the runtime layout (its C# project is not converted)". That becomes untrue: the library is still not carried by `FrontendFixture`, but now because it needs a SQL Server, which is what the `Sample.Forum` entry beside it says. Correct the reason; do not remove the entry.

## Edge cases & interactions

- **Three `Compile` items plus `AssemblyInfo.cs`, and the resource rules do not apply.** There are no `.resx` files and no embedded resources, so none of the `DependentUpon` or resource-naming care that other conversions needed. `Source/Shipping.d4`, `Source/Shipping.tsql` and `Source/CoverageRoles/*.d4` sit in the same folder and are not compiled by anything; leave them where they are (`build-globbing-cleanup` owns stray files, and `ParserRoundTripCorpusTest` already has recorded entries for four of them).
- **`Register.cs` registers class names, which are a compatibility surface.** Read what `DAERegister.GetClasses()` returns and keep every alias string exactly as it is; the sample's `.d4` documents name them in `create operator ... class "..."` statements. Verified by inspection, not by a test: nothing in the suite registers this sample.
- **The layout check fires as soon as the exclusion goes.** `Sample.Shipping.d4l` lists `Alphora.Shipping.dll` and nothing else, so the build fails until the project is in the layout's Library list and produces that assembly name. Expect that to be the first error and the signal that the two halves are in step.
- **`SamplesCorpusTest` discovers samples by walking `samples/`,** so the case already exists; what changes is which list answers it. After the move the case still reports Inconclusive, so the pass's pass/skip counts shift by nothing except the reason text. The two assertions to watch are `EverySampleIsAccountedFor` and the one that refuses a sample appearing in more than one list.
- **A sample that needs a database server is not attempted at all today,** by an accepted tradeoff recorded at the `NeedsADatabaseServer` site (failing to reach an absent server costs 54.6 s). The new entry inherits that tradeoff; do not try to make this sample register. `test-device-live` owns turning those entries into "attempt when a database server is configured".
- **`StoreRebuildWorkflowTest` names this sample** in its remarks as one of the libraries that stay out because they need a SQL Server. That stays true and needs no edit here.
- **No new test.** The conversion is wiring, and the two list edits are what the existing assertions already demand - the suite fails without them and passes with them, which is the whole verification. The project rules' characterization-test requirement applies to a subsystem being ported or re-hosted; this ports no behaviour. Say so in the handoff, and say plainly that the sample's own registration is still unproved on .NET 10 because no server in the suite can carry it.
- **A migration note is owed only if a public type or member changes.** The three source files are not edited, so none does; the sample's assembly simply ships again. Mention in the handoff that you checked and decided none is owed.
