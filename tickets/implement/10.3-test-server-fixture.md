# Isolated in-process server fixture for DAE.Server.Tests

Second of three tickets that make up `test-harness-inprocess` (after `test-common-tests-sdk`, before `test-harness-inprocess`, which keeps the slug and adds the coverage-script runner and manifest). This ticket converts `tests/DAE.Server.Tests` to an SDK-style project, gives it the reusable isolated-server helper the coverage runner will also use, ports the portable tests and deletes the machine-dependent ones (K18).

## Constraints (from the plan, WS3 "Cross-cutting requirements", and the rules)

- Each fixture gets a fresh temporary instance directory and reads libraries from the runtime layout, never from source folders; no test touches `%ProgramData%`, the registry or a fixed port.
- A running server writes into its library directory (creates `General/`, rewrites `.d4l` files, creates library folders), so the helper points `LibraryDirectories` at a **copy** of the library folders it needs, never at `artifacts/layout` or the repository (AGENTS.md "Rules that are easy to break"; `build-runtime-layout` mirrors the layout on every build, so a server pointed there would see its state change under it).
- Pass absolute paths: relative library directories are resolved through `PathUtility`, which is unreliable on .NET 10 (K22).
- `ServerConfiguration.ApplyTo` (`src/engine/Server/Server/ServerConfiguration.cs`) does not pass `PortNumber`, and an in-process `Server` opens no port. Do not set `PortNumber` (the legacy fixture and the spike set 8061).
- With logging enabled, `Server.StartLog` and `Server.LogMessage` (`src/engine/Server/Server/Server.cs`) create the Windows event-log source and write to the event log when the process is elevated (as on GitHub-hosted runners). `Engine.LoggingEnabled` (`src/engine/DAE/Server/Engine.cs`, settable only while stopped) turns off both the event log and the instance log file.
- Never edit test logic or expected values while porting; never suppress `SYSLIB`/`WFDEV` warnings.

## Design (settled)

**Project file** (`tests/DAE.Server.Tests/DAE.Server.Tests.csproj`), SDK-style, following the conventions `test-common-tests-sdk` set (packages from `Directory.Packages.props`, no shared tests props, `IsPackable` false, `DefineConstants` outright: legacy Release had `TRACE`, so `TRACE` / `DEBUG;TRACE`). Keep the file's byte-order mark and CRLF.

- `Compile` items: `CatalogStoreTest.cs`, `CursorTest.cs`, `InProcessTestFixture.cs`, `InternalCoverageTests.cs`, `TestEnvironment.cs`, `TestServerInstance.cs`, `Properties\AssemblyInfo.cs`. **Not** `CoverageTest.cs`: it stays on disk, uncompiled, for one ticket, because the spike's `--coverage` mode reads it (`tools/net-spike/run.py`); `test-harness-inprocess` deletes it together with that mode.
- `ProjectReference`: `src/engine/DAE/DAE.csproj`, `src/engine/Server/Server.csproj`, `src/engine/Store.SQLite/DAE.SQLite.csproj` (Base and Base.Windows arrive transitively; reference them only if the compiler needs them directly). Drop the legacy references to `Client`, `DAE.Client`, `Store.MSSQL` and the SQL CE project.
- `ProjectReference Include="..\..\tools\layout\Layout.csproj"` with `ReferenceOutputAssembly="false"` and `Private="false"`, so that `dotnet test tests/DAE.Server.Tests` (and Visual Studio's test run) builds the runtime layout first instead of running against a stale or missing one. Both are `net10.0`, so the reference resolves (the `NOTE:` in `Layout.csproj` about `net10.0-windows` does not apply).
- `<AssemblyMetadata Include="DataphorLayoutDir" Value="$(DataphorLayoutDir)" />`: the layout path for the configuration being built, read at run time with `Assembly.GetCustomAttributes<AssemblyMetadataAttribute>()`. `DataphorLayoutDir` is defined in the root `Directory.Build.targets` and is final when items are evaluated (`build-runtime-layout`). Never spell the layout path in code. Tradeoff accepted: the test assembly embeds an absolute build-machine path; it is a test assembly, never shipped, and determinism across machines does not matter for it.
- Add the project to the `/tests/` folder of `Dataphor.slnx`.
- `Properties/AssemblyInfo.cs`: delete `AssemblyConfiguration`, `AssemblyCompany`, `AssemblyProduct`, `AssemblyCopyright`, `AssemblyTrademark`, `AssemblyCulture`, `AssemblyVersion("3.1.*")` and their template comments; keep `AssemblyTitle`, `AssemblyDescription`, `ComVisible`, `Guid`, the byte-order mark, CRLF.

**`TestEnvironment`** (static, new file):

- `LayoutDirectory`: from the `DataphorLayoutDir` assembly metadata; `LibrariesDirectory` = `<layout>\Libraries`. If the metadata is missing or the folder does not exist, throw an exception that names the expected path and says to run `dotnet build Dataphor.slnx`.
- `RunDirectory`: created once per test process, `Path.Combine(Path.GetTempPath(), "Dataphor.Tests", "<process id>-<8 random hex>")`. On first use, delete (best effort, errors ignored) any sibling folder whose process-id prefix names no running process: these are left by earlier runs that could not delete their folders (see edge cases). Tradeoff accepted: a reused process id keeps a stale folder until a later run.
- `NewDirectory(string name)`: a fresh, uniquely named subfolder of `RunDirectory`.
- `KeepFiles` / `LoggingEnabled`: both true when the environment variable `DATAPHOR_TEST_LOGGING` is `1`. Opt-in for diagnosis: the engine then writes its instance log file under the temporary instance directory, directories are not deleted afterwards, and their paths are written with `TestContext.Progress`. Documented in AGENTS.md together with its cost: when the process is elevated, the server then also creates and writes the Windows event-log source, which the default run never does.
- `CopyLibraries(string targetDirectory, IEnumerable<string> names)`: copies each `<layout>\Libraries\<name>` folder recursively; a name with no folder in the layout throws, naming it.

**`TestServerInstance`** (`IDisposable`, new file): one directory holding `Libraries\` (the copies) and `Instance\`, and one `Server` configured on it.

- Construction: `new TestServerInstance(string name, params string[] libraryNames)` copies the named libraries (none is valid: the `System` library is built into the engine, and the server creates `General\` in the empty library folder).
- Configuration: `ServerConfiguration { Name = name, LibraryDirectories = <abs>\Libraries, InstanceDirectory = <abs>\Instance, CatalogStoreClassName = "Alphora.Dataphor.DAE.Store.SQLite.SQLiteStore,Alphora.Dataphor.DAE.SQLite", CatalogStoreConnectionString = @"Data Source=%CatalogPath%\DAECatalog;Journal Mode=WAL;BusyTimeout=30000" }`, `ApplyTo(server)`, then `server.LoggingEnabled = TestEnvironment.LoggingEnabled` (before `Start`). The connection string is the spike's, so results compare with the spike's baseline; `store-sqlite-concurrency` revisits it. `store-remove-sqlce-references` later makes SQLite the server's default store; these explicit settings stay valid after that.
- Members: `Server` (the `Server` object, for `Start`/`Stop` and for `Engine.StopProcess`), `Directory`, `Connect()` (returns an `IServerSession` for `new SessionInfo("Admin", "")`), `ExecuteScript(string d4)` (one session and process, stopped and disconnected in `finally`).
- `Dispose`: stop the server if it is running (errors reported, not swallowed silently: write them with `TestContext.Progress` and rethrow only when no other exception is in flight), then delete the directory unless `KeepFiles`; a failed delete is written to `TestContext.Progress` and left for the next run's stale-folder cleanup.
- The coverage runner (`test-harness-inprocess`) adds a way to create an instance from a copy of a stopped instance's directory; do not build that here.

**`InProcessTestFixture`** (rewritten, same public shape so `CursorTest` compiles unchanged): `[OneTimeSetUp]` creates a `TestServerInstance` with `protected virtual string[] Libraries => []`, starts it, and runs `EnsureLibraryRegistered('<name>');` for each of `protected virtual string[] LibrariesToRegister => []`; `[OneTimeTearDown]` disposes it; `[SetUp]`/`[TearDown]` connect a session and start a process per test, as before; `Server`, `Session`, `Process`, `ExecuteScript(string)` and `ExecuteScript(string library, string script)` keep their meaning. The legacy fixture registered `Frontend` and `TestFramework.Coverage.Base` for every derived fixture; `CursorTest` needs neither (it creates its own tables on the default device), so the default is none.

## Edge cases & interactions

- **Layout missing or stale.** The `Layout.csproj` reference builds it before the test project; a missing layout (for example `dotnet test --no-build` after a clean) makes `TestEnvironment` throw with the path and the remedy, so every server test fails visibly; none passes vacuously. Verify once by hand (rename the layout folder, run, restore) and report.
- **Locked files.** A library assembly (`Assembly.LoadFrom` in `src/engine/Server/Schema/LibraryUtility.cs`) is loaded once per process from the first copy that registers it and stays mapped until the process exits; later copies of the same assembly are not loaded again. Measured in planning: after four servers in one process, the first copy's folder could not be deleted (`UnauthorizedAccessException` on `Alphora.Dataphor.Frontend.Server.dll`), the later ones could. Hence best-effort deletion plus the stale-folder sweep. Nothing in this ticket registers a library with an assembly (`CursorTest` registers none), but the coverage runner does.
- **Nothing outside the temporary folder.** Check by inspection that no code path in the fixture reaches `%ProgramData%` (`Server.InstanceDirectory` falls back to it only when unset; `InstanceManager` is not used), the registry, a port, or the event log (logging off). Then run the tests and confirm `%ProgramData%\Alphora` did not appear or change and that `artifacts/layout` has no new or changed files (`git status` does not see `artifacts/`; compare a recursive listing with timestamps before and after). The elevated-run check is in `test-harness-inprocess`.
- **Restart on the same instance** (`CatalogStoreTest`): the second `Start` reopens the SQLite catalog the first one created; a failure there is a real regression, not a fixture problem.
- **Teardown after a failed start.** If `Start` throws in `OneTimeSetUp`, `OneTimeTearDown` still runs; `Dispose` must cope with a server that never started and with a null instance.
- **Parallel execution.** NUnit runs these fixtures one at a time by default; add no `Parallelizable` attributes. Put a `NOTE:` on `TestServerInstance`: two servers in one process share static engine state (K1, the catalog emitter race, is one known case), so parallel fixtures need `port-catalog-emitter-race` first and a check of other statics.
- **Admin session.** Tests connect as `new SessionInfo("Admin", "")` (AGENTS.md).
