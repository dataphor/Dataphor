## What this is

Two separate pieces of the plan's WS8 work-item row `docs-contributing`, both small, both under `docs/`:

1. **A contributing guide** under `docs/contributing/`, the folder the plan's WS8 target tree asks for. There is nothing there today. `AGENTS.md` carries the build and test knowledge, but it is written for agents working tickets, not for a person who has just cloned the repository.
2. **Folding the two inherited plain-text files in `docs/reference/` into Markdown pages.** `docs/reference/CompilerDefines.txt` and `docs/reference/Error Message Prefix Codes.txt` were moved into `docs/reference/` unchanged by the repository reorganization and were deliberately left unconverted by `docs-convert-asciidoc`. They are the last two non-Markdown documents in `docs/`.

The plan's prerequisite, `build-core-sdk-projects`, landed long ago.

## Scope decision: the release checklist is WS9's, not this ticket's

The WS8 row for `docs-contributing` says "Build, test, layout, release checklist", and the WS8 target tree lists `contributing/ build, test, writing docs, release checklist`. But WS9 has its own work item for it - `release-checklist-and-changelog`, scope "Checklist, `CHANGELOG.md`, release workflow in CI", prerequisites `installer-msi` and `build-ci` - and WS9's own target section says "A release checklist in `docs/contributing/` (L8 tests, version bump, change log, artifacts)". Two rows claim the same page.

**Settled here: WS9 owns the release checklist.** It needs the installer and the release workflow to describe, and neither exists; a checklist written now would be a list of steps nobody can follow. This ticket creates `docs/contributing/` and leaves the release page to WS9's `release-checklist-and-changelog`, and removes "release checklist" from the WS8 row's scope so the overlap does not come back. Record that in the plan edit.

## The pages

Three, no more. Each is short; the point is that a newcomer can build, test and document without reading `AGENTS.md`.

- **`docs/contributing/README.md`** - the entry point. What you need (the .NET 10 SDK that `global.json` pins, and nothing else - no Visual Studio requirement, no Node, no pandoc; the Python documentation checks need only Python 3), which solution to open (`Dataphor.slnx` at the root; `Dataphor.sln` is the dead legacy solution and does not build), where build output goes (`artifacts/bin/<project file name>/<debug|release>/`, never into source folders), and a link to each page below. One paragraph on what this project *is* belongs in the root `README.md`, which already has it - link, do not repeat.
- **`docs/contributing/build-and-test.md`** - build, test and the runtime layout. The three commands (`dotnet build Dataphor.slnx`, the same with `-c Release`, `dotnet test Dataphor.slnx`) and roughly what each costs; that the whole suite is slow enough that you normally run a subset, and how to (`--filter`, `NUnit.Where`); the runtime layout the build assembles at `artifacts/layout/<debug|release>/`, what it is for (tests, a local run, and later the installer all start from the same files) and that `tools/layout/Layout.csproj` is its only writer; the environment variables that gate or diagnose tests - `DATAPHOR_TEST_LOGGING`, `DATAPHOR_TEST_MSSQL`, `DATAPHOR_TEST_PGSQL` - with one line each on what they turn on and that a pass without its variable says it was skipped rather than passing quietly; the coverage report and the benchmark program as things that exist and are run by hand, with links to their own documents; and that CI (`.github/workflows/build.yml`) runs the same build and test commands in Debug and Release on every push.
- **`docs/contributing/writing-docs.md`** - the replacement for the old `Documentation/AuthoringDocumentation.adoc`, which described a GitBook editing workflow for AsciiDoc sources that no longer exist and which `docs-convert-asciidoc` deliberately did not convert. What this page says: the documentation is GitHub-flavoured Markdown under `docs/`, UTF-8 with no byte-order mark, LF line endings, one paragraph per line with no hard wrapping; where each kind of page goes (the three converted guides, `reference/`, `architecture/`, `admin/`, `contributing/`); the two automated gates and how to run them locally - `python tools/docs-link-check/check_links.py docs` for links and anchors, and `python tools/docs-size-check/check_size.py` for the 1,500-word cap on every page under `docs/architecture/` - and that `.github/workflows/docs.yml` runs them; the architecture-page rule itself (a short root `architecture.md` plus one page per subsystem, split rather than grown); the `NOTE:` comment convention for a conditional concern or an accepted tradeoff; and that a change an application, a deployment script or a custom C# extension could notice gets an entry in `docs/migration-notes.md` in the same commit.

### Do not restate `AGENTS.md`

`AGENTS.md` stays the agent-facing operating manual and keeps the detail: which tests to run at which ticket stage, the five part-commands that run the whole suite without tripping the runner's idle timeout, the ticket workflow, the compatibility-surface list, the code-search configuration. A fact written in both places is a fact that will rot. So where these pages need that detail, **link to the section of `AGENTS.md`** rather than copying it, and say plainly at the top of `build-and-test.md` that `AGENTS.md` is the fuller reference. The newcomer-facing material above is the part `AGENTS.md` genuinely does not carry.

## The two reference files

### `CompilerDefines.txt` → `docs/reference/compiler-defines.md`

64 lines, one per behaviour switch, each in the ad-hoc form `#define NAME in <where> // <what it does>`, with the disabled ones commented out (`//#define …  (currently disabled)`). It is the index to the file-level `#define`s that `AGENTS.md` calls load-bearing.

Make it a Markdown page with a table: the define's name, where it is defined, whether it is on or off today, and what it does. Every one of the 64 lines must appear - including the disabled ones, which are the record of switches that exist and are off. Keep the names exactly as they are, `NILPROPOGATION` misspelling included; they are the identifiers in the source. Add a short summary paragraph saying what these are (per-file `#define`s plus the project-wide constants `Directory.Build.props` sets) and pointing at the plan's "Non-default compiler constants to preserve" paragraph for the project-wide set. Then delete the `.txt`.

### `Error Message Prefix Codes.txt` → merged into `docs/reference/error-codes.md`

These two overlap and disagree, which is the reason to merge rather than convert:

- `docs/reference/error-codes.md` (the converted page) has a two-column table, Prefix and a human source name, running 100-129 then 200-205. It is missing **130**, **206** and **207**.
- `docs/reference/Error Message Prefix Codes.txt` has 100-130 and 200-207, each naming the exception type rather than a human name.

Merge into one table on `error-codes.md`: prefix, the human source name, and the exception type. The result has 130 (`DAE.Store`), 206 (`Frontend.Client.Web.WebDAC.ControlsException`) and 207 (`Frontend.Client.Silverlight.SilverlightClientException`), which the Markdown page lacks today. Keep the existing summary paragraph about the six-digit shape. Then delete the `.txt`.

**Three constraints on this one.** First, **error codes are a compatibility surface** (`AGENTS.md`, *Compatibility surfaces*): no prefix may be renumbered, and no retired prefix may be dropped, because the file is the allocation record and a dropped prefix gets reused. Second, 204, 206 and 207 belong to the two browser clients that 4.0 removed; `1-repo-delete-dead-trees` decided they stay listed, so mark them retired-but-reserved rather than deleting the rows. Third, `AGENTS.md` line 161 names `docs/reference/Error Message Prefix Codes.txt` as *the* document for that compatibility surface, so that pointer must move to `docs/reference/error-codes.md` in the same commit - otherwise the rule names a file that does not exist.

## Edge cases & interactions

- **Dangling references to the two `.txt` files.** Measured at commit `e414e316`, the references are: `AGENTS.md` line 34 (the `docs/` layout row names both files), line 161 (the error-code compatibility pointer) and line 166 (`CompilerDefines.txt` is the index); `docs/modernization-plan.md` line 166 (the old → new path table: "WS8 converts them"), line 628 (the work-item row) and line 907 (file-level defines are catalogued in `CompilerDefines.txt`); and `Dataphor.sln` lines 8-9. Fix every one but the last.
- **Leave `Dataphor.sln` alone.** It is the legacy solution, it no longer builds (its .NET Framework projects reference the converted `net10.0` ones), and `build-remove-legacy-build` - an arm of `debt-ws12-hygiene-remainder` in `tickets/backlog/` - deletes it. A stale solution-item path in a dead file is not worth a cross-ticket edit; say so in the handoff so a reviewer does not read it as an oversight.
- **Index pages.** `docs/reference/README.md` lists seven numbered sections and `docs/README.md` mirrors that list. Neither lists the two `.txt` files today, so the merge needs nothing there - but `compiler-defines.md` is a new page and must be added to both, and `docs/README.md`'s *Misc* list has "3. Authoring Documentation" as **plain text** (the conversion deliberately left it unlinked because the page did not exist); point it at `contributing/writing-docs.md`. `docs/contributing/` needs an entry in the *Project documents* list of `docs/README.md` too.
- **The link checker is the completeness test.** Every new page and every repointed link is checked by `python tools/docs-link-check/check_links.py docs --pending tools/docs-convert/legacy-links.tsv`. The baseline at `e414e316` is `0 errors, 203 pending`; a wrong relative path, a wrong letter case or a fragment that names no heading all come back as errors. This is why no hand-written list of "links I should check" is needed.
- **A fragment link into a deleted file is invisible to the checker.** The checker only follows links inside `docs/`; the references in `AGENTS.md` and the plan are outside its roots (the plan is under `docs/`, so its links *are* checked; `AGENTS.md` is not). Grep for both file names after the change and confirm the only hits are deliberate historical mentions.
- **Word-count gate.** `tools/docs-size-check/check_size.py` caps pages under `docs/architecture/` at 1,500 words. `docs/contributing/` is **not** in that set, so these pages are not capped - do not add them to it, and do not take the absence of a cap as licence to write a long document. Three short pages beat one long one.
- **Source hygiene.** New pages: UTF-8, no byte-order mark, LF, no hard wrapping - matching every other file under `docs/`. The two `.txt` files are deleted, not reformatted in place.
- **Privacy.** This repository is public. Nothing in these pages names a customer, an application, a library or a schema.
