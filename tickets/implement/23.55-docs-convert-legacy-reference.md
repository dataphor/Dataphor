## The three pages that still say "Under construction"

All three currently carry the same stub - a one-line summary, an "Under construction" heading and a GitHub alert linking `http://dataphor.org/DocumentationOverview.ashx`, which is dead. (`docs/reference/libraries/README.md` was the fourth; `docs-reference-libraries` replaced it.)

**`docs/reference/frontend-nodes/README.md`.** The Frontend component reference - the element reference for the user-interface description language - was generated from the client's node interfaces, and no copy of the output survives anywhere in the repository or in the published help file. Write a short page that says exactly that, points at the converted chapters that do document forms and frames (`docs/developers-guide/presentation-layer.md`, `docs/developers-guide/form-automation.md`, `docs/users-guide/using-dataphor-forms.md`) and at where the node types live in the source (`src/frontend/`), and names the backlog ticket `feat-frontend-node-reference` as the work that would produce the element reference. Do not list the node types by hand: a partial list that drifts is worse than a pointer to the source.

**`docs/reference/call-level-interface.md`** and **`docs/reference/data-access-components.md`.** Both were generated .NET API reference, produced by NDoc from source comments. The help file confirms it: `DRCLIChapter.html` is a 1,287-byte table of contents whose only entry is the `Alphora.Dataphor.DAE` namespace, and the Data Access Components pages are the `Alphora.Dataphor.DAE.Client.*` member pages - roughly 2,000 of the help file's 3,330 pages. **A generated .NET API reference for the 3.x surface does not belong in this documentation set:** it is produced by a tool from the current source, the tool that produced it is long dead, and the surface has moved. Replace each stub with a short hand-written overview instead - what the interface is, the few types a reader starts from, where they live in `src/`, and which converted guide chapters explain them. Two or three hundred words each is right; these are signposts, not reference.

One pending link already resolved to `data-access-components.md` before this chain started (`Alphora.Dataphor.DAE.Client.DataFieldProperties.html`), so the page has a reader. No link points at `call-level-interface.md`, which is why it is the cheapest of the three to settle.
