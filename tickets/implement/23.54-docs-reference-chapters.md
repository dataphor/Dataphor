## What this is

The fourth of five tickets converting the old reference material. The three before it took the operators, the types and the libraries; this one takes the chapters that are in the old DocBook and nowhere else, so that `docs-remove-old-sources` can delete `legacy/Documentation/` without losing anything a reader would want.

These are small - about 80 KB of DocBook against the 760 KB the earlier tickets handled - but they are the reason that ticket can run at all, so they are not deferred to a backlog item whose source would be gone by the time anyone picked it up.

## How these were identified

`tools/docs-convert/pages.tsv` is the complete list of what the AsciiDoc books became: 75 sources, three books plus the glossary and bibliography. Its Reference book has exactly seven pages - the call-level interface, the D4 grammar, the Data Access Components, the error codes, the Frontend components, the libraries index and the tags. So anything else in the old DocBook that is not operator, type or library reference has no converted home, and these three are what is left after the earlier tickets.

**Check each one against the converted pages before converting it**, by heading text rather than by file name - the plan's own current-state paragraph says "several topic chapters" without saying which, and a duplicate page is worse than a missing one. The checks below were done on 2026-11-26 and found no overlap; redo them, because the earlier tickets in this chain landed pages since.

## The three chapters

**`Docs2.0/Keys.xml`** (25 KB, one appendix, id `Alphora.Dataphor.Keys`) is the keyboard-shortcut reference for the Windows client and Dataphoria. Nothing under `docs/` carries it: the User's Guide mentions shortcuts in passing but has no table. Convert it to **`docs/reference/keyboard-shortcuts.md`** and link it from `docs/reference/README.md`.

**`Docs2.0/RealSQLLanguageGuide.xml`** (28 KB, chapter `DDGP1RealSQLLanguage` with five sections: Introduction, Scripts and Execution, Statements - select, insert, update, delete - and Expression) documents the RealSQL language the server still accepts. `grep -rn RealSQL docs/` finds it only in the plan, the architecture pages and the coverage report; the language itself is live (`debt-realsql-coverage` in the backlog is about testing it). Convert it to **`docs/developers-guide/realsql.md`** and link it from `docs/developers-guide/README.md`.

**`Docs2.0/ProgrammingTopics.xml`** (36 KB, two sections: *Using Strings* and *Using Date and Time Values*) is a Developer's Guide chapter. Neither heading appears anywhere under `docs/`. Convert it to **`docs/developers-guide/d4-programming-topics.md`** and link it from `docs/developers-guide/README.md`. Note that two legacy links in the earlier pages point at `D4LGProgrammingTopics-DynamicExecution.html` and `D4LGProgrammingTopics-UsingGenerators.html`, which are **not** in this file - those sections live in `D4LanguageGuide.xml`, which the AsciiDoc conversion already covered, so `reference-links.tsv` resolves them into `docs/developers-guide/`, not into this new page. Do not create sections here to satisfy them.

## Not converted, and why

**`Docs2.0/TypeConventions.xml`** (2.6 KB) is a table of the printed manual's typographic conventions - bold keywords inside code blocks, `<keycap>` for keys, `<guibutton>` for buttons. It describes how the DocBook manual was typeset, not anything about the product, and GitHub-flavoured Markdown cannot render most of it (a fenced code block has no bold). `docs/contributing/writing-docs.md` already covers how these documents are written. Record the row in `reference-pages.tsv` with that reason.

**Everything else under `legacy/Documentation/` is already accounted for:** the three books, the glossary and the bibliography came through the AsciiDoc conversion; `TagsReference.xml`, `D4ParserBNF.xml`, `D4LexerBNF.xml` and the error-prefix chapter duplicate `docs/reference/tags.md`, `d4-grammar.md` and `error-codes.md`; `D4LanguageGuide.xml`, `DevGuidePart1-4.xml`, `UsersGuidePart1.xml` and `RentalTutorial.xml` are the DocBook originals of pages already under `docs/`; `SystemTables.xml`, `DilReference.xml`, `SystemLibrary.xml` and `DaeClient.xml` are generator stubs with no content. **Confirm this list rather than inheriting it** - a file that turns out to hold real content and is not in the table above is a finding for the handoff, and it is cheaper to find now than after the tree is deleted.

## Edge cases & interactions

- **Keyboard shortcuts describe a client that is mid-port.** The Windows client and Dataphoria are being brought to .NET 10 by WS6 and their shortcuts have not been re-verified. Convert what the chapter says; do not add, remove or "correct" a shortcut against the source. If the chapter names a shortcut for a feature that has been removed (a web client designer, say), note it in the handoff - `docs-retire-removed-client-text` set the precedent for how removed-client text is handled, and the same sweep applies: look for the capability, not only the product name. *Verified by reading the converted page against the source.*
- **RealSQL is a compatibility surface being described.** The chapter documents statement forms the server accepts. If one looks wrong against the current parser, that is a finding for the handoff and possibly a `fix/` ticket, not an edit to the page. *Verified by the handoff naming anything noticed.*
- **These chapters link into the books both ways.** `RealSQLLanguageGuide.xml`'s own cross-references go into the D4 Language Guide, and `D4LGComparisonWithSQL.html` in the earlier pages may want to come back here; add the `reference-links.tsv` rows and check that the new pages are reachable, not just reached. *Verified by 0 unresolved and by following the links in the rendered pages.*
- **Heading level.** `Keys.xml`'s root is an `<appendix>` and `RealSQLLanguageGuide.xml`'s is a `<chapter>` with `<sect1>`/`<sect2>` children, where the earlier tickets fed the splitter `<section>` trees. `convert.py` moves body headings down one level and reports what it adjusted; read that part of the report rather than assuming. *Verified by the report's heading-adjustment list and by the rendered pages having one `#`.*
- **Images.** `Keys.xml` and the two guide chapters may reference figures from `Docs2.0/Images`. Any image used lands under `docs/images/` through the usual name rule, and `docs/images/` must still have no orphan. *Verified by the report's image lists and `git status docs/images`.*
- **Tables.** `Keys.xml` is mostly a table, and `TypeConventions.xml` was excluded partly because of what DocBook tables can carry. A table whose cell holds several blocks becomes an HTML table, which the report counts per page - check that the keyboard table is a pipe table and still readable at phone width, and that it has not become an unreadable HTML block. *Verified by reading the rendered page and the report's HTML-table count.*
- **Do not grow the scope.** Three pages. If a fourth chapter turns out to have real content, **report it in the handoff and file it** rather than converting it here; `docs-convert-legacy-reference` is the ticket that declares the work item finished and it needs an accurate list more than it needs a fourth page. *Verified by the handoff.*
- **No compatibility surface changed and no migration note.** Documentation only. Say so in the handoff.
