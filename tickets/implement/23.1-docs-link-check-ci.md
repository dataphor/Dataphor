## What this is

`tools/docs-link-check/check_links.py` checks every link and image reference in the Markdown under `docs/` and exits 1 if any points at nothing. It was written by `docs-link-checker` and was the acceptance check for the documentation conversion, but nothing runs it automatically. This item gives it a step in CI.

Both prerequisites in the plan's WS8 table have landed: `build-ci` (the workflows exist) and `docs-convert-asciidoc` (there is documentation to check).

## Where it goes, and why

`.github/workflows/docs.yml` - the existing *Docs* workflow, which today runs the architecture page-size check and that checker's own tests. Not `build.yml`: that workflow ignores `docs/**` on purpose, so a docs job in it would be skipped for exactly the changes this check exists to catch. The comment at the top of `docs.yml` already says the link checker's step belongs there, and so does `tools/docs-link-check/README.md`. Nothing about the workflow needs renaming or restructuring.

## The command, and the `--pending` argument

```
python3 tools/docs-link-check/check_links.py docs --pending tools/docs-convert/legacy-links.tsv
```

`--pending` names a tab-separated list of link targets that do not exist yet; a link to a listed target is reported as `pending` rather than `error`, so it does not fail the run. The list is `tools/docs-convert/legacy-links.tsv`, the 204 links into the old DocBook reference pages that `docs-convert-legacy-reference` will create. Without the argument the check fails with 203 errors today, so the argument is not optional.

Measured at commit `e414e316`:

- with `--pending`: `90 files scanned, 1079 links checked, 0 errors, 203 pending, 12 external`, exit 0.
- without it: `203 errors`, exit 1.

**This is a decision, not a default.** The alternative - hold the CI step until `docs-convert-legacy-reference` lands and the list is empty - was rejected: that conversion is the largest remaining WS8 item and leaves every real broken link ungated in the meantime, while `--pending` gates everything *except* the 203 links that are already tracked as known-missing (defect K17 in the plan). The cost is one argument that has to be removed later, and that removal has an owner: `docs-remove-old-sources` deletes `tools/docs-convert/` (including this list) and must drop the argument in the same commit. That ticket says so and takes this one as a `prereq:`, so the two cannot land out of order.

## The path filter

`docs.yml` triggers on `docs/**`, `tools/docs-size-check/**` and its own path, for both `push` and `pull_request`. Add `tools/docs-link-check/**` to both lists, so a change to the checker runs the check.

Do **not** add `tools/docs-convert/**`: the pending list changes only when the converter is rerun, which happens by hand and only until `docs-remove-old-sources`, and a change there cannot break a link in `docs/`.

The inclusion-filter warning already written into both workflow files applies unchanged and needs no new wording: a push touching none of the listed paths gets no run at all, so this check must never be a required status check while the filter is there.

## Out of scope

Running the link checker's **own unit tests** in CI. `tests` for three of the four Python tools under `tools/` are ungated, and `debt-tool-tests-not-run-by-ci` in `tickets/backlog/` owns that, by discovery rather than by a hard-coded list. This ticket puts the *checker* into CI; that one puts the *checkers' tests* into CI. They are independent and can land in either order. Do not add a `python3 -m unittest discover -s tools/docs-link-check` step here - it would pre-empt that ticket's "discovery, not a list" shape with the very hard-coded list it exists to avoid.

## Edge cases & interactions

- **The step must fail the job.** `check_links.py` exits 1 on errors and 2 on bad arguments; a plain `run:` step fails the job on any non-zero exit, so no `continue-on-error` and no piping that would swallow the status. Verify by inspection of the added step, and by the deliberate-break check in the TODO.
- **`python3`, not `python`.** The job runs on `ubuntu-latest` and the existing steps use `python3`, which the Ubuntu image guarantees. The tool is standard-library Python 3 and needs no setup step.
- **Letter case.** The checker compares each path component against the real directory listing, because Windows ignores case and GitHub does not. The Ubuntu runner is case-sensitive, so a wrong-case link that passes on a developer's Windows checkout is caught here. That is the point of running it on Linux; do not "fix" a case failure by relaxing the checker.
- **A pending target that starts existing** is simply a valid link - the list does not have to shrink in step with the conversion, so a partial conversion landing does not break this step.
- **The pending file must exist.** A missing or malformed `--pending` file exits 2. After `docs-remove-old-sources` deletes it the argument must be gone; that is why the ordering above is enforced with a `prereq:`.
- **Timeout and permissions.** The job already has `timeout-minutes: 10`, `permissions: contents: read` and a concurrency group. The check takes about a second over 90 files. Change none of them; in particular never switch the workflow to `pull_request_target` (the repository is public and the comment in the file says so).

## Tests

None new. The step itself is wiring, and the checker's own 14 unit tests already exist (`tools/docs-link-check/test_check_links.py`); getting them run automatically is `debt-tool-tests-not-run-by-ci`.
