## Context

The work item `docs-convert-asciidoc` (plan WS8) converts `Documentation/` (75 AsciiDoc files, about 189,000 words, 107 images) into Markdown under `docs/`. It was split into three tickets:

- `docs-link-checker` — the standalone link checker in `tools/docs-link-check/` (stdlib Python; also exports `slugify` / `heading_slugs`, GitHub's heading-anchor rule).
- **this ticket** — the conversion tooling under `tools/docs-convert/`, run over the whole corpus into a scratch directory. It does not write into `docs/`.
- `docs-convert-asciidoc` — the content decisions (reviewing every code-block language tag, deciding the cross-references that are broken in the source), generating into `docs/`, link check clean, spot checks.

This ticket writes only under `tools/` (plus one `AGENTS.md` layout row). It never edits `Documentation/`, `legacy/Documentation/` or `book.json`.

Survey facts this design rests on (from the plan ticket; re-verify any you depend on): every file declares `:encoding: iso-8859-1` but all 75 are UTF-8 (50 pure ASCII; non-ASCII is U+00A0 no-break space ×307, U+2013 ×7, ®, ©, ™, and one mojibake U+00C2 before a no-break space in `DevelopersGuide/OperatorMapping.adoc`); no `include::` anywhere; each file is a standalone document (`:doctype: book` in 70, `chapter` in 4) with `:data-uri:` set; the books exist only through `SUMMARY.adoc` (GitBook table of contents) and each book's index file. 649 explicit `[[id]]` anchors, **all of them directly above a heading** (checked: none inline or before a block), so every explicit anchor is a section id. About 525 `<<…>>` cross-references, mostly of the form `<<File.adoc#Heading_Text, label>>` or `<<Heading_Text, label>>`, where `Heading_Text` is the section title with spaces replaced by `_` (a GitBook convention, not Asciidoctor's); about 22 are broken in the source. 206 links to 107 legacy `.html` reference pages (88 `O-System.*` operator pages, 16 `T-System.*` type pages, `DRSimpleDeviceLibrary.html`, `dilrefAlphora.Dataphor.Frontend.Client.IFrame.html`, `Alphora.Dataphor.DAE.Client.DataFieldProperties.html`; none carry a `#fragment`). Images: 59 BMP, 33 PNG, 10 SVG, 4 GIF (all single-frame), 1 JPG; 98 distinct files referenced by 103 image macros (block `image::` and inline `image:` with `width`/`height`); SVGs reference no external files; no two image names collide after lower-casing and dropping the extension.

## Decisions (settled in planning, with the evidence)

**Toolchain: Asciidoctor (DocBook 5 backend) → pandoc (DocBook reader) → a Python pass over pandoc's JSON syntax tree → pandoc GitHub-flavoured Markdown writer.** The plan's recommended route. A trial during planning ran four representative chapters (`D4Catalog`, `D4LanguageGrammar`, `Tags`, `Dataphoria`) through both this route and pandoc 3.14's own `asciidoc` reader. The direct reader mis-parsed `link:T-System.Boolean.html[System.Boolean]` (the dot in the link text became an HTML class), left `footnote:[…]` as literal text, emitted every cross-reference as raw `<a class="cross-reference">` HTML with a `#File.adoc#X` href, and lost the section heading markers. The DocBook route got all of these right: Markdown headings, pipe tables, `[^1]` footnotes, `> [!WARNING]` GitHub alerts, and links of the form `File.xml#Heading_Text` / `#explicit-anchor` that a rewrite pass can resolve. Asciidoctor even resolved same-file references whose text equals a heading title to the explicit anchor (`<<Constraints,…>>` → `#D4LGCatalogElements-Constraints`). The same DocBook → Markdown stage converts the legacy DocBook 4.3 reference for `docs-convert-legacy-reference`.

| pandoc | 3.14 | not an npm package: `winget install JohnMacFarlane.Pandoc --version 3.14`, or the portable `pandoc-3.14-windows-x86_64.zip` from the pandoc GitHub releases; `convert.py --pandoc PATH` overrides the lookup |
| Python | 3.12+ (3.14 on the survey machine) | |

The converter prints the version of each tool at start and **stops if pandoc's or Asciidoctor's major.minor differs from the pin**, because a different version changes the output and breaks the reproduction check. `--allow-tool-versions` overrides for experiments.

Ruby Asciidoctor is an acceptable substitute only if Node is unavailable; the README says the pins above are the tested route.

**Language: Python 3 for the driver, the syntax-tree pass and image conversion;** Node only to run Asciidoctor. Python is already the repo's scripting language (`tools/net-spike`), and the link checker it shares the slug rule with is Python. The pass works on pandoc's JSON (`pandoc -f docbook -t json`, transform, `pandoc -f json -t gfm`), not on Markdown text, so it never pattern-matches rendered Markdown.

**Asciidoctor invocation** per source file: `asciidoctor -r @asciidoctor/docbook-converter -b docbook5 -a data-uri! -a outfilesuffix=.adoc -o <scratch>/<name>.xml <source>`. `data-uri!` is essential: the sources set `:data-uri:`, which makes Asciidoctor inline every image as base64 (the trial's `Dataphoria` output grew from 2 KB to 1.2 MB). `outfilesuffix=.adoc` keeps inter-document references as `File.adoc#X` (without it they come out as `File.xml#X`; verify which you get and handle both). The declared `iso-8859-1` is ignored by Asciidoctor.js, which read the files as UTF-8 in the trial (® came through intact); do not convert the input encoding. Asciidoctor warnings are collected into the report, not fatal.

**pandoc invocation:** `-f docbook -t json` in, `-f json -t gfm --wrap=none --eol=lf` out. `--wrap=none` because the project's Markdown is not hard-wrapped; `--eol=lf` because the existing `docs/*.md` are LF, UTF-8 without a byte-order mark, and pandoc on Windows would otherwise write CRLF.

**Granularity: one Markdown page per source file.** Keeps reference mapping one-to-one. Splitting long Developer's Guide chapters can come later.

**Page names** come from `tools/docs-convert/pages.tsv` (columns `source`, `output`; paths relative to `Documentation/` and `docs/`), committed, seeded by this rule and then hand-set where the rule is wrong:

- base name: replace `_`, spaces and other non-alphanumerics with `-`; insert `-` between a lower-case letter or digit and an upper-case letter, and between an upper-case letter and an upper+lower pair (`SQLDevice` → `SQL-Device`); lower-case; collapse repeated `-`, trim. `D4ComparisonWithSQL` → `d4-comparison-with-sql`, `EnforcingStimulus-ResponseRules` → `enforcing-stimulus-response-rules`, `Tutorial_BookPublishing` → `tutorial-book-publishing`, `D4LanguageGuide` → `d4-language-guide`.
- folders: `UsersGuide/` → `users-guide/`, `DevelopersGuide/` → `developers-guide/`, `DataphorReference/` → `reference/`.
- each book's index file is its folder's `README.md` (GitHub shows it on the folder page): `UsersGuide/UsersGuide.adoc` → `users-guide/README.md`, `DevelopersGuide/DevelopersGuide.adoc` → `developers-guide/README.md`, `DataphorReference/DataphorReference.adoc` → `reference/README.md`.
- hand-set rows: `DataphorReference/D4LanguageGrammar.adoc` → `reference/d4-grammar.md`; `Tags.adoc` → `reference/tags.md`; `ErrorMessagePrefixCodes.adoc` → `reference/error-codes.md` (left as the converted table; `docs-contributing` later merges `docs/reference/Error Message Prefix Codes.txt` into it); the four stubs `Libraries.adoc` → `reference/libraries/README.md`, `FrontendComponents.adoc` → `reference/frontend-nodes/README.md`, `CLI.adoc` → `reference/call-level-interface.md`, `DataAccessComponents.adoc` → `reference/data-access-components.md` (the plan's target tree has no slot for the last two; `docs-convert-legacy-reference` fills or moves them); `GLOSSARY.adoc` → `glossary.md`; `BIBLIOGRAPHY.adoc` → `bibliography.md`; `README.adoc` and `SUMMARY.adoc` → `README.md` (see the index below).
- not converted, and listed in the table with an empty `output`: `AuthoringDocumentation.adoc` (describes the GitBook workflow this retires; `docs-contributing` writes its replacement). Also not converted, not in the table: `Documentation/Scripts/scroll-to-hash.js` and `Documentation/.bookignore` (GitBook support), `Documentation/Images/Working/*.cdr` (source art).
- two sources mapping to one output is an error.

**`docs/README.md`** is assembled from the converted `README.adoc` (the introduction; its `[horizontal]` labelled list converts as a definition list, check it renders), then a `## Contents` section that is the converted `SUMMARY.adoc` list with its title dropped (its nested `link:` lists become nested Markdown lists of resolved links), then the contents of `tools/docs-convert/index-extra.md`, a committed hand-written section `## Project documents` linking `architecture.md`, `modernization-plan.md` and `migration-notes.md` with one line each. The `SUMMARY.adoc` `## User's Guide`-style headings stay as `###` headings under Contents.

**Headings.** Each page gets exactly one `#` heading, the document title (`= Title`, which pandoc puts in the metadata, not the body); every body heading shifts down one level so `==` becomes `##`. Asciidoctor wraps a book's preamble in an untitled preface, which pandoc emits as an empty `# ` heading: drop empty headings, keep their content. Check the four `:doctype: chapter` files (not a doctype Asciidoctor knows; it falls back to `article`) come out with the same levels.

**Anchors and cross-references.** GitHub generates heading anchors itself and ignores any id the Markdown sets, so every target becomes a GitHub heading slug, computed with `heading_slugs` imported from `tools/docs-link-check/check_links.py` over the final rendered headings of each page (title included, duplicates suffixed `-1`, `-2` as GitHub does). Two passes:

1. Convert every page to its transformed syntax tree; for each output page record, in order, each heading's rendered text, its DocBook id (the explicit `[[anchor]]` where there was one, else Asciidoctor's generated `_lower_case` id) and its GitHub slug.
2. Rewrite every link:
   - scheme `http:`/`https:`/`mailto:`/`ftp:` → unchanged, listed in the report.
   - path ending `.html` with no scheme → a legacy reference link (below).
   - otherwise split `path#fragment`. Resolve `path` relative to the source file's folder (empty path = the current file; strip a leading `./`; accept `.adoc` and `.xml` suffixes), find the output page through `pages.tsv` with an **exact-case** match, and emit the path relative to the current output page.
   - resolve `fragment` in the target page, first match wins: (a) equals a heading's DocBook id; (b) equals a heading's text with `_` read as space, case-sensitive; (c) the same, case-insensitive; (d) a row in `xref-fixes.tsv`. Emit `#<slug>`; drop the fragment when it resolves to the page's own title heading (link to the page). When two headings in a page have the same text, (b)/(c) take the first, which is where GitBook's generated id pointed.
   - anything still unresolved is listed in the report as `unresolved` and, without `--allow-unresolved`, fails the run. The link is left as written so the link checker shows it too.
   - explicit anchors that nothing references are simply dropped (they only ever named headings, which GitHub anchors anyway). No `<a id>` tags are emitted.
   - `xref-fixes.tsv` columns: `source` (the `.adoc` path the reference is in), `ref` (the reference exactly as the resolver saw it, `path#fragment`), `replacement` (a corrected reference in the same source-side form, for example `../DevelopersGuide/D4ScriptsAndExecution.adoc#Script_Execution`, which then goes through normal resolution; or empty, meaning unlink: keep the label as plain text), `reason`. It ships with the rows whose answer is unambiguous from the survey (for example the two `link:Tutorial_FrontendComponents.adoc` → `Tutorial_SampleComponents.adoc`, wrong-case file names such as `D4ScriptsandExecution.adoc` → `D4ScriptsAndExecution.adoc`); the remaining by-hand decisions are `docs-convert-asciidoc`'s.

**Legacy reference links (the 206).** Each is rewritten to the page `docs-convert-legacy-reference` will create, computed by rule, and listed in `tools/docs-convert/legacy-links.tsv`, which the converter regenerates on every run:

| Legacy page | Target under `docs/reference/` |
|---|---|
| `O-<Name>.html` | `system-library/operators/<Name>.md` (`O-System.iAddition.html` → `system-library/operators/System.iAddition.md`) |
| `T-<Name>.html` | `system-library/types/<Name>.md` |
| `DR<Name>Library.html` | `libraries/<Name>.md` (`DRSimpleDeviceLibrary.html` → `libraries/SimpleDevice.md`) |
| `dilrefAlphora.Dataphor.Frontend.Client.I<Name>.html` | `frontend-nodes/<Name>.md` (`IFrame` → `frontend-nodes/Frame.md`) |
| `Alphora.Dataphor.DAE.Client.<Name>.html` | `data-access-components.md` (the placeholder page this conversion creates; one link, so it resolves today but is still listed) |
| anything else | listed with an empty `target` and reported as unresolved |

Names keep the legacy spelling and case, including the misspelled `System.SecurityOperartors`; `docs-convert-legacy-reference` may retarget by editing the rule and rerunning, or by rewriting from the list. `legacy-links.tsv` format: tab-separated, header row, columns `page` (output page, relative to the docs root, e.g. `developers-guide/d4-catalog.md`), `line` (1-based line in that output page), `text` (link text), `legacy_page` (e.g. `O-System.iAddition.html`), `target` (relative to the docs root, e.g. `reference/system-library/operators/System.iAddition.md`), `source` (the `.adoc` it came from, relative to `Documentation/`). Sorted by page then line. The link checker's `--pending` reads its `target` column relative to the root it checks, so the same list works for `docs/` and for a scratch output folder.

**Literal blocks and language tags.** Every pandoc `CodeBlock` (from `....` literal blocks, `----` listing blocks and indented literal paragraphs alike) gets a language class so pandoc writes a fenced block with an info string. Allowed tags: `d4`, `sql`, `xml`, `bnf` (grammar productions; GitHub has no BNF highlighter and shows it plain, but the tag marks the block), `csharp`, `text`. The authority is `tools/docs-convert/code-blocks.tsv`, committed: columns `page` (output path relative to `docs/`), `n` (1-based ordinal of the block in that page), `sha` (first 12 hex digits of SHA-1 of the block text after character clean-up), `lang`, `reviewed` (`yes` or empty), `first_line` (first non-blank line, truncated to 60 characters, for the reviewer only). Behaviour:

- `--seed-code-table` adds a row for every block missing from the table, with the heuristic's tag and `reviewed` empty, and rewrites rows whose `sha` changed, clearing `reviewed`. Without it, a missing or changed block is an error. This ticket commits the seeded table (all rows unreviewed); `docs-convert-asciidoc` reviews it.
- `--require-reviewed` fails if any row is unreviewed (used by `docs-convert-asciidoc` for the final run).
- Heuristic, first rule that matches: contains `::=` → `bnf`; first non-blank line starts with `<?xml`, or is a tag `<Name …>` and the block contains `</` or `/>`, and no line contains `::=` → `xml` (grammar blocks start with `<` too, about 150 of them; never tag those `xml`); a line starts with an upper-case SQL statement keyword (`SELECT`, `INSERT INTO`, `UPDATE`, `DELETE FROM`, `CREATE TABLE`, `ALTER TABLE`) → `sql`; contains any of `;`, `:=`, `{`, or (case-insensitive, as words) `select`, `insert`, `update`, `delete`, `create`, `alter`, `drop`, `var`, `begin`, `where`, `table` → `d4`; else `text`. It is a seed, not an answer; the review owns the result.

**Characters.** In every `Str` and `CodeBlock` text: U+00C2 directly followed by U+00A0 → a single space (the mojibake); U+00A0 → ordinary space (282 of the 307 sit in prose, mostly inside `<class name>`-style grammar references, 25 in code, where they would break copy-and-paste). Keep the typographic characters Asciidoctor produces (’ for `'`, — for `--`, …): GitBook rendered the published books with Asciidoctor.js too, so readers already saw them. The legacy `iso-8859-1` attribute is ignored.

**Block titles, figures, admonitions, tables, footnotes.**

- Block titles (`.Further reference` above a list, `.Sections`): pandoc wraps the block in a `Div` with a `title` child `Div`, written as raw `<div>` HTML. Replace with a bold paragraph `**Further reference**` followed by the block, no `Div`.
- Figures (titled `image::`): emit the image paragraph followed by the caption as an italic paragraph; untitled block images as a plain image paragraph. Inline images with `width`/`height` keep them (pandoc writes `<img … width height>`, which is fine).
- Admonitions: GitHub alert syntax (`> [!NOTE]`, `> [!WARNING]`, `> [!IMPORTANT]`), which pandoc's gfm writer already emits. Check all 11 come out that way.
- Tables: keep whatever pandoc writes. Simple tables become pipe tables; a table whose cells hold several paragraphs or nested blocks comes out as raw HTML, which GitHub renders. No restructuring (this is a format conversion); the link pass runs on the syntax tree before writing, so links inside HTML tables are rewritten too. The report counts HTML tables per page.
- Footnotes: pandoc's `[^n]` (GitHub renders them). Check all 33.
- Any remaining raw `<div>` in the output is reported per page (the report is the review list for `docs-convert-asciidoc`).

**Images.** Only images referenced by a converted page are converted (the 9 unreferenced ones are listed in the report). Output to `docs/images/` (flat), named by the page rule above applied to the base name, extension `.png` for BMP, GIF and JPG (converted with Pillow, `optimize=True`, palette and transparency preserved) and unchanged for PNG and SVG (copied byte-for-byte). `Dataphor Overall - Simplified.svg`, referenced URL-encoded as `Dataphor%20Overall%20-%20Simplified.svg`, is matched after percent-decoding → `dataphor-overall-simplified.svg`. Image paths in pages are rewritten relative to the page. Report the total size of `docs/images/` (the BMPs are 28 MB; PNG should be a small fraction; say what it came to).

**Output and reruns.** `python tools/docs-convert/convert.py --out DIR` converts everything into `DIR` laid out as `docs/` (so `DIR/users-guide/…`, `DIR/images/…`, `DIR/README.md`). **The report is printed to standard output** (nothing is written into `DIR` besides pages and images), and the run's tables (`legacy-links.tsv`, and `code-blocks.tsv` when seeding) are written under `tools/docs-convert/`. The converter writes only the paths `pages.tsv` and the image rule name, so pointing `--out` at `docs/` never touches `architecture.md`, `modernization-plan.md`, `migration-notes.md` or `docs/reference/*.txt`, and it never deletes anything. Intermediate DocBook and JSON go to a scratch folder (`--work DIR`, default a temporary directory, deleted unless `--keep-work`). Running twice gives byte-identical output (no timestamps; stable ordering).

**Reuse for the legacy DocBook.** Keep the DocBook → Markdown stage callable on its own: `convert.py docbook FILE.xml … --out DIR` runs pandoc's DocBook reader, the character, heading, block-title, figure, code-tag and image steps, and writes Markdown, with the link-resolution configuration (page map, how a fragment resolves) passed in rather than hard-coded to the AsciiDoc conventions. `docs-convert-legacy-reference` supplies its own page map and resolver rules for DocBook 4.3 `<link linkend>`/`<xref>` ids. Do not build that ticket's mappings here.

## Edge cases & interactions

- Heading text that slugs to the same value as the title (a chapter `Security` with a section `== Security`): the section gets `security-1`; the resolver must use the computed slug, never `slugify(text)` alone. Verified by the link check of the scratch output.
- References to `File.adoc#Summary`: `Summary` is usually the first `##` section; it resolves to `#summary`, not to the page. By the link check.
- A heading containing inline code, emphasis, a link or a curly apostrophe (`User’s Guide` → `users-guide`): the slug comes from the rendered text through the shared `heading_slugs`. By the link check.
- Fragment that matches a heading's explicit id in one page and another heading's text elsewhere: the resolver only looks in the target page; order (a) before (b). By inspection.
- The 5 `<< | >>`-style BNF fragments in `D4LanguageGrammar` are inside literal blocks, which Asciidoctor does not parse for references (confirmed in the trial); they must survive as text in a `bnf` block. Spot check.
- `link:` targets with `./` prefixes (all of `SUMMARY.adoc`) and `../` across books. By the link check.
- Case: a reference naming `D4ScriptsandExecution.adoc` must not resolve on Windows by accident; the page lookup is an exact-case dictionary lookup, never a file-system probe. By inspection.
- Pandoc's empty preface heading, and a page whose first body element is an image (the book index pages start with the logo). Spot check one book index page.
- Inline `image:` icons (`Running.gif`, width/height 48) inside table cells: converted to PNG and still sized. Spot check in `DataphorService` (or wherever the three status icons appear).
- Same-named heading repeated in `Tags` (a tag described under two components): references resolve to the first, as GitBook's id did; listed in the report as ambiguous so the reviewer can check. By the report.
- A run on a different pandoc or Asciidoctor version: refuses (version check). By inspection.
- Output pointed at `docs/` while `docs/` holds hand-written files: never overwritten, never deleted. By inspection of the write paths (they all come from `pages.tsv` and the image rule).
- Node or pandoc missing: a one-line message naming the README section, not a traceback.
- Scratch run's link check: `python tools/docs-link-check/check_links.py <out> --pending tools/docs-convert/legacy-links.tsv` must show 205 pending (the 206th, to `data-access-components.md`, resolves to the placeholder page) and no errors other than the `unresolved` references the report already lists. This works for a scratch folder because `legacy-links.tsv` paths are relative to the docs root, and the checker reads `--pending` targets relative to the root it checks.

## Testing

No automated test for the converter: it runs once, by hand, and its verification is the link checker over its output plus the spot checks `docs-convert-asciidoc` performs. Its tables are data, not logic. The heading-slug rule it depends on is tested in `docs-link-checker`.
