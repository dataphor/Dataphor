## What this is

The second of five tickets converting the old reference material into `docs/reference/`. `docs-reference-tooling` built the splitter, the `--legacy-map` option and the three tables and proved them on a sample; this ticket runs them over the whole core-library reference and lands the pages.

Of the 203 pending links recorded in `tools/docs-convert/legacy-links.tsv`, **200 end here**: 88 distinct operator pages, 16 distinct type pages, and three that want operator-category pages (`System.AggregateOperators`, `System.CursorOperators`, `System.ListOperators`). The remaining three are a library page, a Frontend component page and a misspelling, which the later tickets handle.

## Two rules the whole chain follows

**Index pages are hand-written; converted pages are never hand-edited.** `convert.py` overwrites exactly the paths its page map names and nothing else, so a hand-edit to a converted page is lost on the next rerun. `docs/reference/system-library/README.md` is therefore written by hand and is not any source's output; `legacy/Documentation/Docs2.0/SystemLibraryReference.xml` is **not converted** (its own prose is thin and 39 of its blocks are generated content), and `reference-pages.tsv` records that with a reason. After `docs-remove-old-sources` deletes the sources the converted pages become ordinary documents like the rest of `docs/`.

**Each ticket reruns the conversion over every source landed so far**, not only its own, and checks with `git diff` that pages landed earlier changed only where expected. That is what the byte-for-byte reproducibility established by `docs-reference-tooling` is for.

## The hand-written index

## Edge cases & interactions

- **Do not pass `--legacy-table tools/docs-convert/legacy-links.tsv`.** That file is CI's pending list, produced by the AsciiDoc run. Writing the reference's own internal links over it would make CI's gate meaningless. Send it to a scratch path, as above. *Verified by reading the command and by `git diff tools/docs-convert/legacy-links.tsv` being empty.*
- **Twelve links point out of the core library** - `SystemOperators.xml` has 12 occurrences of `O-Frontend.*`, `O-SQLDevice.*`, `O-MSSQLDevice.*` and `O-SimpleDevice.*`, whose pages land in `docs-reference-libraries`. Give each an empty target in `reference-links.tsv` with the reason naming that ticket, so the reference becomes plain text rather than a link to a page that does not exist; that ticket fills the rows in and reruns. Leaving them to the built-in rule would publish links to `reference/system-library/operators/Frontend.*.md`, which nothing will ever create, and CI would go red. *Verified by the link checker with no pending list for these targets: the pages exist or the links are text.*
- **Letter case, everywhere.** 344 mixed-case page names, compared by the checker against the real directory listing, because Windows ignores case and GitHub does not. Every name comes from `reference-pages.tsv`. CI runs the checker on Linux, which is the guard. *Verified by CI.*
- **Duplicate headings within a page.** A merged page can carry two *Remarks* or two *See Also* headings; GitHub anchors the second as `-1`, which `convert.py`'s slug computation already mirrors. What it must not do is resolve a cross-reference to the wrong one - the report lists ambiguous matches, and `xref-fixes.tsv` settles any that matter. Read the ambiguous list rather than skimming it. *Verified by reading the report's ambiguous section.*
- **See Also links between the new pages must land resolved, not dropped.** `SystemOperators.xml` and `SystemTypes.xml` hold 1,221 `O-*` and 76 `T-*` links; a silent drop would hide here, which is why the acceptance gate is 0 unresolved rather than a spot check. *Verified by the report's unresolved count and by the link checker.*
- **Six operator pages have no signature** (`System.ActualDate`, `System.ActualDateTime`, `System.ActualTime`, `System.IsNotNil`, `System.MonthsBetween`, `System.YearsBetween`): the sections post-date the published help file. They carry no *Declarations* heading at all. Confirm by reading those six pages, not by trusting the splitter. *Verified by inspection of the six pages.*
- **A signature that disagrees with the code is a finding, not a typo.** These are the 3.x published declarations, and operator signatures are a compatibility surface this port must not have changed. If one looks wrong, report it in the handoff; do not edit it to match the code. The disagreement is itself information, and `docs-reference-generator` is the work item that resolves it. *Verified by the handoff naming any that were noticed.*
- **Images.** `SystemOperators.xml` and `SystemTypes.xml` reference no image; `docs/images/` currently has no orphan and should still have none. If the report lists an image, it lands under `docs/images/` through the usual name rule and the page links it relatively. *Verified by `git status docs/images`.*
- **Nothing enumerates `docs/**` with a size assumption.** `tools/docs-size-check` reads only `docs/architecture/`, which this does not touch. The link checker becomes a CI step and goes from 94 files to about 440 - time it and say how long it takes in the handoff, so a future slow run is noticed as a regression rather than accepted. *Verified by timing the run.*
- **Do not add 344 entries to `docs/README.md`.** Its contents list is the books' nested list; the reference is reached through `docs/reference/README.md` and the new `system-library/README.md`. `docs-convert-legacy-reference` tidies the reference index. *Verified by `git diff docs/README.md` being empty.*
- **No compatibility surface and no migration note.** Documentation only; no public type or member, no file format, no D4 semantics. Say so in the handoff.

## Tests

None added. The project's testing rule asks for a characterization test when behaviour is ported, and no behaviour is: this is a document conversion whose gate is the link checker, which already fails when a referenced page is missing. A test asserting a page count or that a named operator page exists would pin a number the next ticket changes. If a defect in the splitter or the resolver turns up here, its fix takes a case in `tools/docs-convert/test_reference_split.py` or `test_convert.py` as `docs-reference-tooling` set up.

Run `python -m unittest discover -s tools/docs-convert` anyway - the tool tests are not in CI (`debt-tool-tests-not-run-by-ci`) and a page-map change can break them.
