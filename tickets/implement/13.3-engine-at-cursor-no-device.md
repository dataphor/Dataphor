description: Inside an application transaction, reading a table by its bare name (a cursor on it, or a plain select) fails with "does not support retrieval", because the query that copies the table's rows into the transaction never gets a device assigned; give that query its device so the read works.

## Symptom

Inside a joined application transaction (AT), any statement whose top table node is a bare table reference fails:

```
create table Test { ID : Integer, key { ID } };
create table ATID { ID : Guid, key { } };
ATID := table { row { BeginApplicationTransaction() ID } };
JoinApplicationTransaction(ATID[].ID, false);
select Test;    // RuntimeException 104137: Device "<no device>" does not support retrieval for the table variable "General.Test".
```

The same error comes from `cursor(Test capabilities { navigable, updateable })`, which is how the coverage script `ApplicationTransactions` hits it at line 20. `select Test where ID = 1;` in the same state works. Verified in this fix stage with a scratch in-process test (since removed) that ran these statements directly on a process.

## Cause

When a process is joined to an AT, `Compiler.OptimizeNode` (`src/engine/DAE/Compiling/Compiler.cs`, about line 735) runs, in order:

1. `PrepareJoinApplicationTransactionVisitor`: each `TableNode` calls `PrepareJoinApplicationTransaction` (`TableNode.cs`, about line 3244), which compiles a *populate node*: the same expression recompiled in the AT's global context, so it reads the real tables (here `General.Test`). At run time, `TableNode.InternalBeforeExecute` executes the populate node and copies its rows into the AT's copy of the table (`ApplicationTransactionUtility.JoinExpression`, `ApplicationTransaction.cs` about line 220).
2. `planNode.DeterminePotentialDevice(plan)`. `TableNode.DeterminePotentialDevice` (`TableNode.cs`, about line 674) calls `base` and then `_populateNode.DeterminePotentialDevice(plan)`.
3. `DetermineDeviceVisitor`, which `TableNode.BindingTraversal` (about line 694) also runs over `_populateNode`.

`BaseTableVarNode.DeterminePotentialDevice` (`TableNodes.cs`, about line 1819) overrides the `TableNode` method **without calling base**, so a `BaseTableVarNode`'s own populate node never gets step 2. Its inner `BaseTableVarNode` for `General.Test` keeps `_potentialDevice == null`, step 3 sets `NoDevice = true`, and when the cursor (or `select`) executes the AT table node, `BeforeExecute` runs the populate node and `BaseTableVarNode.InternalExecute` (about line 1879) throws 104137. With a restriction on top (`Test where ID = 1`), the outer `RestrictNode` inherits the `TableNode` method, so its populate node is prepared and the read works.

History: commit 423f8bc7 (2015, "Fixed an issue with A/T nodes not properly binding due to the new binding methodology", in tag `v3.1`) moved potential-device determination after the populate-node pass and added the populate-node call to `TableNode.DeterminePotentialDevice` only; `BaseTableVarNode`'s override already existed and was not updated. So this is a defect in 3.1 as shipped, not a porting defect; nothing the port changed (store, runtime, threading) is involved.

`OnNode.DeterminePotentialDevice` (`TableNodes.cs`, about line 2515, `NoDevice = true;`) has the same shape and drops its populate node the same way.

## Fix

Verified in this stage: adding `if (_populateNode != null) _populateNode.DeterminePotentialDevice(plan);` at the end of `BaseTableVarNode.DeterminePotentialDevice` makes the snippet above pass and moves the `ApplicationTransactions` coverage script past line 29 to its next cause (below). With the fix, the whole 707-line script passes when run batch by batch directly on a process.

Recommended shape, so a future override cannot drop the populate node again: in `TableNode`, make populate-node handling independent of the override. For example, `TableNode` overrides `DeterminePotentialDevice` as `sealed` and calls a new `protected virtual void InternalDeterminePotentialDevice(Plan plan)` (default: `base.DeterminePotentialDevice(plan)`) followed by the populate-node call; `BaseTableVarNode` and `OnNode` override `InternalDeterminePotentialDevice` instead. Checked in this stage: within the repository, only `DDLNodes.cs` (not table nodes), `TableNode.cs` and `TableNodes.cs` override `DeterminePotentialDevice` (`grep -rln "override void DeterminePotentialDevice" --include=*.cs src libraries samples tests`). It is still a public virtual member, so a custom C# extension with its own `TableNode` subclass could override it, and sealing it would break that extension's build. If you seal it, add a "Custom C# extensions" row to `docs/migration-notes.md` naming the replacement method. Otherwise, use the one-line fix in both overrides and leave a `NOTE:` on `TableNode.DeterminePotentialDevice` saying that overrides must call base or handle `_populateNode`. Either is acceptable; prefer sealing unless it turns out to be more than a few lines.

## Next cause in `ApplicationTransactions`

After the fix, the harness run fails at line 41 with `Application Transaction read is not repeatable.` That failure happens only because the harness runs the script nested in one statement (the D4 `ExecuteScript` operator). Leaving the AT disposes the AT device session, which rolls back AT work not yet committed, and inside one statement nothing has committed yet. It is a separate cause, filed as `engine-at-leave-rolls-back-open-work`. Re-point the manifest entry there.
