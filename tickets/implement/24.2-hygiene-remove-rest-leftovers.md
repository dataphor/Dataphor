## What this is

`src/engine/DAE/REST/RESTResult.cs` (`public class RESTResult`) and `src/engine/Server/REST/RESTMarshal.cs` (`public static class RESTMarshal`) convert engine results to and from JSON for an HTTP interface. Their only consumer was the web and cloud prototype now parked under `legacy/`, which decision D6 parked rather than ported. Both files are still compiled: `DAE.csproj` has `<Compile Include="REST\RESTResult.cs" />` and `Server.csproj` has `<Compile Include="REST\RESTMarshal.cs" />`.

Nothing in the repository calls either type. Verified 2026-11-21 by `test-coverage-gap-analysis` and again 2026-11-26: outside the two files themselves, the only places the names `RESTResult` and `RESTMarshal` appear anywhere in the tree are those two `Compile` entries, the project-file comment described below, the coverage report and the coverage tool (which uses one of the paths as synthetic test data, not as a real path).

## What to change

- Delete `src/engine/DAE/REST/RESTResult.cs` and its `Compile` entry in `src/engine/DAE/DAE.csproj`. The `REST/` folder is then empty and goes with it.
- Delete `src/engine/Server/REST/RESTMarshal.cs` and its `Compile` entry in `src/engine/Server/Server.csproj`. Same for that folder.
- Delete `<PackageReference Include="Newtonsoft.Json" />` from `src/engine/Server/Server.csproj`. The long comment above the package group in that file says, in its own words, that this package is there for `REST\RESTMarshal.cs`: remove that sentence from the comment and leave the rest of the comment, which explains the other four references, untouched.
- Keep the `Newtonsoft.Json` entry in `Directory.Packages.props`. Two live projects still reference the package — `src/protocol/NativeCLI/DAE.NativeCLI.csproj` for `NativeCLIHelper`, and `libraries/System.Internet/Source/System.Internet.csproj` for the `Dynamic` type and its conveyor — and a third, `tests/libraries/LibraryLoadingProbe`, uses a package that depends on it.
- Drop the `excluded` entry in `tools/coverage-report/areas.json` whose `paths` are `src/engine/DAE/REST/` and `src/engine/Server/REST/`. That entry exists only to keep these files out of the coverage rollup until they went, and it names the hygiene umbrella as its owner. Leave the other two `excluded` entries alone: one is for generated source, and the other belongs to `hygiene-remove-dead-compiled-files`, which runs after this ticket.
- Repoint the two places in `docs/coverage-report.md` that name the hygiene umbrella for this removal — one row in the *Excluded from the area rollup* table and the sentence in *What this pass found* if it mentions these paths — so they name `hygiene-remove-rest-leftovers` and say the removal has landed. That document is the record of one measured run and its tables below *Line coverage per assembly* are regenerated wholesale by the next instrumented run; the point of the edit is only that the document must not claim an exclusion the map no longer has.
- Add one clause to the *Removed by the port* row of `docs/architecture/what-is-alive.md`: the engine-side and server-side JSON marshalling helpers that served the parked web prototype are deleted, with no replacement. Then run `python tools/docs-size-check/check_size.py` — that page set is capped at 1,500 words a page.

## Migration note

Both types are `public`, so a custom C# extension could in principle have called `RESTMarshal` or returned a `RESTResult`. That makes this a change an extension can notice, so it needs an entry in `docs/migration-notes.md` under *Custom C# extensions*: the two types are gone, there is no replacement in the product, and an extension that marshalled engine results to JSON should do so with its own code and its own choice of JSON library. Nothing an application or a deployment script can see changes.

## Edge cases & interactions

- **`Newtonsoft.Json.dll` must still reach both places that need it at run time.** It is in the runtime layout twice: in `bin/`, because `DAE.NativeCLI` ships there, and in `Libraries/System.Internet/`, because `libraries/System.Internet/System.Internet.d4l` lists it as a library file. The second of those is checked by the build itself — the layout fails the build when a file a `.d4l` lists is not in the library folder — so a build proves the library half. For the `bin/` half, look in `artifacts/layout/<config>/bin/` after building and confirm the assembly is still there. If it is not, the right fix is a package reference on the project that needs it, never putting one back on the server.
- **The server assembly is what the catalog store for SQL Server builds on**, and that project file comment also explains the SQL Server client reference and the ASP.NET Core framework reference. Delete one sentence from the comment, not the comment.
- **`tools/coverage-report/test_coverage_report.py` mentions `src/engine/DAE/REST/` in two places** — in a synthetic area map and in a synthetic Cobertura fixture. Those are test data, not references to the real tree, and they must not be changed: the tool test is what proves an exclusion keeps a file out of every area, and it has to name some path.
- **The coverage tool tests are not run by CI** (that gap is `debt-tool-tests-not-run-by-ci`), so run them here by hand after editing the map.
- **Formatting.** Both project files are UTF-8 with a byte-order mark, tabs and CRLF, as are the deleted sources. `areas.json` is two-space-indented JSON; match it, and leave the file valid JSON with no trailing comma.
- **Deleting a folder.** `git` tracks files, not folders, so removing the last file in `REST/` removes the folder from the index; check that no empty `REST` folder is left on disk to confuse a later `git status` or a glob.
