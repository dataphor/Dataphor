## The calls to make

**1. Code-block language tags.** Review every row of `code-blocks.tsv` (about 760). For each block, look at the block in the scratch output (the `first_line` column is only a hint) and set `lang` and `reviewed=yes`. Tags: `d4` (D4 statements and expressions, including D4 snippets inside SQL-comparison chapters), `sql` (SQL for a back end, mostly in `d4-comparison-with-sql`, the device chapters and the mapping chapters; often lower-case, so the heuristic misses it), `xml` (form documents, configuration; only about 5), `bnf` (grammar productions `<x> ::= …` and syntax summaries written in that notation; about 150; **never** `xml` even though they start with `<`), `csharp` (C# host code, if any), `text` (program output, tag syntax lines such as `Storage.IsSparse = "true | false"`, directory listings, anything not code in one of the other languages). Work page by page; a page is usually all one language with exceptions. When unsure between `d4` and `text`, prefer `d4` if the block would be accepted by the D4 parser in principle (the plan's later "run doc samples as tests" idea looks for `d4` blocks). Run the final conversion with `--require-reviewed`.

**2. Cross-references broken in the source** (about 22, the `unresolved` list in the tooling's report). For each, add a row to `xref-fixes.tsv` by this rule, in order:

- the intended file is unambiguous (wrong case or path, such as `D4ScriptsandExecution.adoc`, `D4LanguageGrammar.adoc` named from the wrong folder, `../DataphorReference.adoc#…`) → correct the path;
- the fragment names an explicit anchor of a heading in a different file than the one named, or names a heading that moved → point at that heading;
- a bare `<<Heading_Text>>` whose heading is not in the current file but exists in exactly one other file of the set → link there; in several files (about 6 cases, such as `Select_Statement` and `Libraries`) → choose the one the surrounding sentence describes (the chapter it names, or the same book), and say why in `reason`;
- no sensible target → empty `replacement` (the label stays as plain text), with the reason.

Every row has a `reason`. The handoff lists the rows (they are the record of these decisions).

**3. Raw HTML the tooling reported** (left-over `<div>`, HTML tables). HTML tables stay (GitHub renders them; no restructuring). A left-over `<div>` is a tooling gap: fix it in `convert.py` if the fix is local (a block-title or sidebar shape the pass does not handle yet), else list it in the handoff.

## Edge cases & interactions

- A reviewed `code-blocks.tsv` row whose block changed because a tooling fix in this ticket altered block text (for example a character clean-up): the `sha` changes, `--require-reviewed` fails; re-review just those rows. By the run itself.
- Fixing a tooling gap changes output pages that were already spot-checked: redo the affected spot checks. By inspection.
- An `xref-fixes.tsv` replacement that itself does not resolve: the converter reports it as unresolved; the run fails. By the run.
- Two references to the same broken target from different files may deserve different answers (context decides): rows are per `source` file. By inspection.
- Hand-written files in `docs/` with the same name as a converted page: none expected (`README.md` is new); `git status` before and after shows only additions plus the two doc edits above. By inspection.
