## What this is

The last WS8 clean-up. Two old documentation trees and a publishing configuration file stay in the tree only until their content has been converted; this deletes them and repoints what referred to them.

- **`Documentation/`** - 32 MB, the AsciiDoc GitBook sources. Converted by `docs-convert-asciidoc`; the Markdown under `docs/` has been the copy to read and edit since that landed.
- **`legacy/Documentation/`** - 81 MB, 786 files: the DocBook 4.3 originals, their DTDs and build tools, a vendored XSL toolchain, jars, a 3.2 MB compiled help file and an 11 MB PDF. The plan's WS12 inventory marks it "Delete after WS8" and calls it "most of 79 MB" of the repository's large binaries.
- **`book.json`** - the GitBook configuration at the root; it names `./Documentation` as its root and loads plugins for a site nobody builds.
- **`tools/docs-convert/`** - the conversion scripts. The plan keeps them only until the sources are deleted; with no `Documentation/` there is nothing to convert and the tool cannot run. `tools/docs-link-check/` **stays**: it is the CI gate, not a conversion script.

## Do not run this before its prerequisites

Both `prereq:` entries are load-bearing, not decoration.

- **`docs-convert-legacy-reference`** takes what `docs/reference/` needs out of `legacy/Documentation/`. Delete that tree first and the material is gone from the working tree (recoverable from history, but nobody will go looking).
- **`docs-link-check-ci`** lands the CI step with a `--pending tools/docs-convert/legacy-links.tsv` argument. This ticket deletes that file, so this ticket must remove the argument - and it can only do that if the step already exists. If this ran first, the CI step would arrive pointing at a deleted file and exit 2 on every push.

## Edge cases & interactions

- **Removing `--pending` is part of this change, not a follow-up.** After the edit the CI step is `python3 tools/docs-link-check/check_links.py docs`, with nothing else. Run that exact command locally first: it must report **0 errors**. If it does not, `docs-convert-legacy-reference` has not finished and this ticket is not ready - stop and say so rather than restoring the argument or deleting the step.
- **Also drop the `tools/docs-convert` path filter** from the workflow if `docs-link-check-ci` added one (it was told not to, but check) - a filter naming a deleted folder is dead weight and misleads the next reader.
- **The root `README.md` has nine links into `Documentation/`**, on five lines (99-103 at commit `e414e316`): the product tour, the movie-rental tutorial, the D4 introduction, D4-compared-with-SQL, form automation, storage integration architecture, and the three book indexes (`UsersGuide.adoc`, `DevelopersGuide.adoc`, `DataphorReference.adoc`). `grep -o 'Documentation/[A-Za-z/._]*' README.md` lists them all. Every one has a converted page under `docs/users-guide/` or `docs/developers-guide/`; `tools/docs-convert/pages.tsv` maps each old source file to its new page, so read the map rather than guessing a name. Do this **before** deleting the tool, since the map goes with it.
- **The link checker does not check `README.md`.** Its roots are `docs/` only, so a wrong repointed link in the root README fails nothing. Check those nine links by hand, one by one, against the real file names - and note that the checker's rule about letter case applies to the reader's browser just the same.
- **Deleting `tools/docs-convert/` deletes the chain's provenance record with it** (added by the review of `docs-convert-legacy-reference`). Its README is where the five reference tickets recorded which pages under `docs/reference/` were hand-written and which were converted, where the published operator signatures came from, and why two pages were re-laid by hand. Most of that survives on the pages themselves, and the warnings about rerunning the converter stop mattering once its inputs are gone - so the expectation is that nothing moves. Read the README's *The pages written by hand* table and its `NOTE:` paragraphs once before deleting, and move anything a reader of `docs/` would still want into the plan's WS8 design notes; say in the handoff that you checked.
- **`AGENTS.md` describes both trees.** The `docs/` layout row says the Markdown was "converted from `Documentation/`"; the `Documentation/` row says the Markdown is the copy to read and edit "until `docs-remove-old-sources`"; the `tools/` row describes `docs-convert/` as the converter. The `legacy/` row and the code-search paragraph mention these trees too. Fix every one; grep rather than trusting this list.
- **`tickets/index-config.json`** excludes `Documentation/` and `legacy/` from the code-search index. The `legacy/` exclusion stays (other parked trees are under it); the `Documentation/` entry goes, because excluding a path that does not exist is a trap for whoever next reads that file.
- **`.gitattributes`** lists binary types for extensions that only these trees used (`*.cdr`, `*.jar`, `*.chm`, `*.emf`, `*.clk`, `*.cub`, and the upper-case variants). Leave them. They are declarations, they cost nothing, and `hygiene-gitattributes-editorconfig` owns that file; a pattern matching nothing is not a defect.
- **Nothing in the build or the tests reads either tree.** Verify rather than assume: grep the project files, `Directory.Build.props`, `Directory.Build.targets`, `tools/layout/Layout.csproj`, `global.json` and the two workflows for `Documentation` before deleting, and say in the handoff that you did.
- **Two open backlog tickets name individual files inside `legacy/Documentation/` and expect them to be recoverable afterwards.** `feat-revive-dropped-reference-documents` and `feat-dac-developers-guide` list sources whose prose nothing under `docs/` replaces, and both carry a `git log --diff-filter=D` recipe for getting a file back. Neither blocks this deletion - that is stated in both - but mention in the handoff that this commit is the one those recipes resolve to, so a reader who comes to them later knows what to look for.
- NOTE: `legacy/Documentation/Docs2.0/Images/Working/` holds nine CorelDRAW `.cdr` files - the editable originals of the entity diagrams whose exported `.emf` and `.svg` are published beside them, and the only editable copies in the tree. Nothing references them and no converted page uses one, so they are not a reason to keep the tree; but if a published diagram ever needs changing, the recipe below is how to get its source back.
- **Git history keeps the content.** This is a deletion of 113 MB from the working tree, not from history, so the clone size does not change. Say that in the handoff if anyone expects otherwise; `hygiene-large-binaries` already decided not to rewrite history.
- **Both `Documentation/` and `legacy/Documentation/` resolve case-insensitively on Windows.** `library-park-side-projects` had to do a two-step rename for exactly that reason. Deletion is not affected, but use `git rm -r` rather than a shell delete so the index is what decides what goes.
- **The plan's own text cites these paths in places that must stay.** Its old-to-new path table, its WS8 current-state paragraph and Appendices A and B are dated records of what was measured before the move; `repo-move-to-new-layout` and `hygiene-large-binaries` both deliberately left them. Change the rows that describe a *present* state (the layout table's "stay until WS8 converts them" entries, the WS12 large-binaries row, the WS8 work-item row) and leave the historical measurements alone.
- **Source hygiene.** `README.md` and `AGENTS.md` keep their existing line endings; edit the lines, do not rewrite the files.
