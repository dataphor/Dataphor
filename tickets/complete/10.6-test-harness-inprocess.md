It keeps the slug that `test-decouple-coverage-base`, `port-engine-runtime-fixes`, `port-catalog-emitter-race`, `store-remove-sqlce-references`, `store-sqlite-concurrency` and `build-ci` wait on.

## What landed

- **`CoverageScripts.cs`** (new `[TestFixture]`, 463 lines):
  - **Discovery.** `Cases()` reads the embedded manifest and lists `*.d4` (top level, extension compared exactly) in `<layout>\Libraries\TestFramework.Coverage.Scripts\Documents`. It starts no server. It yields one case per name, in ordinal order of the union of file and entry names, named after the script (`TestCaseData.SetName`):
    - a script case when both a file and an entry exist;
    - a failing case for a file with no entry ("not in the manifest") and for an entry with no file ("the script file is missing");
    - instead of all of these, `Harness.ManifestInvalid` (lists every problem) and/or `Harness.LayoutMissing`.
  - **Template.** `[OneTimeSetUp]` builds a template `TestServerInstance` with the fixed library set (`Libraries`, the spike's `COVERAGE_LIBS`), starts it, registers `Frontend` and then `TestFramework.Coverage.Base`, each in its own `try` (a failure goes to `TestContext.Progress`, not thrown), and stops it. It skips the template when discovery yields no script case. If the template itself fails, every script case fails with that error. A `NOTE:` at the second registration names K14 and `test-decouple-coverage-base`.
  - **Per script.** Copies the template's whole directory, starts a server on the copy, runs the script on a background thread with a 16 MB stack in one session and one process (`register` libraries, then `preamble`, then `ExecuteScript('Coverage.Scripts', '<script>')`), stops the process and disconnects in `finally` (nothing can escape the thread), stops the server, and disposes the directory.
  - **Timeout.** The test thread joins the worker for `timeoutSeconds` (default 120). On timeout it calls `Engine.TerminateProcessThread` on the worker's process, joins for up to 10 s more and records `HarnessTimeout: script did not finish within <N> s`, adding `; it did not stop when aborted and its server was abandoned` when the thread is still alive. An abandoned server is stopped on a background task (`TestServerInstance.Abandon`, waits at most 10 s), and its folder is left for the next run's sweep.
  - **Error text** (`ErrorText`): each exception down the `InnerException` chain as `Type: Message`, joined with ` <= `, CR/LF replaced by spaces, no truncation. Harness texts: `HarnessTimeout`, `HarnessRegister: <lib> <= …`, `HarnessStop: …` (appended with `; ` to the script's error), and `HarnessCleanup: …` (see the decisions below).
  - **Outcomes**, following the ticket's table: `pass` → Passed or Failed; `known-failure` → Warning when the text contains `error`, Failed when the text differs, Failed with "now passes; change its manifest entry to pass" when the script succeeds; `unstable` → Warning either way.
  - **Summary.** `[OneTimeTearDown]` writes one block: case count; `pass` passed/failed; `known-failure` matched/mismatched/unexpectedly passing, with a line per ticket; `unstable` per ticket; discovery problems.
- **`CoverageManifest.cs`** (new): `CoverageStatus`, `CoverageEntry` (JSON-mapped) and `CoverageManifest`.
  - The XML doc comment on `CoverageManifest` is the format reference.
  - It parses with `System.Text.Json` (`UnmappedMemberHandling = Disallow`, `AllowDuplicateProperties = false`, strict defaults: no comments or trailing commas, case-sensitive names). A JSON error is reported as a single problem.
  - Validation collects every problem: null entry; missing script; duplicate; out of ordinal order; unknown or missing status; `ticket` missing (unless `pass`), forbidden on `pass`, or not a lower-case hyphenated slug; `error` missing or empty on `known-failure`, or present on another status; `timeoutSeconds` outside 1–600; a `register` name outside the library set.
  - `Matches` is an ordinal substring test, with the localization `NOTE:`.

The counts follow in "Manifest".

## Decisions taken in implement (check them)

- **`TerminateProcessThread`, not `Engine.StopProcess(processID)`**, on timeout. In the first full run, `StopProcess` on `DebugTest` threw `NullReferenceException`. `StopProcess` is `TerminateProcess`: it aborts and waits for the thread, then disposes the process. At that moment the worker's own `finally` is disposing the same process, so two threads disposed one process concurrently (the NRE was `process.ServerSession` already null). `TerminateProcessThread` does only the abort-and-wait part, and the worker stays the only one that disposes. After the change: no error, and `DebugTest` stops within its 5 s.
- **`HarnessCleanup: …`** is a fourth harness text, not in the ticket. It is appended when the worker's `StopProcess` or `Disconnect` throws, so a process that cannot be stopped cleanly fails a `pass` script, as `HarnessStop` does for the server. After a timeout these errors are not read. Not observed in any run.
- **A server that fails to `Start`** fails its case outright (the exception propagates), whatever the manifest says, and is not counted in the summary.
- **The template is built in `[OneTimeSetUp]`**, but only when discovery yields a script case. So a filtered run that selects only discovery-problem cases still pays the 25 s template cost.
- When both the manifest and the layout are broken, both harness cases are yielded.
