## What landed

Layer **L7** of the WS3 test-suite layer table, for the example applications this repository ships: `tests/DAE.Server.Tests/SamplesCorpusTest.cs` makes one NUnit case per library folder under `samples/` - twelve today, found by walking the folder at discovery time - and gives nine of them a server of their own carrying that sample's requisite closure and nothing else, registers the sample there, enumerates its surfaces from the catalog and derives all eight page types of each. The other three report Inconclusive with a recorded reason. `tests/DAE.Server.Tests/CorpusLibrary.cs` is the reusable half: the discovery rule, the `.d4l` requisite read (through the engine's own deserializer, `Schema.LibraryUtility.LoadFromStream`) and the depth-first requisite closure, knowing nothing about samples, this repository or NUnit, which is what `compat-corpus-harness` (WS13) points at a corpus outside the repository.

The derivation check is shallow by design - a form must be produced, parse as XML, and have `<report>` as its root for the `Report` page type and `<interface>` for the other seven - because `test-frontend-derivation-golden` already compares every derived form of every surface any sample defines against a checked-in file. What this pass adds instead is discovery (a sample library added to `samples/` becomes a case with no code change), isolation (one server per sample, so a sample that only registers because a sibling created something first fails here), and the four samples the golden fixture does not carry at all. 16 surfaces x 8 page types = 128 derivations, 16 of them on the report branch.

Three recorded name-to-reason lists keep the pass honest, each asserted against the tree in both directions so none can rot into dead text hiding a sample nobody looks at: `NeedsADatabaseServer` (`Sample.Forum`, `Sample.Pubs`), `DefinesNoTableVariable` (`Sample.Components`, `Sample.Demo`, `Sample.Rental`, `Sample.ScriptAction`) and `NotInTheRuntimeLayout` (`Sample.Shipping`). A sample in none of the three must register, enumerate and derive; a sample in more than one fails as well. The one direction that needs a registered server to answer - "it now exposes a surface" - lives in the per-sample case; everything answerable from files alone is in the one server-free `EverySampleIsAccountedFor`.

Three existing helpers changed, each the smallest change that would do: `TestEnvironment.CopyLibraryFolders` is new and does the copying, with `CopyLibraries` now a wrapper that keeps its own name-aware failure message; `TestServerInstance` gained a constructor taking source folders beside the one taking layout library names, both delegating to a private constructor that holds the shared body; and `FrontendFixture.FlattenMessages` went from `protected` to `public` so this pass calls it rather than adding an eighth copy of an exception-chain walk.

Documentation: a new paragraph in AGENTS.md's "Build and test" beside the sibling corpus paragraphs, the neighbouring claim that "nothing else in the suite is skipped" amended (the three Inconclusive samples are now reported as Skipped by VSTest too), and a **Done** summary on the WS3 ticket-table row in `docs/modernization-plan.md`.

No `docs/migration-notes.md` entry, in the implement stage or this one: everything changed is in the `DAE.Server.Tests` assembly, which `tools/layout/Layout.csproj` does not ship and nothing outside the suite references, plus documentation, tickets and one MSBuild comment. No D4 semantics, class name, assembly name, file format, error code, WCF contract, port or on-disk layout is touched.

## Tests

The whole ticket is a characterization test for the sample libraries, per this project's testing rule. Three cases and nothing more:

| Case | What it verifies |
|---|---|
| `TheSampleRegistersAndDerives(sample)`, one per discovered sample (12 today) | the sample registers on a fresh server carrying only its own requisite closure; the surfaces it then defines agree with `DefinesNoTableVariable` in both directions; and every page type of every surface derives into a parseable form with the right root element. A sample in `NotInTheRuntimeLayout` or `NeedsADatabaseServer` reports Inconclusive with its reason and starts no server |
| `EverySampleIsAccountedFor` | the three lists and the tree agree in every direction answerable without a server: every entry names a real sample, the layout premise, the SQL-device premise, no sample in two lists |
| `TheSamplesDirectoryHoldsLibraries` | discovery found at least one library, so a renamed or moved `samples/` cannot turn the pass into one green case covering nothing |

The review added no test and cut none. It did not add one for `CorpusLibrary`'s getters, its `.d4l` parsing or its closure walk - every per-sample case exercises all three, and a wrong closure means a server missing a library, which means registration fails - and it did not add a golden comparison, which would be a second set of expected documents to keep in step with the first.

dotnet build Dataphor.slnx

Expect 11 passed and 3 Skipped (`Sample.Forum`, `Sample.Pubs`, `Sample.Shipping`, each printing its reason) in about 38 s. Note that VSTest's totals line counts the 11, not the 3: the skips appear only as their own lines.

The three "could not delete ... the next test run deletes it" lines are expected and were observed: only the *first* loader of each of three library assemblies cannot delete its folder, which is why the count is three and does not grow with the number of samples.
