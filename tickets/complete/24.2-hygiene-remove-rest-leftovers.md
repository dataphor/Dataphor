## What landed

`src/engine/DAE/REST/RESTResult.cs` and `src/engine/Server/REST/RESTMarshal.cs` are deleted with their `Compile` entries in `DAE.csproj` and `Server.csproj`; both `REST` folders are gone from the index and from disk. `Server.csproj` no longer takes `<PackageReference Include="Newtonsoft.Json" />`, and the sentence naming `RESTMarshal.cs` as that package's user is gone from the comment above the package group. `Newtonsoft.Json` stays in `Directory.Packages.props`: the native client interface (`src/protocol/NativeCLI`) and the `System.Internet` library still reference it, and both still ship it in the runtime layout.

The coverage area map's `excluded` entry for the two REST paths is dropped from `tools/coverage-report/areas.json`, and `docs/coverage-report.md`'s row for it now records the removal instead of claiming a current exclusion. The removal has a migration note (both types were public), a clause in `docs/architecture/what-is-alive.md`'s *Removed by the port* row, and a **Done** note on the WS12 plan row.

Implementation commit: `ticket(implement): hygiene-remove-rest-leftovers`.

## Review findings

The change is deletions of code nothing called, plus build configuration and documentation. There is no new logic, no new error path and no object whose lifetime changed, so the correctness, resource-cleanup, type-safety and performance angles had nothing to examine; the build is the evidence that the deletion is invisible to the product. What was worth checking was whether anything still pointed at the deleted paths and whether the documentation the change wrote is true.

**Checked.** The implement diff read before the handoff summary. Whole tracked tree grepped for `RESTResult`, `RESTMarshal` and the two folder paths (remaining hits: `legacy/` sources, which are parked and keep their own copies; `docs/`; one historical `tickets/complete/` record; and the coverage tool's test, fixed below). `Newtonsoft.Json` references in the modern tree enumerated to confirm the surviving two and that the removal of the server's direct reference changes no deployment. Runtime layout checked for both `Newtonsoft.Json.dll` copies after a fresh build. The plan checked for a planned HTTP or JSON interface that would have wanted these helpers - Q7 parks the web prototypes and no work item plans one, so the deletion does not contradict the plan. `areas.json` parsed. No accepted-tradeoff `NOTE:` at any site touched.

**Minor findings, all fixed in this pass.**

- `docs/architecture/what-is-alive.md` claimed "nothing in the product marshals engine values to JSON". That is false: `System.Internet`'s `JSONObjectConveyor` writes a JSON object to a scalar's stream, and `NativeCLIHelper` reads a JSON object into a native value. Reworded to say no shipped assembly converts engine *results* to JSON any more, and to name the two places JSON still lives so a reader is not surprised by them.
- The migration note said the server assembly "no longer references Newtonsoft.Json", which a reader could take to mean the assembly disappears from a deployment. It does not - the server still receives it transitively through its project reference to the native client interface, and `bin\` is unchanged. The row now says "directly" and says where the package still comes from.
- The migration note's row sat in the middle of the *Custom C# extensions* table rather than at the end, where this running list appends. Moved to the end of the section; no text changed by the move.
- `tools/coverage-report/test_coverage_report.py` used `src/engine/DAE/REST/` and `src/engine/Server/REST/RESTMarshal.cs` as its synthetic excluded-path fixture - the last live reference to a path that no longer exists, and a false lead for anyone grepping the tree. Repointed at `artifacts/`, which is the one exclusion the real map still has. 14 tool tests pass.
- The ragged comment paragraph in `Server.csproj` that the handoff flagged for a reviewer: the three lines of that sentence are rewrapped. Comment text is unchanged apart from the wrap.

**Major findings: none.** Nothing reached the filing bar, so no ticket was filed.

**Tripwires: none recorded.** There is no condition under which this removal becomes work again: the deleted code has no callers in the built tree and its only historical consumer is parked in `legacy/` with its own copy.

**Tests: none added, and the implementer's decision not to add one is upheld.** No behaviour changed, so there is nothing to characterize; the project's rule that a subsystem change owes a characterization test does not bite on removing code with no callers. The surviving JSON paths are already pinned by `JSONObjectConveyorTest` and the `Internet` coverage script, both of which were run.

**Known gaps carried forward (both by design).** `docs/coverage-report.md`'s generated tables still count the 203 deleted lines, because the page records one measured run and everything below *Line coverage per assembly* is regenerated wholesale by the next instrumented run; the row above now says so. The second `excluded` entry in `areas.json` still names the retired umbrella slug `debt-ws12-hygiene-remainder`; `hygiene-remove-dead-compiled-files` (sequence 24.3) deletes that entry outright and its TODO list says so, so repointing it here would have been churn.
