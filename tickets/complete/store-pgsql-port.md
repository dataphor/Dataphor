## What landed

The PostgreSQL catalog store — the back end that keeps a Dataphor server's *own* catalog in a PostgreSQL database instead of in a SQLite file — is built, in the solution, in both host executables, in the runtime layout, and held to the same fifteen-case store contract the SQLite and SQL Server stores pass. It is the third shipping store. SQLite is still the default and still the recommendation.

The plan's bar for porting it was that it should need **only the store contract tests to pass**, and that bar was met in the narrow sense that matters: nothing in `src/engine/DAE/Store/` or `src/engine/DAE/Device.Catalog/` changed. The store works on the shared store machinery exactly as it stands.

The implement stage is commit `ticket(implement): store-pgsql-port`. Review added one fix with its reproduction test, two comment corrections, one small refactor in the test harness and four documentation corrections; all are listed under *Review findings*.

**The store.** `src/engine/Store.PGSQL/DAE.PGSQL.csproj` became an SDK-format project modelled on `DAE.MSSQL.csproj`, with the catalog seed script `SystemStoreCatalog.sql` embedded under the name `CatalogStore.Initialize` reads it by. Three dead things from release 3.1 went: a second `InternalCreateConnection` behind `#if USESQLCONNECTION` that returned a *SQL Server* connection from the PostgreSQL store (the constant was defined in the same file and never undefined, so it was one edit away from compiling), and the `#define` itself in both files. `ShouldEnsureDatabase` was a property that was set and never read; it now does what both other stores do, creating the database the connection string names from a connection to the stock `postgres` database. `HasTable`'s lower-casing of the table name became invariant rather than current-culture: PostgreSQL folds an unquoted identifier and the whole store agrees that it does, but under a Turkish or Azeri culture `ToLower()` turns the `I` of `DAEServerInfo` into a dotless `i`, and the store would then report that it has no catalog and seed itself over the one it already wrote.

**The store reports no multiple active result sets**, as 3.1 had it, and that is the one behavioural difference a deployment can see. The engine reads that flag for exactly one thing: it turns on `CatalogStore.UseCursorCache`, which keeps a finished cursor's reader open past `CloseCursor` so a later open of the same index reuses it. So the trade is one extra statement per catalog read against never holding two readers on one connection — which is all the PostgreSQL driver allows. No method of `CatalogStore` nests two cursor opens (each reads its rows into a list, closes, and opens the next), which is why this store needs no equivalent of the SQL Server store's forced `MultipleActiveResultSets=True`.

**The layout, and the one thing no build check could see.** This is the only store whose connection classes live in a D4 library (`libraries/PGSQLConnection`) rather than in the engine, and a catalog store is loaded *before* any library is registered — the library resolver is built out of what the catalog says is registered, which is what the store exists to read. So `bin/` has to hold the library's assembly and `Npgsql.dll` as well as the store: a named rule in `tools/layout/Layout.csproj` puts them there, and `bin/` goes from 84 to 89 top-level files. The same project reference also dragged the OLE DB and ODBC package closure of the library `Connection` into `bin/`, where `System.Data.OleDb` wants `System.Configuration.ConfigurationManager` 10.0.15 and `Microsoft.Data.SqlClient` wants 9.0.21 and `bin/` holds one file per name; the reference is now `PrivateAssets="all"`, which keeps the pairing the `.d4l` requires without letting the packages reach a consumer.

**A new general guard.** Both hosts' dependency files *named* the connection assembly while the layout did not copy it — a failure that appears only when an instance configured on this store starts, which no build check and no existing test saw. `HostProgramTest.TheRuntimeLayoutProvidesEveryAssemblyTheHostsDependencyFilesName` now holds the layout to providing every `.dll` either dependency file names (153 each), which is the general form of the class rather than a line about this one store.

**The contract fixture.** `PGSQLStoreContractTests` is the third subclass of `StoreContractTests`, gated on `DATAPHOR_TEST_PGSQL`, with no case of its own. Three facts about the back end became hooks on the base fixture, each defaulting to what the two SQL Server dialect stores already had: the text column type (`nvarchar(20)` / `character varying(20)`), the boolean column type (`tinyint` / `boolean`) — PostgreSQL has neither `nvarchar` nor `tinyint` — and whether text can hold an embedded NUL, which PostgreSQL refuses outright (SQLSTATE 22021). The two-cursors case now states what each kind of store does instead of assuming multiple result sets. No case, no assertion and no expected result differs between the three fixtures.

**Documentation.** `AGENTS.md` (the store row, the `DATAPHOR_TEST_PGSQL` section and its container recipe, the skip roll-up), `docs/architecture/catalog-and-store.md`, `docs/users-guide/dataphor-service.md` (the `catalogstoreclassname` prose with the instance XML and the four things to know, and the PostgreSQL versions section, which previously said there was no PostgreSQL catalog store), `docs/migration-notes.md`, `.github/workflows/build.yml`, and the plan.

## Review findings

The review read the implement diff first, then re-derived the two load-bearing claims from the engine source rather than taking them from the handoff, and re-measured every number in it. Everything it checked is below, including the categories that came back empty.

**Checked and confirmed, by reading and by running.**

- **`_supportsMARS = false` is safe**, which is the one decision that could have corrupted a catalog. Read every cursor open in `CatalogStore.cs` and every holder of a store cursor outside it (`ServerCatalogDeviceSession` has three, all over an in-memory table): none nests. `SQLStoreCursor.InternalInsert` and `InternalUpdate` call `DisposeReader()` before the generated write, so a write under an open cursor needs no second reader either. The handoff's "none of the 88 is nested" holds.
- **The seed script is the same catalog in another dialect.** Compared `src/engine/Store.PGSQL/SystemStoreCatalog.sql` against the SQL Server one mechanically: same 27 tables, same 20 indexes, same column names in the same order in every table, and one consistent type mapping (`nvarchar(n)`→`character varying(n)`, `ntext`→`text`, `tinyint`→`boolean`, `int` and `nchar(2)` unchanged — PostgreSQL resolves `nchar` to `character`).
- **The shipped executable, end to end.** Started `artifacts/layout/debug/bin/DAEServer.exe` on a PostgreSQL 18.7 catalog store with no such database: 37.0 s, the store created the database, 1,251 catalog objects / 1,704 objects / 1,078 operators written; restart on that catalog 24.7 s; nothing matching error, exception or warning in either instance log. Reproduces the handoff (36.9 s / 26.2 s) within measurement noise.
- **The layout.** `bin/` holds 89 files including `Alphora.Dataphor.DAE.PGSQL.dll`, `Alphora.Dataphor.DAE.Connection.PGSQL.dll` and `Npgsql.dll`; `Libraries/PGSQLConnection/` still holds its own copies; both `.deps.json` name `System.Configuration.ConfigurationManager/9.0.21` and the file in `bin/` is 9.0.21, so the `PrivateAssets` fix left the two agreeing.
- **The three things the handoff asked to be checked.** With `DATAPHOR_TEST_PGSQL` unset every case reports Inconclusive with the sentence naming what to set; twice in a row passes 15/15 both times; and the drop-before-the-run is what makes the second run clean.
- **PostgreSQL really does refuse an embedded NUL**, so the `TextCanHoldEmbeddedNul` hook is not hiding a store defect: `insert into nultest values (E'a\000b')` straight through `psql` gives `ERROR: invalid byte sequence for encoding "UTF8": 0x00`, the exact error the fixture cites.

**One defect found and fixed, with its reproduction.**

- **The create-database probe missed one of the driver's two spellings of the database keyword.** `PostgreSQLStore.EnsureDatabase` looked only for `Database`, and Npgsql also accepts `DB` — not as an unknown keyword it would reject, but as the same setting. So a `catalogstoreconnectionstring` spelling it `DB` got no database created and a first start failed with PostgreSQL `3D000` naming the database the store was supposed to make. Measured, not inferred: the shipped `DAEServer.exe` on such a configuration failed exactly that way. The fix reads both spellings and replaces the name under the spelling the connection string used, as `MSSQLStore` already reads both of SQL Server's (`Initial Catalog` and `Database`). `tests/DAE.Server.Tests/PGSQLStoreEnsureDatabaseTest.cs` is the reproduction, one gated case; it fails with the fix reverted ("the store left the database its connection string named unmade") and passes with it, and the shipped executable now starts and writes a full catalog on the aliased spelling. The canonical spelling needed no new test — `PGSQLStoreContractTests` makes its own database through this probe on the first case of every run.

**Two comment corrections, where the tree now contradicted itself.**

- `MSSQLStore.InternalInitialize`'s comment attributed its forced `MultipleActiveResultSets=True` to `CatalogStore` opening `PK_DAEBaseCatalogObjects` "inside the loop" over `PK_DAECatalogObjects`. It does not: `SnapshotBase`, `SelectBaseCatalogObjects` and the name-table writes all read into a list, close, and open the next. What actually holds the first reader open is the cursor cache, which that store's own `_supportsMARS = true` turns on — so the conclusion was right for the wrong stated reason, and the new PostgreSQL store's comment (which names the cache correctly) read as a flat contradiction of it. The comment now names the mechanism and points at the other store for the other side of the trade.
- `docs/architecture/catalog-and-store.md` carried both claims in one paragraph for a reader to trip over. The SQL Server sentence now gives the same mechanism; the page is at 1,451 words of its 1,500 cap.

**One refactor in the test harness.** The review's new fixture would have been the third verbatim copy of "drop this database from the stock database, with `(force)`", so that moved to `TestEnvironment.DropPGSQLDatabase`, which is where this suite's PostgreSQL housekeeping already lives, and `PGSQLStoreContractTests` uses it too.

**Three documentation corrections.** `docs/migration-notes.md` sent the reader to "the three things to know about this store" where the user's guide lists four, and named only three — the fourth, the cursor difference, is now in both. The user's guide said the first server start took 40 seconds where the measurement was 36.9; it now says 37, and gives the restart as the range the two independent measurements span. `AGENTS.md` and the CI cost comment gained the new gated case.

**Tripwires parked, not filed.** Both are conditional — fine now, work only if something changes:

- `tests/DAE.Server.Tests/StoreContractTests.cs`, above `PGSQLStoreContractTests`: this fixture and the SQL Server one are the same forty lines around a different server, which is cheaper to read than a shared base with a hook for each of the seven things they vary. A *third* server-backed store would change that answer.
- Already at their sites from the implement stage and still right: the cursor cache being off on this store (`PGSQLStore.InternalInitialize`), and two simultaneous runs of a fixture sharing one database name.

**The two judgement calls the handoff put to a reviewer, and how they came out.**

- **Parameterizing the contract on three back-end facts: accepted.** All three are properties of the server that no amount of store code could change, and two of them (the column types) are the difference between the contract running against this store and not running at all. The NUL hook is the only real call, and where it is false only the NUL is dropped: the quotes, the quote beside a statement separator and the closing parenthesis — the characters the parameterized writes exist for — are all still asserted. Routing the store to `blocked/` over PostgreSQL's refusal of a byte no catalog column can hold would have parked a store that demonstrably runs a real server's catalog, and the precedent (`store-mssql-port`) shipped a store with a *silent* text-loss limitation where this one is a loud error.
- **`LibraryLoadingTest`'s lost assertion: accepted, and the trade is the right way round.** The PGSQLConnection arm used to assert that an `Npgsql` assembly was in the loaded set, on the ground that only the library's `.d4l` entry could have loaded it. That ground is gone — checked: `Npgsql.dll` is now in `artifacts/bin/DAE.Server.Tests/debug/`, where the default load path finds it before the resolver ever fires — so the assertion could have passed without anything registering, and removing it rather than weakening it was correct. The resolver mechanism is still properly proved by the other four arms, whose private packages (`Newtonsoft.Json.Bson.dll`, `Microsoft.Data.SqlClient.SNI.dll`, `System.Data.OleDb.dll`, `System.Data.Odbc.dll`) are confirmed absent from that folder. Moving the store fixture to a project of its own to recover one assertion would cost a whole test project and a second layout dependency; not worth it.

**Empty categories, and why.** **No tickets filed.** The one defect found had a local fix with a local reproduction, which the project's rules say is fixed in the ticket that meets it; nothing else reached the filing bar. **No tests cut.** The contract's fifteen cases are the specification of a behaviour each, the three new hooks removed no assertion, and the one assertion that did go had become unfalsifiable — the review re-derived that independently rather than taking it on trust. **No accepted-tradeoff notes re-opened**: the `NOTE:` at `PGSQLStoreConnection.HasTable`'s site and `bug-pgsql-device-identifier-case` both concern the device's per-table reconciliation, a different site, and neither revisit condition has tripped. **No pre-existing failures met**, so no `tickets/.pre-existing-error.md`.

## Known gaps carried forward

- **Nothing automated starts the shipped host executable.** The end-to-end start above is a hand measurement, twice now. That is `debt-test-shipped-host-executable`'s subject, and it is blocked on the shipped host having no way to be told not to write the Windows event log.
- **Encryption is unmeasured**, as it is for the PostgreSQL device: the containers accept unencrypted connections, which is what the driver then used. The user's guide says so rather than implying otherwise.
- **The cursor cache being off is not measured against a large catalog.** Recorded at the site and in one sentence of the user's guide.
- **`docs/architecture/catalog-and-store.md` is at 1,451 words of its 1,500 cap.** The next substantive change to that page has to split it; `python tools/docs-size-check/check_size.py` is the gate.
