## What landed

Five compiled-but-unreferenced files deleted with their `Compile` entries: `src/engine/Base/IndexList.cs` and `src/engine/Base/TemporaryStream.cs` (assembly `Alphora.Dataphor`), `src/engine/DAE/Streams/CopyOnWriteStream.cs` and `src/engine/DAE/Debug/DebugContext.cs` (assembly `Alphora.Dataphor.DAE`), and `src/engine/Server/Connection/GenericDotNetConnection.cs` (assembly `AlphoraDataphorServer`). Seven public types in all, counting the nested `IndexList.Node` family and the `DebugContexts` stack and `GenericDotNetCommand` that travelled with their files. One migration note under *Custom C# extensions* covers all five, says nothing an application, a D4 script or a deployment script can observe changes, and names `DotNetConnection` as the base a custom connection class keeps deriving from.

`TableForEachNode` in `src/engine/DAE/Runtime.Instructions/ListNodes.cs` is dead in the same sense and stays: its comment is now an accepted-tradeoff `NOTE:` saying what was declined, why (`DAERegister.GetClasses()` publishes every `PlanNode` subclass under a D4 class name, so the class is `System.TableForEachNode` and retiring it touches a compatibility surface), and the revisit condition.

Documentation brought in step: the coverage report's four places that described these files as pending removals, the WS12 plan row, and the one sentence in `docs/reference/compiler-defines.md` that described a `#define DEBUG` at the top of a file this change deletes. The coverage area map lost its three-path exclusion and the one `paths` entry that named a deleted file.

## Review findings

**Re-derived rather than trusted, and both checks hold.** The implement handoff rests entirely on two claims, so both were redone from scratch against `ticket(implement): hygiene-remove-dead-compiled-files`.

- *Nothing references the deleted types.* Searching the tree for all seven names as whole words, excluding `tickets/` and the git-ignored `artifacts/`, leaves hits only in `docs/coverage-report.md`, `docs/migration-notes.md` and the plan row — all of them deliberate historical prose. Nothing in `src/`, `libraries/`, `samples/`, `tests/` or `tools/`.
- *No D4 class name disappeared.* Both `DAERegister.GetClasses()` methods (`src/engine/DAE/Register.cs:20`, `src/engine/Server/Register.cs:20`) register only subclasses of `PlanNode`, `Schema.Device`, `Conveyor`, `Schema.DeviceOperator` and `Schema.DeviceScalarType`, and none of the five deleted classes derives from one of those. Followed one step further than the handoff did: `ClassLoader.GetClass` resolves a D4 class definition *only* out of the registered list each assembly's `GetClasses()` builds (`src/engine/DAE/Device.Catalog/ClassLoader.cs:89`), with no fall-back to a type name, so an unregistered class was never nameable from D4 — including through a device's `ConnectionClass`. The safety argument is sound, and stronger than stated.

**Fixed in this pass.**

- `docs/reference/compiler-defines.md` was left with two consecutive blank lines where the removed sentence had been. Collapsed.
- `tools/coverage-report/areas.json` held a `paths` entry naming a file this change deletes, which the implementer caught by hand and flagged — the second hygiene ticket in a row to need that same manual catch (`hygiene-remove-rest-leftovers` was the first). Rather than accept a third, added `ShippedMapTest` to `tools/coverage-report/test_coverage_report.py`: it reads the checked-in `areas.json` and asserts every path under `src/`, `libraries/`, `samples/`, `tests/` or `tools/` is in the tree, exempting generated roots a clean clone has not built. Mutation-checked — restoring the deleted `TemporaryStream.cs` path to the *Streams* area fails it with the area named — then reverted. This is the only test added; it pins a hand-maintained manifest against the tree, which no compiler or lint rule checks here.
- The WS12 plan row now names that test, in the shape earlier hygiene rows use for a review addition.

**Found, measured, and deliberately left alone.** Deleting these files orphaned four error codes — `StreamsException.Codes.CopyOnWriteOverflow`, `BaseException.Codes.Duplicate`, `ConnectionException.Codes.ProviderFactoryAlreadyConstructed` and `ConnectionException.Codes.ProviderInvariantNameRequired` — each of which had its only thrower in a deleted file. Removing an error code is a compatibility surface change, so keeping them is right, and no `NOTE:` was added at the sites: counting declarations of the form `Name = <number>` against every `Codes.Name` use in `src/` and `libraries/` gives 262 of 1,001 error codes already with no thrower in the tree, so an unraisable code is the normal state of this enum set and a note at four of them would say nothing a reader could act on.

**Checked and clean, with the reason.**

- *The two edits outside the ticket's file list*, which the handoff asked to have looked at. Both are right: each deleted the only thing its text named. Dropping the `compiler-defines.md` sentence leaves the page silent about a switch that no longer exists rather than pointing at a missing file, and the page's counts are unaffected — the sentence was explicitly about a `#define` that is *not* one of the 55 behaviour switches it indexes.
- *Nothing stale left in docs.* Searched for the concepts as well as the names ("copy-on-write", "index list", "temporary stream", "debug context", `DbProviderFactory`): the remaining hits are the engine's live copy-on-write stream behaviour in `ServerStreamManager` and its tests, an unrelated SQL device error message, and a settings-folder migration entry about the server's temporary stream *files*. None refers to a deleted type.
- *Every path in the shipped coverage map exists* — now by the new test rather than by hand.
- *No code review findings in the deleted content*, because there is no surviving code to review: the change is five whole-file deletions, five one-line project edits and a comment rewrite. The `TableForEachNode` note is long, but every line of it is what the code cannot say — what was declined, why, and when to revisit — and the load-bearing half of the old comment (the three nodes hold one copy each of the same lending code, so a fix applied to two of three is the hazard) is kept.
- *No tests cut.* The implementer added none, which was the right call: none of this code ever ran, so there is no behaviour to characterize.

**Nothing filed.** No finding reached the filing bar: the one class-level invariant worth having (the map going stale) was cheap enough to land here rather than queue, and nothing else was more than cosmetic.
