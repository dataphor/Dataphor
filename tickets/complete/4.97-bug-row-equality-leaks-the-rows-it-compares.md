## What landed

Two nodes in `src/engine/DAE/Runtime.Instructions/RowComparisonNodes.cs` joined the const-operand rule that `docs/architecture/operand-ownership.md` describes, and a reflection test now holds the list of nodes that owe that rule by hand. The implementation is `ticket(implement): bug-row-equality-leaks-the-rows-it-compares`; this ticket records it and the review pass over it.

**`RowEqualNode`** - what `=` and `<>` between two rows compile to, and therefore what a transition constraint, a key comparison and `in` over a row-valued list compile to:

- `DetermineDataType` calls `base.DetermineDataType(plan)` instead of `DetermineModifiers(plan)`. That is the only path that reaches the `const` branch of `InstructionNodeBase.DetermineDataType`, which is the only place that asks an argument node to lend the value it already holds (`PlanNode.SetByReference`).
- `InternalExecute(Program)` is an ownership wrapper: evaluate the left, evaluate the right inside a `try` whose `catch` releases the left where this node owns it, then compare inside a `try` whose `finally` releases each side where `Nodes[index].ReturnsByReference` is false. The comparison itself - nil propagation, the `_comparisonNode` stack push, the run-time branch - lives in a private `InternalCompare(Program, object, object)`.
- The run-time branch (either operand's type a generic `row`, which `operator F(const A : row, const B : row)` produces) builds its inner `RowEqualNode` over a private `BorrowedValueNode` rather than `ValueNode`, so the inner node leaves alone the two values the outer one still owns.

**`CompoundScalarEqualNode`** - the equality the compiler generates for a scalar type whose single representation has more than one property (`Compiler.CompileComparisonOperator`, which declares both operands `const`): the same two halves, with nil propagation moved inside the `try` so a nil on one side still releases the other, and each `DataValue.FromNative` wrapper held as `IDataValue`, cleared of `ValuesOwned` and disposed in a `finally`.

**The guard.** `tests/DAE.Server.Tests/OperandOwnershipShapeTest.cs` reflects over the engine assembly for every non-`TableNode` subclass of `InstructionNodeBase` that declares `InternalExecute(Program)` itself, and compares the set with a checked-in list of eighteen names - the five argument shapes plus the thirteen reviewed nodes. Its failure messages tell a node's author what to do: apply the rule and add the node to the list, or remove a node that no longer has the shape. No server and no base class.

## Tests

- `AssignmentValueOwnershipTest.RowEqualityReleasesTheRowsItCompares` - four shapes through `AssertShapeLeavesNoStreams`, each naming itself. The computed rows verify the release half, the row variable the asking half, the two-column row the per-column arithmetic, and the generic `row` operand the run-time branch and so `BorrowedValueNode`. Each shape reads its own result, so a comparison that silently stopped happening cannot pass vacuously.
- `AssignmentValueOwnershipTest.RowEqualityGivenVariablesLeavesTheCallersRowsAlone` - the loan, which the count cannot see: lending without releasing and releasing without copying both balance the count. Two row variables, so each argument node is a separate loan; asserts the comparison answered true every time and that both rows' columns are still readable afterwards.
- `AssignmentValueOwnershipTest.CompoundScalarEqualityReleasesTheValuesItCompares` - a `ZCompoundBinary` type with a `Binary` and an `Integer` property, compared as computed values and from a variable, with the result read both times and the variable's property read afterwards. `tests/libraries/TestFramework.Coverage.Scripts/Documents/Types.CompoundEquality.d4` is untouched: it is all-`Integer` and cannot see a stream leak.
- `OperandOwnershipShapeTest.TheNodesOutsideOperandCleanupAreTheOnesReviewedForIt` - the class guard above.

The review added no test and cut none. The four above each pin a behaviour the engine has no other coverage for, and every finding the review raised was a claim in a comment or a document rather than a defect in the code, so there was nothing new to reproduce.

## Review findings

### What was checked

The implement diff was read before the handoff summary. Beyond reading it: traced `base.DetermineDataType` through to the `const` branch and confirmed from `src/engine/DAE/Schema/SystemCatalog.d4` and `Compiler.CompileComparisonOperator` that both operands of both operators really are `const`; confirmed `base` guards its own body on `Operator != null`, which is what the inner generic node relies on; confirmed `Compiler.Upcast` returns its node unchanged (`USETYPEINHERITANCE` is undefined), so the comments' claim about it is true, and that reading `ReturnsByReference` off `Nodes[index]` at run time is right for the `Compiler.ConvertNode` case, where the wrapper owns the converted value and its own const cleanup leaves the lent source alone.

Walked the release arithmetic on both nodes: for a row, the argument node hands back an `IRow` and `DataValue.DisposeValue` disposes it, releasing its column streams only where `ValuesOwned`; for a compound scalar the native is a `NativeRow` that `DisposeValue` walks, and the two `FromNative` wrappers are cleared of `ValuesOwned` and disposed before the native is released, so each stream is released exactly once. Checked the early-return and raise paths: nil propagation is now inside the try in both nodes, and the `catch` around the second argument matches what `InstructionNodeBase.ReleaseUncalledOperand` does, whose const rule is the same on both paths.

Checked who else can build these nodes: `RowEqualNode` only through its registered class name and the inner node in `InternalCompare` (`TableComparisonNodes`'s `RowEqualNode` property is a compiled expression, not this class), and `CompoundScalarEqualNode` only through `Compiler.CompileComparisonOperator`. Confirmed the handoff's inspection argument about `BorrowedValueNode` and `PlanNode.Clone`: `Clone` does clone child nodes, but the inner node is built inside `InternalExecute` and discarded, so no reference escapes for anything to clone. Spot-checked one entry on the reviewed list rather than taking the page on faith - `RowExtendNode`'s early `sourceRow.IsNil` return releases nothing, which is safe because `Row.IsNil` is `_row == null`, so there is no native to release.

### Found and fixed in this pass

- **The guard reached less than the claims it backs.** It reflects `typeof(InstructionNodeBase).Assembly` - the engine - and three nodes of exactly the dangerous shape live outside it: `InsertNode`, `CopyNode` and `CopyTablesNode` in `libraries/System.Integration/Source/IntegrationNodes.cs`, non-`TableNode` subclasses of `InstructionNodeBase` that override `InternalExecute(Program)`. All three were read: their operands are tables the node never evaluates as values (`ExpectsTableValues = false`) plus `String` and `Boolean` arguments, whose natives the garbage collector reclaims, so there is nothing stream-backed to release and no leak. The Server assembly was checked too - every non-table instruction node there overrides the `object[]` shape, so it contributes nothing. Fixed in three places: the fixture carries a `NOTE:` naming the three and the condition to widen on, the architecture page says the guard reads the engine assembly only, and `docs/migration-notes.md` no longer tells extension authors that their node "fails that test until it is added to the list" - it would not; the obligation is theirs and the entry now says so.
- **A count wrong in the new fixture's own remark**: "The nine that re-override the entry point" - it is ten (`RowEqualNode`, `CompoundScalarEqualNode`, the six table comparisons, `RowExtendNode`, `RowRedefineNode`), as the architecture page says. The guard exists because a hand count went wrong; the fix kept the hand count wrong in the fixture that replaced it.
- **The gap the handoff flagged in the list of simple names** is closed rather than left standing: a third assertion in the same `Assert.Multiple` fails on a repeated simple name and says to compare full names. Two engine types sharing one name would otherwise have matched the list with only one of them reviewed. Cheaper than eighteen namespace-qualified strings.
- **Lambda parameters in the new fixture used the pre-modernization `A`-prefix** (`AType`, `AName`) where the rest of the suite uses camelCase. Renamed.
- **The `ValueNode` hazard was recorded at the wrong site and understated.** The `NOTE:` at `BorrowedValueNode` framed a `SetByReference` on `ValueNode` as the cheaper design; what it did not say is that `ValueNode` hands back the value it holds *without copying it* while answering `ReturnsByReference` false, so a const operand releases a value the node still holds and will hand back again on the next execution. The `NOTE:` now lives at `ValueNode` in `ImperativeNodes.cs`, where whoever builds one will meet it, and states that. Each site was checked before claiming it bites nothing today: folded literals are natives the garbage collector reclaims; `RestrictTables.cs` builds one over an order column's value, and a stream-backed type has no comparison operator so it cannot be an order column (`SystemCatalog.d4` gives `Binary` only `iEqual`); `CatalogNodes.cs` builds one over a compound value whose properties are all parser literals, which `IsParserLiteral` admits no stream-backed type into. The remark at `BorrowedValueNode` now points there.

### Parked as tripwires, not tickets

- The guard's assembly reach, above: fine now, and work only if a library node of that shape takes an operand with a stream behind it - a `Binary` or a `Graphic`, or a row or list holding one. Its home is the `NOTE:` in `tests/DAE.Server.Tests/OperandOwnershipShapeTest.cs`, with one sentence on the architecture page.
- The `ValueNode` lending question, above, re-sited to `ValueNode` itself with the hazard stated and the condition to act on it.

### Considered and declined

- **A shared helper for `if (!Nodes[i].ReturnsByReference) DataValue.DisposeValue(...)`**, six copies across the two nodes. Declined: `IfNilNode` and the five argument shapes in `InstructionNode.cs` all spell that predicate inline, so a helper would make these two the odd ones out, and a new `protected` member on `InstructionNodeBase` is extension surface needing its own migration-notes entry for no change in behaviour.
- **A parameterless constructor on `BorrowedValueNode`** so `PlanNode.Clone` could not throw on one. Declined: nothing can clone it, since no reference escapes `InternalExecute`, and an unused constructor to satisfy an unreachable path is worse than the inspection argument the remark now carries.
- **Splitting the 1,769-line `AssignmentValueOwnershipTest.cs`**, as the implement stage also declined. Its head `NOTE:` names the two backlog tickets that hold the split open; both were confirmed on the board, and `bug-a-cursor-loop-variable-stays-stale-once-written` does say its taker should split first.

### Major findings: none, and no ticket filed

Not "looks good": the reason is that nothing survived as a defect. Every path traced above releases each value exactly once, and the one class-level gap found - the guard's assembly reach - causes no defect today, so it is an honest sentence and a tripwire rather than work. The architecture ladder was climbed on it: the rung that would retire the class is widening the reflection to the library assemblies, which are compiled into their own assembly and loaded only when the library is registered, so the guard would have to load them by hand for no behaviour it can protect today. Not worth a ticket; worth the condition that makes it worth one.
