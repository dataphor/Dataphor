## What landed

The golden half of layer L5 of the WS3 test suite. `FrontendDerivationGoldenTest` (new, on the `FrontendFixture` server) derives every page type of every table variable the carried libraries define and compares each resulting form, character for character, with a file checked in under `tests/goldens/frontend/<Library>/<Surface>.<PageType>.xml`.

Vocabulary, for a reader without the ticket in front of them: **derivation** is the Frontend server library turning a D4 table expression into a form; a **surface** is a table variable (a table or a view) a library defines; a **page type** is the kind of form to build from it (`Browse`, `Edit`, …). The entry point is the D4 operator `Frontend.Derive(<expression>, <page type>)`, which returns the form as a single-line XML string.

- The corpus is 52 surfaces across eight of the fixture's ten libraries (`System.Platform` and `SimpleDevice` define no table variable of their own), crossed with the eight page types the engine builds: 416 cases, of which 369 derive and are checked against a golden, and 47 fail — all of them `OrderBrowse`, all covered by one expected-failure row naming `bug-orderbrowse-derivation-fails`. 369 files, 1,185,018 characters, 2.0 MB on disk; largest 8,677 bytes (`Sample.IssueTracker/IssueDetail.Browse.xml`).
- `tests/goldens/` is new, deliberately above the test project so that `test-device-sql-golden` (WS3 L3, not yet filed) can put its golden SQL beside it. The directory is found through a new `DataphorGoldensDir` `AssemblyMetadata` entry read by `TestEnvironment.GoldensDirectory`; no path is spelled in code.
- `DATAPHOR_UPDATE_FRONTEND_GOLDENS=1` makes the pass **write** the files instead of comparing them, delete the ones no case produces, and then fail the run anyway, so an update can never be mistaken for a pass. Documented in AGENTS.md beside `DATAPHOR_TEST_LOGGING`, with the rule that the diff is the review.
- A golden is the derived document *printed* — indented with tabs, one element per line, LF, UTF-8 with no byte-order mark, no XML declaration, ending in a newline — because what `Derive` returns is one long line, and a single-line file makes every change read as a whole-file rewrite. Both sides of the comparison go through the same printer. No normalizer: derivation was measured deterministic across two independently created server instances.
- The sets must agree exactly in both directions: a case with no golden, a golden no case produces, a failure with no expected-failure row, and a row no failing case matches each fail the run — which is how the `OrderBrowse` row drains when that defect is fixed.
- `.gitattributes` gained `tests/goldens/** text eol=lf`, so a checkout cannot convert files the pass writes and compares with newlines.
- `FormCustomizationTest.DeriveAcceptsTheBrowsePageType` is deleted, which its own `NOTE:` asked this ticket to do once the goldens covered `Browse` for every surface.
- No `docs/migration-notes.md` entry: nothing an application, a deployment script or a C# extension can observe changes.

The implement stage also corrected the plan ticket's measurement, which said 45 surfaces, 360 cases and 320 goldens, and that `System.Internet` defines no table variables. It defines seven, all of which fail `OrderBrowse`; the probe that produced the plan's numbers never enumerated that library. `tickets/fix/bug-orderbrowse-derivation-fails.md` was corrected in place to 47 of 52.

The `.gitattributes` rule governs only each file's own line endings, which is the right scope.
- **Nothing else in the tree touches the new files.** No pass walks `*.xml` repository-wide; `FormDocumentCorpusTest` walks `.dfd` and `.dfdx` only, which is why `.xml` was the right extension to choose. The goldens are not ignored by Git, and `.editorconfig` sets only `indent_style = tab` for `[*]`, matching their tab indentation, so no formatter would rewrite them.
- **The one judgement call the handoff put up for argument — one NUnit case for all 416 derivations rather than one per surface — is right, and I am not changing it.** NUnit builds its case list at discovery, before any server exists, so a per-surface case list would have to come from a checked-in list, which defeats the catalog-driven discovery that makes a newly added table turn up as new cases, or from the golden file names, under which a brand-new surface would produce *no case at all* — a hole the one-case shape closes. The cost, one red test naming up to 25 problems instead of N red tests, is the smaller one.
- **The three test cases all pay for themselves; none cut, none added.** `EveryDerivedFormMatchesItsGolden` is the deliverable. `PrintingKeepsALineBreakInsideAnAttribute` is not redundant with it, which is the non-obvious part: an update run rewrites *both* sides of the comparison, so a printer regression would be baked into all 369 files and then compare clean for ever, and this case is the only guard against that. `DerivingTheSameFormTwiceGivesTheSameText` narrows a nondeterminism regression to one red test instead of 369, and its cache clear is load-bearing — without it the second call returns the first call's cached document. I added no test, because every defect I found was in prose, which no test can pin.
