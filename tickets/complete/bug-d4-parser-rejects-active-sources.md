## What landed

The implement commit `ticket(implement): bug-d4-parser-rejects-active-sources` did all of it in one change, with no parser edit: the investigation's finding that none of the thirty-eight unreadable files is a parser defect held up under review, and nothing in `src/engine/DAE/Language.D4/` was touched.

**`tests/DAE.Server.Tests/ParserRoundTripCorpusTest.cs`.** `FormatTemplates` is a new path → argument-list map for the three `.d4` files that are `String.Format` templates rather than scripts — a SQL device's `SystemCatalog` resource, which the device formats before executing. Each is formatted with the argument list its own device's C# call site passes, then parsed, emitted, re-parsed and compared like any other file, so all three are ordinary passing cases rather than exclusions. The twenty `legacy/` entries left the allow list in favour of a rule in `RoundTrips`: a document under the parked trees whose *first* parse produces messages reports `Assert.Ignore` instead of failing. That rule is keyed on the parse result and not on the path, which is what keeps the 58 readable parked documents testing the emitter. `TheParkedTreeIsNoLessReadableThanItWas` is the ratchet that stops those Ignores from rotting: it walks the parked tree, counts the documents the parser cannot read, and fails if the count rises above 19 or if the walk finds no parked file at all. `EveryExcludedFileIsStillWhatItsReasonSays` holds the two hand-written lists against the tree.

`AllowList` is fifteen entries, each naming what the file is and the line the parser stops at, and naming `test-pre-3-1-scripts-policy` on the eight it owns.

**`src/engine/DAE/Schema/SQLDeviceMappings.d4` deleted** (1,657 lines). It was an orphan: a repository-wide search finds no `.csproj` item, no `.d4l` entry and no C# reference, and `src/engine/DAE/DAE.csproj` names its embedded `.d4` resources one by one with no glob and does not name this one. Its content is eight `create device TestDevice { operator … }` blocks in a form the original authors removed from the grammar in 2006. Nothing an application, a deployment script or a C# extension does can notice it going, so there is no `docs/migration-notes.md` entry; git keeps the file if that judgement is ever wrong.

**`docs/modernization-plan.md`** — the `test-parser-roundtrip-corpus` row records the new case count and what became of each of the thirty-eight files, split so they add up without double-counting (3 templates + 19 parked + 1 deleted orphan + 15 named = 38; the Oracle template is both a template and a parked document, which is where the arithmetic is easy to get wrong).

## Review findings

Checked by reading the implement diff first, then re-deriving every factual claim in it from the tree rather than from the handoff: the deletion's two premises, the three templates' argument lists against their C# call sites, all fifteen allow-list reasons against the parser's own reported stop position, the `Assert.Ignore` rule's placement, the ratchet's slack, both new tests' ability to fail, and the two documents the change claims not to need (`coverage-manifest.json`, `SamplesCorpusTest`'s accepted-tradeoff note).

**Found and fixed inline.** Two of the fifteen reasons named the wrong line. `Coverage.Controller.d4`'s entry said "line 15's `select ServerSettings`"; that statement is on line 14 (the parser does stop at 16, as the entry said). `UnsupportedOracleOperators.d4`'s entry blamed line 8's own `EnsureDeviceStarted(…)` for the missing `;`; the parser stops at line 8 column 1, *before* reading that statement, because the `select` on line 6 is the one with no terminator. Both are corrected.

Rather than correct the two numbers and leave the next drift undetected, the class is retired: `AllowList`'s value is now `(int StopLine, string Reason)`, and `EveryExcludedFileIsStillWhatItsReasonSays` grew a fourth arm asserting the parser still gives up at the line each entry records. Mutation-checked by putting the committed value back — with `Coverage.Controller.d4` at 15 the test fails with "entry says line 15, parser stopped at 16" and names the file, so the defect found in this review would not have survived the new assertion. The prose beside each line is still unchecked by anything, which the comment at the list now says outright.

One claim in that comment was overstated. It said the eight `Coverage.Scripts` entries are recorded in `coverage-manifest.json` "with the same error text"; only two of the eight match (`Syntax error near "alter"`, `Syntax error near "select"`). The manifest records the engine's error from *running* the script — `Unknown create directive "domain"`, `LexerException: ";" expected`, `"," or ")" expected`, `"{" is not a valid identifier` — not the parser's own. Reworded to "against the same causes", with the difference stated.

Two smaller things: `docs/modernization-plan.md` said "two assertions hold that list against the tree" and now names three; and the reasons test's summary counted its arms as first/second/third when there are four, so it now names each arm by what it catches. Two comment-wrapping artifacts from the implement edit (an orphaned "2006" on its own line, a short line mid-paragraph) were rewrapped.

**Checked and found sound, no change.** The deletion's two premises both re-confirmed from the tree, as above, plus the deleted content read to confirm it is an operator-map script belonging to no library; omitting the migration note is right. The three templates' argument lists match their call sites exactly, including that the real call sites pass lower-case strings (`IsMSSQL70.ToString().ToLower()`) and that Oracle's passes two where the other two pass four. The other thirteen reasons are accurate in every quoted line and token, measured against the parser's reported position; `Administration.d4` and `Coverage.AdministrationRole.d4` are byte-identical, as the entry claims. The `USEISTRING` explanation is real: `#if USEISTRING` guards the `"…"i` suffix in `Parser.cs` and no project defines it. The ratchet sits exactly at its bound with no slack — 19 Ignored cases, 19 counted, bound 19 — and fails at 18 naming all nineteen paths. The `Assert.Ignore` rule is after the first parse, so the 58 readable parked documents still round-trip. `SamplesCorpusTest`'s accepted-tradeoff note rests partly on every `.d4` in the tree being parsed by this corpus; `Sample.Forum` and `Sample.Pubs` each have one `.d4`, neither is in either list nor under `legacy/`, so that premise holds and the note needed no edit. The eight `coverage-manifest.json` entries are present, `known-failure`, and owned by `test-pre-3-1-scripts-policy`; left alone, as that ticket owns them.

**Tests: none cut, none added.** Both tests the implement ticket added pay for themselves — each asserts something no type, compiler check or lint rule can (that a hand-written list still describes the tree), and each was confirmed to fail under mutation rather than assumed to. The strengthening above is a fourth arm on an existing test, not a new test, and it is itself the reproduction of the two wrong line numbers, so those needed no separate test.

**Major findings: none.** Nothing reached the filing bar. The two defects found are prose errors in a comment with a one-line fix each, and the invariant that prevents their recurrence was cheap enough to land in this pass rather than file.

**Tripwires: one carried, none added.** The implement ticket's `NOTE:` at the `Assert.Ignore` site stands — the ratchet bounds *how many* parked documents may be unreadable, not *which*, so a regression that breaks one parked document while a different one starts parsing keeps the count at 19 and passes. One concern was weighed and deliberately not recorded: a `legacy/` path added to `AllowList` would be dropped from the cases *and* counted by the ratchet, pushing it past its bound. That is the ratchet measuring the tree correctly, and the resulting failure names the offending file, so it diagnoses itself rather than trapping anyone.

**Conditional/speculative: none beyond the above.**

## Known gaps carried forward

The seven supported-tree documents are not repaired, by design: whether a D4 document's statements may be edited to make it run is an open owner decision, carried as the second arm of `test-pre-3-1-scripts-policy`. `samples/Sample.Common/Documents/D4LanguageTour.d4` is the one with user-visible weight — a reader who executes the whole guided tour rather than one statement at a time gets a syntax error at line 133. `coverage-manifest.json` is untouched; its eight `Coverage.Scripts` entries already point at that ticket and changing them is its job.
