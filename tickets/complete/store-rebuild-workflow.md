## What landed

New NUnit fixture `tests/DAE.Server.Tests/StoreRebuildWorkflowTest.cs` with one `[Test]`, `RebuildRegistersLibrariesAndSurvivesRestart`. It owns its own `TestServerInstance` (not a subclass of `InProcessTestFixture`) because it starts, stops and restarts the server inside the test body. Wired into `DAE.Server.Tests.csproj`. WS4's "No migration" paragraph in `docs/modernization-plan.md` gains a **Done** annotation pointing at this test as the live proof and naming the sample set, measured timing and out-of-scope arms.

- **Sample set** (`SampleSetLibraries`, in registration order): `System.Platform`, `SimpleDevice`, `Frontend`, `Sample.Common`, `Sample.DetailAdd`. `General` is auto-registered by `Server.EnsureGeneralLibraryLoaded` on start.
- **Rebuild script**, one process-per-call through `TestServerInstance.ExecuteScript`, wrapped in a single `Stopwatch`:
  1. Register each library through `EnsureLibraryRegistered`; each library's `Documents/Register.d4` runs as a side effect (Frontend creates `User` and `Developer` roles, Sample.Common creates `SampleDevice` on `SimpleDevice`, Sample.DetailAdd creates `Master`, `Category`, `Detail`).
  2. Security: two roles (`RebuildReader`, `RebuildWriter`), one right each (`System.CreateUser`, `System.CreateRole`), one user (`RebuildUser`) in `RebuildReader`, one device user on `SampleDevice`.
  3. DDL: `create table RebuildWidget` then `create view RebuildWidgetView RebuildWidget over { ID };` — the view references the table.
- **Clean-stop sidecar assertion.** After `Server.Stop()`, the catalog directory must hold exactly `{ DAECatalog }`. A stray WAL or journal would mean a reopen could silently reconcile from stale state.
- **Restart assertions.** Every rebuilt object is checked via `exists (…)` / `Count(…)` on the catalog-device views (`LoadedLibraries`, `Users`, `Roles`, `UserRoles`, `RoleRightAssignments`, `DeviceUsers`, `Devices`, `BaseTableVars`, `DerivedTableVars`). Each query is namespace-tolerant (`Name = '<bare>' or Name like '%.<bare>'`) because roles, devices and tables created by Register.d4 land under their library's namespace while objects created in General come back bare.
- **Password round-trip.** Reads `DAEUsers.Data` for `RebuildUser` and `DAEDeviceUsers.Data` for the same user through `TestServerInstance.OpenCatalogStoreFile` (read-only, no pooling); both must be non-null and non-empty. Asserts the stored form round-trips, not that it is secure — `security-password-storage-design` owns what goes into that column.
- **Timing.** Stopwatch brackets register + security + DDL; result prints via `TestContext.WriteLine` as `StoreRebuildWorkflow timing: register+security+DDL = <ms>` and is **not asserted on**. Measured 893 ms on this review run and 1.4 s on the development machine. Consumers (`docs-admin-guide`, `tool-cli-catalog-commands`, `security-password-storage-design`) can grep CI output for the "StoreRebuildWorkflow timing:" prefix.

## Review findings

Reviewed the full diff of `` `ticket(implement): store-rebuild-workflow` `` with fresh eyes before the handoff summary, then re-read the test alongside `TestServerInstance`, `Server`, and the SQLite store catalog schema. Ran the test (one passed, 893 ms timing printed) and verified the sample libraries' `Register.d4` matches what the test asserts afterwards.

- **Design / SPP / DRY / modularity.** Single-method fixture with two private helpers (`CatalogFile`, `ReadScalar`); no overlap with `CatalogStoreTest` (which covers store internals, not the registration-through-restart flow) or `InProcessTestFixture` (persistent server; this test owns start/stop lifecycle). Namespace-tolerant assertions (`Name = X or Name like '%.X'`) are the right choice here — reading the exact library-qualified name first and then asserting would be more precise but would couple the test to which library each object happens to live in today, which is not what this test is about.
- **Resource cleanup and error handling.** `TestServerInstance` is in a `using`. Its `Dispose` stops the server if non-stopped and reports any stop failure through `TestContext.Progress` while letting the test's own exception propagate. `ReadScalar` disposes both `SQLiteConnection` and `SQLiteCommand`; `OpenCatalogStoreFile` opens read-only without pooling so the file handle releases before the instance directory is deleted. No leaks observed.
- **Type safety and warnings.** Clean build locally; no new warnings tied to this file. The file uses the project's preferred `string` D4 literal concatenation (`+` across lines) for the one multi-statement script.
- **Comments / source hygiene.** One confusing stale comment at the base-table / derived-table assertion block referenced `Catalog.Contains`, a method the test does not use (it was in an earlier draft per the implementer's own "Review targets" note). Fixed in place — the comment now says the bare-vs-namespaced accept is because Register.d4-created objects land under their library's namespace while the two created in General come back bare, which is what the surrounding assertions actually encode. Other comments (phase markers, WAL rationale, password round-trip disclaimer) say *why* and stay. Tabs / CRLF / BOM preserved; file size reasonable (143 lines).
- **Scope of the DDL.** The ticket's step 3 reads "Run one small DDL from each library"; the implementation runs two explicit DDL statements in the default library and relies on each library's `Register.d4` to exercise its own slot. Not weaker in practice: Register.d4 side effects are the DDL for each library (and the restart assertions actually verify what those scripts produced — `SampleDevice`, `Master`/`Category`/`Detail`, `User`/`Developer`). Accepted as implemented; a per-library `defaultLibraryName` session-per-statement form would add surface area that isn't WS4's concern.
- **Tests that pay for themselves.** One test, one behavior — the rebuild-and-restart contract for WS4. This project rule (characterization tests for ported subsystems) covers it. No add, no cut.
- **Stated gaps — judged, not re-filed.**
  - *`General` not in `SampleSetLibraries`.* It is auto-registered by `Server.EnsureGeneralLibraryLoaded`; listing it would be redundant and would mask a regression where auto-registration stops working (the restart assertions on `User`/`Developer` and other General-namespace objects implicitly check it is loaded). Accept.
  - *No second restart.* Adding a second stop/start would catch a one-shot replay bug that a single restart misses. `CatalogStoreTest.SQLiteCatalogRegressionTest` already covers "the shape of two starts" for the store layer; this test's job is the workflow. Accept.
  - *WAL sidecar on other machines.* The clean-stop sidecar assertion would catch a stray WAL or journal as a real defect — which is exactly what it is for. The behaviour on this machine (none left after stop) matches WAL checkpoint-on-close. If another machine fails here, it is a defect to file against the SQLite store, not a test bug.
  - *Password round-trip tightness.* `Is.Not.Null.And.Not.Empty` on both password columns is the right assertion for this ticket's claim ("the stored form round-trips"). A before/after-restart equality check would overlap `security-password-storage-design`'s territory and is explicitly out of scope here. Accept.
- **Tripwire — `Catalog.Contains` on a store-backed catalog after restart.** The implementer's draft used `instance.Server.Catalog.Contains("RebuildWidget")` and it failed after restart; switching to `exists (BaseTableVars where …)` forced the schema row to resolve from the store and succeeded. This is almost certainly intentional lazy population (`Server.Catalog` is the in-memory `Schema.Catalog`, filled on demand from the store), and it is fine *now* because every caller that cares about post-restart presence already goes through the catalog-device views. If a future caller treats `Server.Catalog.Contains(name)` as "is this persisted?", it will be wrong. Recorded here as a tripwire (not a ticket): the condition that trips it is a new caller using `Catalog.Contains` as a persistence check; the fix then is to document the lazy-load contract or add an eager form. No file edit for this one — it is a consumer-side concern with no single call site today to carry a `NOTE:`.
- **Minor stylistic choices reviewed and accepted.** `Path.GetDirectoryName` return type is nullable in principle but cannot be null for the path built in `CatalogFile` (an absolute path with two more segments); no guard. `Convert.ToString` with `InvariantCulture` on the password column is appropriate (`Data nvarchar(200)` per the store's schema). `String.Format` with positional placeholders matches the project's other test files; `$"…"` would be fine but adds no value.
- **Docs / migration surface.** `docs/modernization-plan.md` gains a one-paragraph Done annotation in the "No migration" section pointing at the test and naming the sample set, measured timing and out-of-scope arms. Public API surface unchanged; no `docs/migration-notes.md` entry required.
- **Pre-existing failures.** None caused by this change. The three full-suite parts from `AGENTS.md` are not re-run here (comment-only inline fix does not change behaviour); the implementer already recorded that `ServerLink`'s known one-off (`tickets/.pre-existing-known.md` entry 3) is present on this machine.
