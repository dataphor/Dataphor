# Isolated in-process server fixture for DAE.Server.Tests

Second of three tickets that make up `test-harness-inprocess` (after `test-common-tests-sdk`, before `test-harness-inprocess`, which keeps the slug and adds the coverage-script runner and manifest). That ticket builds on `TestEnvironment` and `TestServerInstance` from here, so their shape matters more than the four tests they run today.

- **`TestEnvironment`** (new, static):
  - `LayoutDirectory`/`LibrariesDirectory` come from the assembly metadata. If the metadata or `<layout>\Libraries` is missing, it throws `InvalidOperationException` naming the path and `dotnet build Dataphor.slnx`. The failure is cached in a `Lazy<T>`, so every test fails with the same message.

- **`TestServerInstance`** (new, `IDisposable`):

  - Members: `Server` (the concrete `Server`), `Directory`, `Connect()` (Admin with an empty password), `ExecuteScript(d4)` (its own session and process, cleaned up in `finally`).
  - `Dispose` is idempotent. It stops a running server; a stop error is written to `TestContext.Progress` and rethrown only when no exception is already unwinding. It then deletes the directory unless `KeepFiles`; a failed delete is written to `Progress` and left for the next run's sweep.
  - It carries the parallel-execution `NOTE:` (K1 and other statics).
- **`InProcessTestFixture`** (rewritten on `TestServerInstance`):
  - `protected virtual string[] Libraries => []` and `LibrariesToRegister => []`. The instance is named after the fixture class.
  - `OneTimeTearDown` copes with a null instance.
  - `Server` (still `IServer`), `Session`, `Process` and both `ExecuteScript` overloads keep their meaning. `Instance` is new.
  - The protected `Configuration` and `ServerConfigurationManager` properties are gone; their types were deleted.
  - `CursorTest.cs` is unchanged.

## Decisions taken in implement that the ticket did not spell out (check them)

- **The stale-folder sweep is skipped when `DATAPHOR_TEST_LOGGING=1`.** Otherwise a second diagnostic run would delete the folders the first one kept. The next run without the variable deletes them; AGENTS.md says so.
- **A `ProcessExit` handler deletes this run's own folder if it is empty** (non-recursive delete, errors ignored). Without it every run would leave an empty `<pid>-<hex>` folder for the next sweep. Folders with leftovers, such as a mapped library assembly, are still left for the sweep. The empty `%TEMP%\Dataphor.Tests` root stays.
- **"No other exception in flight" is detected with `Marshal.GetExceptionPointers() != IntPtr.Zero`.** C# has no language-level way to know this inside `Dispose`. I checked it on .NET 10 in a scratch console program: it returns 0 normally and in a `using` block's `finally` after a normal exit, and non-zero in the `finally` while an exception propagates and in the `catch`. It is an obscure API; the alternative was never rethrowing, which hides stop failures. Not exercised by any test here.
- `InProcessTestFixture.TearDown` now disconnects in a `finally`, so a failing `StopProcess` does not also leak the session. The legacy code skipped the disconnect.
- The new files carry the license line of the folder's header but no `© Copyright … Alphora` line.
- The planning `NOTE: accepted tradeoff` for a reused process id (the folder stays until a later run) is recorded at `DeleteStaleRunDirectories`.
