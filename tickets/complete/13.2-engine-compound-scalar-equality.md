## What changed

A scalar type with one multi-property representation and no equality operator of its own gets a generated `iEqual` implemented by `System.CompoundScalarEqualNode`. Its `DetermineDataType` (`src/engine/DAE/Runtime.Instructions/RowComparisonNodes.cs`, the `USENAMEDROWVARIABLES` branch) pushed the right operand's row under an empty name, while the row-equality expression it compiles refers to `right.<property>`, so compilation failed with `Unknown identifier "right.Degrees"`. It now pushes `Keywords.Right`, matching the left side, the class's own `InternalBindingTraversal` and the sibling `RowEqualNode`. One line changed.

This never worked on 3.1 (tag `v3.1` has the same line); the fix only makes previously rejected code compile, so no migration note.

## Tests

- `Types.Coordinate` (existing coverage script) is the reproduction; its manifest entry flipped from `known-failure` to `pass`.
- Added in review: `Types.CompoundEquality`, a small coverage script that checks equal compound values compare true and values differing in either property compare false (and `<>` true). `Types.Coordinate` only ever compares equal values, so an equality that always returned true would have passed it.
