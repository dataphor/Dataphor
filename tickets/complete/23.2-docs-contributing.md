## Review findings

The implement-stage commit is `ticket(implement): docs-contributing`. Its own handoff flagged the compiler-define page's *State* and *Where* columns as the part worth a second reader, and that is where the findings are: the page claims to be measured from the tree, so all 51 of its rows were re-measured against the tree independently. Five disagreements came out of it. The error-code page was measured the same way and holds up completely.

**Fixed in this pass (minor).**

- **`USEELABORABLE` was marked "not in the tree"; the switch exists, is on, and is in 13 files.** The source spells it `UseElaborable`, and the C# preprocessor is case-sensitive, so a search for the inherited index's capitalisation finds nothing. There is an active `#define UseElaborable` in 13 files of `src/engine/DAE/Runtime.Instructions`, each nested inside `#if UseReferenceDerivation`, making reference inference conditional on the plan's cursor carrying the `Elaborable` capability — which is what the inherited description said it did. The row now carries the source's spelling, the measured state and that description. Three arithmetic statements that depended on it were corrected too: the page's own summary of how the inherited file compared with the tree (26 active rather than 25, one name absent rather than two, "those seven" rather than "those eight") and the plan's Done row.
- **Four per-file `#define`s in the tree had no row at all.** The page introduces itself as the index to the per-file switches, so a reader is entitled to read it as complete, and it was not: `PROCESSSTREAMSOWNED` (on), `USESTRUCTTAG` (on), `USEINCLUSIVEMULTIPLEX` (off) and `STORETIMING` (off) are all per-file switches the inherited file never listed. They are now a short second table, kept out of the first so that its stated "the order is the inherited file's" remains true. A fifth `#define` in the tree, `DEBUG` at the top of `src/engine/Base/IndexList.cs`, is noted in prose instead: it is not a behaviour switch, but it does compile that one file's assertions into Release.
- **`USETYPEDLIST` said "four other files"; there are three.** 31 files test it: 24 in `src/engine/DAE`, 2 in `src/client/DAE.Client`, 2 in `libraries/Frontend`, and one each in `libraries/SQLDevice`, `src/engine/Server` and `src/protocol/Client`.
- **Three rows cited `src/client/DAE.Client/View-263.cs` without saying that nothing compiles it.** `DAE.Client.csproj` lists its sources explicitly and does not list that file; `AGENTS.md` already names it as a stray. It is the *only* site for `DATAVIEWBOOKMARKS`, so the page's legend — "the name is still tested in the code" — was misleading for that row; `RELYONCURSORFLAGSAFTERUPDATE` and `USEASYNCSTOPPROCESS` each have a second, compiled site as well. All three rows now say which site is which.
- **`SQLSTORETIMING`'s *Where* undercounted its test sites,** and the reason is worth knowing: the switch has a commented-out define line in `SQLStoreConnection.cs` and `SQLStoreCursor.cs`, but it is *tested* in a third file, `SQLStore.cs`, which has no line of its own.
- **The page had no measurement date.** It now carries one, with the method, the case-sensitivity trap that produced the `UseElaborable` error, and the two pending work items that will move rows (`build-globbing-cleanup` deletes the uncompiled files; the port deletes dead switches in files it is otherwise editing).
- **`AGENTS.md`'s `docs/` layout row and the root `README.md` did not mention the new folder.** The layout row was edited in the implement commit and still omitted `contributing/`; and the one section in the repository actually headed *Contributing* pointed only at `tickets/` and `AGENTS.md`, while the new guide pointed back at the root README. Both now name it.

**Parked as a tripwire, not filed.**

- `src/engine/DAE/Store/SQLStore.cs` carries `//#define STORETIMING` — a name no `#if` anywhere tests. The two timing blocks in that file read `SQLSTORETIMING`, so a developer who uncomments the two real lines to diagnose a store timing problem gets timings from the connection and the cursor but not from the store, with nothing to say why. It is dormant (the switch is off in every file) and diagnostic-only, so it is below the filing bar: a `NOTE:` at the line records it, and the page's `STORETIMING` row catalogues it. Renaming the commented line would fix it in one word, but that is a judgement about the original author's intent and does not belong in a documentation review.

**Checked and found correct — each of these was measured, not assumed.**

- **The error-code table is complete and every type name is right.** A scan of `src`, `libraries` and `tests` for six-digit enumerators found error codes under 29 prefixes, and all 29 are in the table; no prefix in the tree is missing from it. Two six-digit values that are not error codes were excluded by hand: `ShouldReinferReferences = 131072` in `src/engine/DAE/Schema/TableVar.cs` (a bit flag; prefix 131 is correctly absent) and two `120000` timeouts in the test project (prefix 120 is correctly recorded as never allocated). Every one of the 29 exception types was resolved to its declaring file and its namespace compared with the table: all 29 match exactly, with the shared `Alphora.Dataphor.` prefix omitted as the page says. The eight prefixes the page says have no class in the tree really have none — 108, 116 and 118 name sources with no class of their own, 129's `COMClientException` is gone, and 204 to 207 belong to the removed browser clients.
- **Every "on" and "off" in the 51 inherited rows matches the tree,** and so does every file count in *Where*: `NILPROPOGATION`'s 22 engine files, `UseReferenceDerivation`'s 19, `USENAMEDROWVARIABLES`'s 10, `LOADFROMLIBRARIES`'s 2-plus-3 split across the two engine assemblies, the four MSSQL device files, the nine client protocol files behind `USESPINLOCK` and `LOGFILECACHEEVENTS`, and the `src/engine/Store.SQLite` and `src/engine/Store.MSSQL` split behind `USESQLCONNECTION`. `SKIPBETACHECK` and `UseReaderWriterLock` are genuinely absent from the tree, case-insensitively and across every file type. `CHECKCLASSDEPENDENCY` really does guard a `[Conditional]` method rather than an `#if`.
- **`RELYONCURSORFLAGSAFTERUPDATE`'s description reverses the inherited wording, and the new reading is the right one.** The inherited file said the define "forces the server cursor to recognize the BOF and EOF flags by actually navigating"; `src/client/DAE.Client/DataSet.cs` shows the opposite — the navigation is in the `#if !RELYONCURSORFLAGSAFTERUPDATE` branch — and a comment beside it says defining the switch makes the dataset assume the flags are already correct. The new page says that.
- **Every factual claim in the three contributing pages was checked against the thing it describes.** `global.json` pins 10.0.100 with `rollForward: latestFeature`; `Directory.Build.props` really does produce `artifacts/bin/<project file name>/<debug|release>/` and `artifacts/obj/`; `DataphorLayoutDir` is a real MSBuild property; the five part commands are in `AGENTS.md`; the `--filter Name=Lexer` example works, because `Lexer.d4` is a coverage script and its NUnit case is named `Lexer`; the claim that all three `DATAPHOR_TEST_*` variables are read in one place is true — the three `Environment.GetEnvironmentVariable` calls are all in `tests/DAE.Server.Tests/TestEnvironment.cs` and every other mention is a comment; `build.yml` runs on `windows-latest` and ignores `tickets/**` and `docs/**`; `docs.yml` runs both checks on `docs/` and on either checker; the word limit is 1,500 and the checker's scope is `docs/architecture.md` plus `docs/architecture/**`, so `docs/contributing/` is correctly outside it; the 1,500-word rule really is stated in three documents plus the checker; and the benchmark's own README gives the measured 100 seconds and the Release requirement.
- **All 94 Markdown files under `docs/` are UTF-8 with no byte-order mark,** as `writing-docs.md` claims, and the five new and edited pages are `i/lf w/crlf` in git like their siblings. The files this review edited keep their own CRLF and no-BOM state, and `SQLStore.cs` keeps its tabs, CRLF and absence of a byte-order mark.
- **Nothing dangles on either deleted file.** Outside `.git`, `artifacts/`, `tickets/.logs/` and the AsciiDoc sources that `docs-remove-old-sources` deletes, the only mentions left are `Dataphor.sln` lines 8 and 9 and the deliberate historical ones in the plan and in `compiler-defines.md`'s own prose. The two solution-item paths are in the .NET Framework solution, which no longer builds and which `build-remove-legacy-build` deletes; leaving them was the implementer's call and it stands.
- **The privacy generalization is correct and complete for this change.** Two inherited comments named a former customer; the new page describes them generically instead, and the name is in none of the new or edited files. The six tracked files that still carry it are listed in the `hygiene-scrub-inherited-identifiers` arm of `debt-ws12-hygiene-remainder`, which names no customer.

**Nothing filed, and nothing left open.** No finding reached the filing bar: all five documentation errors were one-line corrections made here, and the one source-level concern is dormant, diagnostic-only and recorded at its line.
