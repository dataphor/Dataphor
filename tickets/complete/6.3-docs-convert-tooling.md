## What was built

`tools/docs-convert/` converts `Documentation/` (75 AsciiDoc files) into Markdown laid out as `docs/`: Asciidoctor.js (DocBook 5 backend) → pandoc 3.14's DocBook reader → a Python pass over pandoc's JSON syntax tree (`convert.py`) → pandoc's `gfm` writer. `tools/docs-convert/README.md` documents prerequisites, commands, every transform, the report and the tables. Nothing under `Documentation/`, `legacy/Documentation/`, `book.json` or `docs/` was touched; the only edit outside `tools/docs-convert/` is the `AGENTS.md` `tools/` row.

- `package.json` + `package-lock.json` pin `@asciidoctor/cli` 4.0.0, `@asciidoctor/core` 3.0.4, `@asciidoctor/docbook-converter` 3.0.0. `requirements.txt` pins Pillow 13.0.0. pandoc 3.14 comes from its release zip or winget (`--pandoc PATH`).
- `convert.py` (about 1,400 lines, standard library plus Pillow; imports `heading_slugs` and `extract_links` from the link checker). Two entry points: the AsciiDoc route (`convert.py --out DIR`) and the standalone DocBook stage (`convert.py docbook FILE.xml … --out DIR`, with the resolution rules as options).
- Tables: `pages.tsv` (75 rows), `xref-fixes.tsv` (9 rows settling 10 links), `code-blocks.tsv` (761 rows, seeded, all unreviewed), `legacy-links.tsv` (204 rows, generated), `index-extra.md` (the `## Project documents` section).
- `test_convert.py` (added in review): link-resolution tests that need neither Node nor pandoc; `python -m unittest discover -s tools/docs-convert`.

## Measured results (full scratch run, rerun in review)

- About 6.5 s end to end. 73 pages from 74 converted sources (`README.adoc` + `SUMMARY.adoc` → `README.md`; `AuthoringDocumentation.adoc` not converted). One `#` heading per page; 15 empty preface headings dropped.
- Links: 660 resolved to pages, 10 external, 204 legacy (all with a target), **10 unresolved**. Link checker over the scratch folder with `--pending tools/docs-convert/legacy-links.tsv`: 73 files, 989 links, 203 pending, 13 errors = the 10 unresolved + the 3 `index-extra.md` links to `architecture.md`, `modernization-plan.md`, `migration-notes.md` (they exist only in `docs/`).
- Images: 97 converted (51 BMP, 4 GIF → PNG; 33 PNG, 9 SVG copied), 27.4 MB of sources → 1.07 MB; 10 unreferenced, not converted.
- Code blocks: 761 (seed tags bnf 150, d4 468, text 138, xml 5, sql 0 — the SQL in the comparison chapters is lower case, so it seeds as `d4`).
- HTML tables: 6 on 5 pages; other raw HTML only `<sup>` ×13 in `d4-language-elements.md`. Footnotes 33, GitHub alerts 10.
- Byte-identical output and report across runs.

The 10 unresolved, each needing a decision in `docs-convert-asciidoc`: `SUMMARY.adoc` → `AuthoringDocumentation.adoc` (not converted); `#Select_Statement` ×5 (headings of that name in both `D4DataManipulation` and `D4ComparisonWithSQL`); `D4Catalog` `#Libraries` (two candidate pages); `D4LanguageElements` `../DataphorReference.adoc#Scalar_Types` (probably the legacy reference); `D4LexicalElements` `D4TableOperators.adoc#Row_Extractor` ×2 (no such heading anywhere).

**Counts that differ from the survey:** 204 legacy links (not 206) and 203 pending (not 205), because two `.html` occurrences sit in broken markup in the `D4LanguageElements.adoc` operator-precedence table; 97 images converted and 10 unreferenced (not 98 and 9), because the `image::` line at `UsersGuide/Aliases.adoc` line 45 follows a paragraph directly and AsciiDoc reads it as text.

## Choices beyond the planning ticket (accepted in review)

`-a outfilesuffix=.adoc` not passed (no effect with the DocBook converter; `.xml` and `.adoc` links are read alike); `-a reproducible`; `contentwidth`/`contentdepth` renamed to `width`/`depth` before pandoc so sized icons keep their size; `[horizontal]` lists (18) turned back into definition lists; definition-list terms bold; sidebars as block quotes; table titles as a bold paragraph before the table; single-paragraph lists written tight; zero-width spaces removed; index terms dropped; nothing written when the run has errors (exit 1) and setup problems exit 2; unresolved links written in the source's `File.adoc#Fragment` form; a named `--work` folder never deleted; extra report sections (candidates for each unresolved reference, admonitions nested in lists, macros left as text, arrows, case-insensitive matches). Each is documented in the README and reads as the right call for a format conversion.

## Source defects seen in the output (for docs-convert-asciidoc; `Documentation/` is not edited)

- `D4LanguageElements.adoc` operator-precedence table: an unescaped `||` cell shifts later cells and **drops the `iCompare` row**; `<=` shown as ⇐; following prose run together; a nested `link:` in the `in` row. Since the sources are never edited, a repair would be a hand edit in `docs/` after landing or a decision to leave it.
- `D4LanguageElements.adoc` scalar-type list: `link:…[System.Guid]::System.Guid …` with no space after `::` is not a list item, so several types run together; `2 ** 3 ** 2` became `2 **3** 2`; an index term `(((and)))` left "and" in the text.
- `Aliases.adoc` line 45 image macro read as text.
- `ErrorMessagePrefixCodes.adoc` line 17: "unterminated table block" (the only Asciidoctor warning).
- `Tutorial_SampleComponents.adoc`: a level-0 `= Tree/Explode` section (shown as `##`, reported); a literal `+` in its Technical Terms table.
- `D4Catalog.adoc`: a link label with literal backslashes (`\<order clause\`).
- `#Security`, `#References`, `#Metadata` into `d4-catalog.md` match two headings each and go to the first (the "Objects" subsections) per the first-heading rule; the main sections are probably what was meant (report: ambiguous, 23 links).

## Review findings

Read the `ticket(implement): docs-convert-tooling` diff in full (`convert.py`, README, tables, `AGENTS.md`) before the handoff, then reran the tool with the same pinned pandoc 3.14, Node 24, Pillow 13.0.0.

**Checked and confirmed by running:**
- Full run: every number in the handoff reproduced (pages, links, images, sizes, code-block counts, HTML tables, alerts, footnotes, character counts, 10 unresolved with candidates). `git status` showed no change to `code-blocks.tsv` or `legacy-links.tsv` after the run.
- Determinism: three runs (one before my edits, two after) gave byte-identical output folders (`diff -r`) and identical reports apart from the elapsed time — so the review's edits did not change the output.
- Error path: without `--allow-unresolved` the run exits 1 with "10 unresolved reference(s)" and the output folder is not created.
- Link checker over the output: 73 files, 989 links, 203 pending, 13 errors, all accounted for as above. Link checker's own tests pass.
- Standalone DocBook stage on `D4Catalog.xml`, `D4LanguageElements.xml`, `D4TableOperators.xml` from a kept work folder with `--match-heading-text --global-ids`: 3 pages, links among them resolved, links to other files reported unresolved.
- Spot check of the assembled `README.md`: introduction as bold-term definition list, nested contents list matching `SUMMARY.adoc`, `### User's Guide`-style group headings, Project documents section.
- Write paths: pages only at `pages.tsv` outputs, images only at `images/<rule name>`; no delete anywhere; nothing written on error. Page lookups are exact-case dictionary lookups; image lookups compare each path component against `os.listdir` (exact case, never a case-insensitive file-system probe).
- Encoding: `convert.py` is ASCII-only; tables and README are UTF-8 without a byte-order mark, LF.

**Found and fixed in this pass (minor):**
- `legacy_rows` looked for a legacy link in the rendered page under its bare file name, while the link as written kept its folder (and any fragment) when no rule matched; such a link stopped the run with "cannot find the rendered link" (exit 2) instead of being listed. Latent (no such link in this corpus). Fixed by recording the destination as written; reproduction test `LegacyLinkTest` in `test_convert.py` (fails on the implement commit, passes now).
- A legacy link's `#fragment` was dropped silently when the rule rewrote it; it is now listed in the report's legacy section (none in this corpus).
- The "empty headings dropped" total omitted the `SUMMARY.adoc` page, which is merged into `README.md` before the count; now carried over (no change to today's 15).
- Standalone stage: pages a `--pages` map marks as not converted were still run through pandoc and the tree pass, adding report lines with `None` as the page; now filtered out first.
- Added `FragmentTest` pinning the fragment rules the specification names (id, then heading text with `_` as space, then case-insensitive; a fragment naming the title links to the page; exact-case file names). This is the logic with real branching that every one of the 660 links depends on, and the implementer named it as the first thing worth a test. README now gives the test command.

**Tripwires parked:**
- `code-blocks.tsv` rows are keyed by page and position, so a block added or removed earlier in a page re-seeds every later row and clears its review; fine while `Documentation/` is frozen (`docs-convert-asciidoc` never edits it). `NOTE:` at `tag_code_blocks` in `convert.py`.
- The footnote line-ordering caveat in `legacy_rows` (implementer's `NOTE:`) stays as written.

**Docs:**
- `tickets/implement/6.6-docs-convert-asciidoc.md` still expected 205 pending links and 9 unreferenced images; corrected to 203 and 10, with the reasons. `tickets/backlog/feat-ws8-documentation-remainder.md` said `legacy-links.tsv` lists 206 links; corrected to 204 with the reason. `docs/modernization-plan.md` keeps "206" because it counts `.html` occurrences in the sources, which is still true; `docs-convert-asciidoc` already owns the K17 note update.
- `AGENTS.md` `tools/` row names `docs-convert/` correctly; README matches the code after the fixes (options, exit codes, write paths, tables, report sections).
- No `docs/migration-notes.md` entry: tooling only, nothing an application or extension can notice.

**Considered and left as is:**
- File size (about 1,400 lines in one script): it is a run-by-hand tool with one reader; splitting into modules adds import plumbing for no reader benefit, and the sections are clearly delimited.
- `convert_asciidoc` and `convert_docbook` repeat the settings and report wrapper (about 15 lines); the two routes set different fields, and folding them adds indirection without removing a class of error.
- An image named the same as another after the page-name rule stops the run with exit 2 rather than exit 1; that is reported clearly, and the survey found no such collision.
- No new tickets: nothing found reached the filing bar; the source defects belong to `docs-convert-asciidoc`'s review list, which reads this ticket.
