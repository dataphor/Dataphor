## What landed

`samples/Sample.Shipping/Source/Shipping.csproj` is an SDK-style project, so the build compiles `Alphora.Shipping.dll` and the layout assembles the sample library again. The implementation is `ticket(implement): library-sample-shipping-convert`; the review added three documentation corrections on top of it.

- **The project file**, written the way AGENTS.md *Converting another project* describes: `AssemblyName` `Alphora.Shipping`, `RootNamespace` `Shipping`, `OutputType` `Library`, `AllowUnsafeBlocks` kept (`Coordinate.cs`'s conveyor reads and writes the row buffer through `fixed` pointers), `DefineConstants` set outright - `TRACE` in both configurations plus `DEBUG;TRACE` in Debug, which is the legacy Release set minus `SIGNASSEMBLIES` - explicit `Compile` items for the four source files in legacy order, and the five project references the legacy file had (Base, DAE, Server, `DAE.Connection`, `DAE.Device.SQL`). No `.resx` and no package references. No line of `Coordinate.cs`, `Domains.cs` or `Register.cs` changed.
- **`Properties/AssemblyInfo.cs`** trimmed to `AssemblyTitle`, `AssemblyDescription` and `DAERegister`; version, company, product, copyright and signing come from `Directory.Build.props`.
- **Wiring**: a `/samples/` folder in `Dataphor.slnx`; the project in `tools/layout/Layout.csproj`'s Library list with the `DataphorD4Library Remove` line for `Sample.Shipping.d4l` deleted; `Alphora.Shipping` on the `reported` list in `tools/coverage-report/areas.json`.
- **The two test lists the conversion falsified**: the `Sample.Shipping` entry in `SamplesCorpusTest` moved from `NotInTheRuntimeLayout` to `NeedsADatabaseServer`, leaving `NotInTheRuntimeLayout` an empty dictionary with a `<remarks>` saying why it is kept; `FormCustomizationTest.LibrariesNotCarried`'s reason for the sample is now "requires a SQL Server device", matching its `Sample.Forum` neighbour.
- **Docs**: AGENTS.md (the converted list, the sample-corpus paragraph and the runtime-layout paragraph) and `docs/modernization-plan.md` (the WS7 work-item row, the WS3 `test-samples-corpus` row and the `build-runtime-layout` exclusion sentence). The review added `docs/migration-notes.md`, `tools/coverage-report/README.md` and one clause of AGENTS.md - see the findings below.

## Review findings

**How this was reviewed.** The implement diff was read before the handoff summary. The project file was then checked bullet by bullet against AGENTS.md *Converting another project* and line by line against the legacy project file and the legacy `AssemblyInfo.cs`; the build was run in both configurations; the layout output was inspected in both; the tests below were run; and the tree was swept for text that the conversion makes stale.

**What was checked and held.**

- **The project file against the checklist.** Explicit `Compile` items are correct rather than duplicated because `Directory.Build.props` sets `EnableDefaultItems=false`. Constants match the rule ("the legacy Release set minus `SIGNASSEMBLIES`, the same in both configurations, plus `DEBUG;TRACE` in Debug"). No `OutputPath`, no `NoWarn`, no package reference. The project file name `Shipping.csproj` is used nowhere else, so its new `artifacts/bin/Shipping/` output folder collides with nothing. The spike step ("remove any `PATCHES` entry for the project's files") was vacuous: `PATCHES` is empty and `Shipping.csproj` was never in `tools/net-spike/projects.txt`.
- **Signing and version.** The legacy project signed with the same repository-root `Dataphor.snk`, but only in Release, through an `#if SIGNASSEMBLIES` block in the old `AssemblyInfo.cs`. The assembly now signs in both configurations at `4.0.0.0`, exactly as every other converted project does - which is what makes the missing migration note below a wording problem rather than a missing disclosure.
- **Build.** `dotnet build Dataphor.slnx` in Debug and in Release: 0 errors, 144 warnings each, the count unchanged. The sample contributes no warning of its own (checked by filtering the build log on `Shipping.csproj`), despite the `unsafe` conveyor and the 2008-era source.
- **Layout output.** `artifacts/layout/{debug,release}/Libraries/Sample.Shipping/` each hold `Sample.Shipping.d4l`, `Documents/`, `Alphora.Shipping.dll` and its `.pdb` - and no `.deps.json`, which is what a library folder must not have. The Release `.pdb` is not a slip: every other library folder has one, because no converted project sets `DebugType`.
- **Tests, one ring wider than the implement stage.** `SamplesCorpusTest`, `FormCustomizationTest`, `FormDocumentCorpusTest`, `ParserRoundTripCorpusTest`, `LibraryLoadingTest`, `HostProgramTest` and `StoreRebuildWorkflowTest` together: 488 passed, 0 failed, 19 skipped in 50 s, with `Sample.Forum`, `Sample.Pubs` and `Sample.Shipping` the three skipped samples. `FrontendDerivationGoldenTest` separately: 3 passed. `python -m unittest discover -s tools/coverage-report`: 14 passed (the coverage map changed). `python tools/docs-size-check/check_size.py`: 13 files, 0 over the limit. Those are the neighbours a regression here would surface in: the fixtures of the same test area, the two that read the layout's library folders, and the checker of the file the diff edits.
- **`EverySampleIsAccountedFor` now exercises a path it used to skip.** Its SQL-device assertion is guarded by `LayoutHasTheLibrary`, so for `Sample.Shipping` it was previously short-circuited; with the library assembled it really resolves the sample's requisite closure (MSSQLDevice, Frontend, Security) against the layout and really finds a SQL device library in it. That is a genuine new check passing, not the same green as before.
- **The registration contract, by inspection, further than the handoff took it.** The handoff said no type name changed. Following the scripts instead: `Documents/Register.d4` reaches exactly eight `Shipping.*` class aliases (through `Schema.MSSQLDevice`, `Schema.DataTypes` and `Schema.MSSQLDataTypes`) - `CoordinateSelector`, the latitude and longitude read and write accessors, `CoordinateCompare`, `CoordinateConveyor` and `SQLCoordinate`. All eight are live classes, each caught by one of the five base-type filters in `Register.cs`, and each alias is `"Shipping."` plus the bare type name. The other thirty `Shipping.*` aliases in the tree appear only in `Source/Shipping.d4`, a reference copy of the whole schema that sits outside `Documents/` and that registration never executes; several of the classes it names are inside the commented-out blocks of `Coordinate.cs`, and that was already true in 3.1. So the class-alias compatibility surface is intact, and nothing reachable names a class the assembly does not register.

**Found and fixed in this pass (minor).**

- **`docs/migration-notes.md` carried a hand-maintained count that conversions keep forgetting to bump.** The assembly-version entry said signing and version 4.0.0.0 were "done for the seventeen SDK-style projects (the engine, protocol, server, SQLite store, the converted libraries and the coverage test helper)". Seventeen was the count at `system-library-version`; the hosts, the MSSQL catalog store, ODBCConnection and now `Alphora.Shipping` have been converted since, and the enumeration never mentioned hosts or stores. Rather than bump the number a fourth time, the sentence now points at `Dataphor.slnx` as the authority ("done for every SDK-style project in `Dataphor.slnx` … so read the solution file rather than a count here") and lists the groups without a total. That retires the staleness class instead of resetting its clock.
- **The coverage report's `reported` list is now documented as covering sample libraries.** `tools/coverage-report/README.md` defined it as "libraries, the client stack and the hosts", and AGENTS.md's checklist said "`reported` for a library, the client stack or a host" - neither of which told the implementer where a sample's assembly goes. `Alphora.Shipping` is the first sample assembly on any of the three lists, and `ignored` was not an option because that list is defined as source under `tests/`. The README entry now says so explicitly and names the one such assembly; the AGENTS.md clause now reads "a library - shipped or sample". The `areas.json` entry itself was left where the implementer put it: it is the only list that does not make the report suppress itself, and a sample is a library, not test code.

**Considered and deliberately not done.**

- **No test was added for `DAERegister.GetClasses()`.** This is the handoff's own named gap, and it is a real unverified contract, so it was weighed rather than waved through. A reflection test is the wrong layer here: `tests/DAE.Server.Tests`'s output folder has neither `Alphora.Dataphor.DAE.Connection.dll` nor `Alphora.Dataphor.DAE.Device.SQL.dll`, so `Assembly.LoadFrom` on the sample would need a bespoke resolve handler pointing into the layout, and it would load library assemblies into a test process whose engine state is already process-wide static. The behaviour's real layer is registration, `test-device-live` owns running anything against a SQL Server, and the `NeedsADatabaseServer` accepted-tradeoff `NOTE:` already records the decision with `test-device-live` as its revisit condition - which has not tripped. The inspection above is recorded here instead of as a test.
- **`coverage_report.py`'s own "Libraries, the client stack and the hosts" section blurb was left alone.** It is printed into `docs/coverage-report.md`, a checked-in generated file that can only be regenerated by a full collected test run (about 13 minutes across the suite parts, past what a ticket can hold), so changing the string would leave the tool and its committed output disagreeing until someone regenerates it. The instructional copies - the README and the AGENTS.md checklist - are the ones an agent reads before editing `areas.json`, and those are fixed.
- **`tools/net-spike/README.md`'s "all seventeen converted assemblies" is not stale.** It describes what `EngineCheck` checks, and `EngineCheck` references exactly seventeen projects with seventeen entries in its expected-resource table. It is not a count of conversions.

**Tripwires: none.** Nothing found here is of the "fine now, becomes work if X happens later" shape. The one conditional fact in the area - that `Source/Shipping.d4` names classes the assembly does not register - is not a tripwire either: it is a reference script no supported path executes, it was already so in 3.1, and the project rules forbid editing a sample's `.d4` files.

**Accepted tradeoffs: one re-read, none re-opened.** The `NeedsADatabaseServer` `NOTE:` in `SamplesCorpusTest.cs` was widened by the implementation to cover the third sample while keeping its 2026-11-22 measurement attributed only to the two samples that were measured, and keeping `test-device-live` as its revisit condition. That condition has not tripped, so the decision stands.

**Major findings: none, so no ticket was filed.** The conversion is a project-file change with no behaviour in it; the one thing it leaves unproved (that the sample registers) has an owner, a recorded tradeoff and no code site to fix.

**The three judgement calls the handoff asked about, upheld.** `Alphora.Shipping` on `reported` (now documented, see above); `NotInTheRuntimeLayout` kept as an empty dictionary with a `<remarks>`, because `EverySampleIsAccountedFor` asserts that list against the tree in both directions and a future unconverted sample needs somewhere to go; and the new `/samples/` solution folder, which mirrors the repository layout the way the existing `/engine/`, `/libraries/` and `/tests/` folders do.

## What is still owed

The sample's registration is unproved on .NET 10 and stays that way: `Sample.Shipping.d4l` requires `MSSQLDevice` and `Documents/Schema.MSSQLDevice.d4` creates a SQL Server device against `'ServerName'='.'` with database `Shipping`, which no machine in CI or in development has. What landed is that the assembly builds, ships and sits in the runtime layout. `test-device-live` owns attempting the registration.
