## What landed

`ReferenceSignatureGoldenTest` (new, `tests/DAE.Server.Tests`) starts an in-process server with **no library at all** — empty `Libraries`, empty `LibrariesToRegister`, so the System set is a function of the engine — asks it for every System operator's and scalar type's D4 declaration through the shipped `System.Script` operator, compares each with a checked-in file under `tests/goldens/reference/system-library/`, and then compares that file with the matching block of the published 3.x reference page.

- **331 golden files**: 311 operator declarations, 19 scalar type declarations, and `operator-inventory.txt` — 598 lines, one per System operator name, with its overload count and whether a page documents it.
- **`DATAPHOR_UPDATE_REFERENCE_GOLDENS=1`** writes them, deletes what nothing produces, and then fails the run anyway, like the two existing update variables.
- **Three cases**, all green in about 4 s: `EveryPublishedSignatureAgreesWithTheCatalog`, `TheSameCatalogAlwaysGeneratesTheSameDeclarations`, `ScriptingAScalarTypeWithNoSpecialsReturnsItsDeclaration`.

**The finding.** Of the 290 operator pages with a declarations block, 214 agree with a bare 4.0 catalog after normalization and 76 do not; of the 19 type pages with a declarations block, 15 agree; all 19 published *type declarations* differ. Every one of those differences traces to a change that had already landed by `418a5d45`, the commit this branch starts from, so **no documented System operator signature was changed by this port.** The 99 recorded differences fall into six families, each defined once with its measurement: tags older than the product, the untyped-list spelling, an operator body emitted as stored source text, overloads the 2007 help file did not list, the copy-script shape of a type declaration, and one page that carried the wrong operator's declarations altogether.

**An engine defect fixed along the way.** `Script` on a scalar type with no special values failed with "A nil was encountered where a value was expected." (error 104230) over a `NullReferenceException` from `Schema/Catalog.cs`, because the catalog emitter asked such a type's absent `IsSpecialOperator` for its dependencies. `Script('System.Boolean')` and `Script('System.Scalar')` were both affected, and so was any script of a library or catalog containing such a type. The defect is older than this port — the same unguarded call is at `418a5d45`. Reproduction: `ScriptingAScalarTypeWithNoSpecialsReturnsItsDeclaration`. Entry added to `docs/migration-notes.md`.

**One page corrected.** `docs/reference/system-library/operators/System.RequiredObjects.md` carried `System.RequiredLibraries`' two declarations — a conversion error, not a product difference. Replaced with `RequiredObjects`' four.

**Documentation.** `docs/modernization-plan.md` gains *Design notes, the reference generator*, which settles where the reference generator lives (a test fixture; `legacy/libraries/Documentation` stays parked) and records the measurements behind it. `docs/reference/README.md` and `docs/reference/system-library/README.md` lose the "`docs-reference-generator` will emit signatures from a running server" promises; the latter gains a *What the running product says* section telling a reader which pages are current and which to read the golden for instead. `AGENTS.md` and `docs/contributing/build-and-test.md` gain the fixture and the third update variable. The goldens tree is pinned `text eol=crlf` in `.gitattributes`, because these files are the D4 emitter's own output and `TextEmitter.NewLine` writes CRLF.

The implement stage is commit `ticket(implement): docs-reference-signatures`. Review changed nine things in that work and parked one tripwire; all are listed below.

## Review findings

Read the implement diff before the handoff, then checked every number it asserts against the tree, read `Catalog.EmitDependencies` and all nineteen of its call sites, and broke each of the fixture's invariants on purpose to see it fail. The handoff was unusually candid — it listed nine places where the work departed from the implement ticket and invited a second opinion on each — so those are answered explicitly at the end.

### Checked and sound

- **Every count the diff states reconciles exactly.** 322 operator pages minus the 25 category index pages the README links is 297 object pages; minus the seven with no declarations block is 290. 20 type pages, minus `System.GroupName` is 19 compared. The 311 operator golden names are exactly the union of the 297 object page names and the 20 type names, less the five that are both and less `GroupName` — checked by set difference, both directions, with no name left over on either side. The recorded difference table holds 76 operator entries, 4 type-page `Declarations` entries and 19 `Type Declaration` entries, which is 290 − 214, 19 − 15, and 19.
- **`.gitattributes` does what its comment says.** `git check-attr text eol` reports `eol=crlf` on a reference golden and `eol=lf` on the rest of `tests/goldens`; the later pattern wins, as intended. Deleting a golden and regenerating it through the update variable produced a byte-identical file, so the attribute and the emitter agree rather than only appearing to.
- **The update path behaves as documented.** On a clean tree, `DATAPHOR_UPDATE_REFERENCE_GOLDENS=1` wrote 0 files, deleted 0, and failed anyway. With one golden deleted, the ordinary run named the missing file and the update run wrote exactly 1.
- **A new page cannot escape the comparison.** A page dropped into `operators/` named after a real undocumented operator (`System.AttachLibraries`) with no declarations block failed the run twice over: the missing block, and the inventory line that flipped from `undocumented` to `documented`.
- **The migration note's error text is right.** Reverting the guard and running the reproduction reported error 104230, "A nil was encountered where a value was expected.", with an inner `NullReferenceException` — which is what the note says a user saw, not the bare runtime exception it would have been easy to assume.
- **No case-insensitive collision among the 311 golden names,** which matters because a golden's name comes from a catalog object name compared ordinally while the file it lands in is on a case-insensitive filesystem. There is no such pair today; parked as a tripwire below rather than defended against.
- **Source hygiene.** CRLF everywhere, the UTF-8 byte-order mark preserved on the fixture and absent from `Catalog.cs`, LF preserved on the one reference page that has it. No file reformatted or re-encoded, and nothing in the golden tree touched except by the fixture's own update path.

### Fixed in this pass

- **The engine fix was at one call site of nineteen, and its comment was wrong about the others.** The guard landed as `if (scalarType.IsSpecialOperator != null)` at the site, with a comment saying "the calls around this one are guarded by their own conditions". Two lines below it, `EmitDependencies(context, special.Selector)` and `EmitDependencies(context, special.Comparer)` are not guarded, and both properties are null by construction — their backing fields start null, their setters accept null, and `ResolveGeneratedDependents` only resolves them for a type that has at least one representation. The method itself is the one place that dereferences what it is handed, so the guard moved there, with a comment naming the optional members its callers pass; the site keeps a one-line note. This is strictly crash-to-no-op, the same change the site guard made, and it retires the class rather than the instance. Whether a null can actually reach the two sibling sites was *not* established — the fix removes the need to establish it, which is why no ticket was filed for them.
- **The page reader was not strict, although its remarks said it was.** `Block` searched forward from the heading for the first ` ```d4 ` fence anywhere on the page. 273 of the 310 pages with a declaration heading carry further d4 blocks in their examples (measured), so a declarations block that lost its fence — a reformat, a changed language tag — would have been compared silently against that page's *first example* and classified as a content difference. The fence must now be the first non-blank line after the heading, which is true of every page of the corpus (measured, all 342 files under `operators` and `types`), and a page where it is not fails naming itself. Verified by breaking `System.Abs`'s fence: before, a confusing content mismatch; now, "has a **Declarations** heading whose first non-blank line is not a terminated ```d4 block".
- **A link in the README could silently remove a page from the comparison.** Category index pages are identified by being linked from the system library README's Operators list — which is the right rule, and is what keeps a new page from escaping by looking like a category, but it also means a link *to an object page* added to that list reclassifies it and drops it out. For one of the 214 pages that agree with the catalog, nothing else would have said so. `CategoryPages` now fails if a page it reads as a category carries a declarations block. Verified by adding a link to `System.Abs` to that list.
- **The engine defect's reproduction could never report the engine defect.** Generation ran in a `[SetUp]`, so with the guard reverted all three cases failed in setup with the same message and the dedicated case added nothing — the opposite of what the handoff claims for it. Generation is now called by the two cases that need it. Verified by reverting the guard again: `ScriptingAScalarTypeWithNoSpecialsReturnsItsDeclaration` now fails on its own `Script(ASpecifier)` evaluation, at the expression's own position, while the other two fail on theirs.
- **"308 undocumented operator names" is 301.** Measured from the inventory the fixture itself writes: 297 `documented`, 301 `undocumented`, 598 lines. 308 is 598 − 290, which subtracts the pages that have a *declarations block* rather than the 297 pages that exist — the seven operator pages with no block still document their operator, and the inventory marks them documented. Corrected in `AGENTS.md`, the plan's design note, the system library README and the fixture's own comment, which were the four places that repeated it.
- **"696 cases" in `AGENTS.md` is the passed count, not the case count.** The sentence says the parser corpus "runs one L0 case per `.d4` file in the repository (696 at the time of writing)", but 696 is what a run reports as *passed*; the 19 parked documents are Ignored. There are 726 `.d4` files under the fixture's walk, minus the 15 `AllowList` entries, so 711 file cases — 715 total with the fixture's four set-assertion cases, which is exactly what a run reports. Corrected to 711. (The 387 it replaced was already stale by six; the number is now measured rather than carried.)
- **`docs/contributing/build-and-test.md` had been made less accurate.** "Three variables change what a test run does" became "change which tests a run includes", which is wrong for `DATAPHOR_TEST_LOGGING` — that one changes what a run does and includes no extra test. Reworded to cover both kinds.
- **"214 match this release exactly" overstated the comparison,** which normalizes the tabs and line endings the help file's conversion introduced. The plan and `AGENTS.md` say so; the reader-facing README did not. Reworded.
- **The evaluated value was not disposed.** `ServerProcess.Evaluate` returns an `IDataValue`; the reproduction case read `AsNative` off it and dropped it. Now in a `using`, as `JSONObjectConveyorTest` does. Five of the six existing call sites of this idiom also drop it — that is pre-existing and not touched here.

### Parked as a tripwire, not a ticket

- **Two System names differing only in case would share one golden file.** The set that decides which goldens are still produced is compared case-insensitively, because it is held against names a Windows filesystem gives back, while the catalog's own names are compared ordinally. There is no such pair among the 311 names today. `NOTE:` at the site, saying what would have to change (`GoldenRelativePath` would have to disambiguate) if one ever arrives.

The three tripwires the implement stage parked were read and left where they are: the 19 type-declaration entries (fixture remarks and `ReferenceDifferenceFamily.CopyScriptShape`), whether the reference should track the product or stay the 3.x record (the plan's new design note), and the coupling to the parser corpus (`ParserRoundTripCorpusTest`'s remarks).

### Answers to the handoff's nine deviations

The handoff asked a reviewer to overturn any of nine judgements. Items 1, 2, 8 and 9 are corrections of the implement ticket's own premises, each measured and recorded in the plan; nothing to decide. The other five stand, for these reasons:

- **The fifth verdict, `PreThreeOne` (item 3), stays.** Forcing 75 faithful-to-2007 pages into `Stale` would mean rewriting about 45 pages, and into `Changed` would mean 45 migration-note entries for changes this release did not make. The verdict says what is true, and it is the one that carries the compatibility conclusion.
- **The pages stay the 3.x record (item 4), including the thirteen that omit overloads.** They are the baseline the comparison measures against; a page refreshed to 4.0 makes the next run compare 4.0 against 4.0. The reader is served instead by the README section that names those thirteen and says to read the golden, and the goldens are checked in beside the pages. Whether the reference should eventually track the product is a documentation-policy question, already recorded as such in the plan.
- **One test case rather than ~310 (item 5) stays**, on `FrontendDerivationGoldenTest`'s precedent: the set comparisons need every page's answer, and a per-page case would give the wrong answer under the name filters the suite is run with. The cost is a failure that names pages in its message; the report caps at 40.
- **No structural comparator for type declarations (item 6).** The 19 are recorded with a measured reason — no shipped surface emits the published inline shape, because `Catalog.EmitChildren` moves a representation with external dependencies into an `alter type`, which every System type's representations have — and the fixture fails the day one agrees. Building a comparator that extracts `(representation, properties, selector class)` triples from both texts is new machinery with one consumer; it belongs to `docs-reference-generator` if that ticket wants it.
- **The goldens stay in the parser round-trip corpus (item 7).** It asks whether the catalog copy script the product generates can be read back, which is a property an administrator depends on, and all 330 pass. Both fixtures' remarks say the coupling is deliberate.

One number in the handoff is wrong and nothing committed repeats it: it says the tags family has 46 entries; the table has 53.

### Tests

No test was added and none cut. The three cases each earn their place: the first *is* the ticket and is the characterization test the project's testing rule asks for; the second pins the determinism every golden rests on, including across a second independently built engine, which holds by measurement rather than by construction; the third is the reproduction of the engine defect this ticket fixed, at the lowest layer that shows it, and after the setup fix it now actually reports that defect. The four defects found in this pass are all pinned by deliberate breakage rather than by new cases — two of them (the fence and the README link) by invariants added to the existing pass, which is what makes them regressions a future run catches.
