## What landed

The tooling the four remaining tickets of the legacy-reference chain read. No page under `docs/` was published; the only `docs/` change is the plan's new WS8 design notes, and the link checker still reports 0 errors, 203 pending, 12 external, which is what CI expects.

- **`tools/docs-convert/reference_split.py`** (new, 765 lines) with two modes. `declarations` reads the decompiled help file's `O-*.html` and `T-*.html` pages and writes the signature table. `split` reads the reference DocBook, fills in or removes the generated-content placeholders, groups sections onto pages, and writes one DocBook document per page plus the `pages.tsv` that `convert.py docbook --pages` reads; `--seed-pages` writes a seeded page map instead.
- **`tools/docs-convert/convert.py`**: `--legacy-map TSV`, consulted in `Resolver.legacy()` before the built-in rules; a hit supplies the target (which may carry a `#fragment`), an empty target unlinks and keeps the text, a miss falls through. The legacy-page gate is now `\.html?$` matched case-insensitively. A `<phrase role="code">`, which pandoc leaves as a raw `<span class="code">`, becomes inline code (added in review - see the findings below). Three new report sections.
- **`tools/docs-convert/declarations.tsv`** - 360 rows, read from 411 help pages; every row is a D4 `create operator` or `create aggregate` statement, no non-ASCII byte.
- **`tools/docs-convert/reference-pages.tsv`** - 360 rows covering every section of `SystemOperators.xml` and `SystemTypes.xml`, with the merges applied.
- **`tools/docs-convert/reference-links.tsv`** - 115 rows: 87 with a verified heading anchor, 20 naming a whole page (5 of them retargeting a reference page the built-in rule would place wrongly), 8 deliberately empty.
- **`tools/docs-convert/README.md`** gains a *The legacy reference: reference_split.py* section (both modes, every rule, the decompile-to-scratch warning), three rows in *Inputs and tables*, the `--legacy-map` option row, and the extended legacy-link rules.
- **`AGENTS.md`**'s `tools/` row now names both scripts in `docs-convert/` (added in review).
- **`docs/modernization-plan.md`** gains a *Design notes, the legacy reference* paragraph with the four decisions: where the prose comes from, where the signatures come from, why library facts are not taken from the help file, and what the page layout is.

## How it was validated

`pandoc` is **not on `PATH` on this machine**: it is at `%LOCALAPPDATA%\Pandoc\pandoc.exe`, so every `convert.py` command needs `--pandoc` with that path.

The implement stage proved the machinery on an 18-page sample. The review ran it over **all 341 pages** of the split instead, which is the stronger check and is what the numbers below come from.

    python tools/docs-convert/reference_split.py split legacy/Documentation/Docs2.0/SystemOperators.xml legacy/Documentation/Docs2.0/SystemTypes.xml --pages tools/docs-convert/reference-pages.tsv --declarations tools/docs-convert/declarations.tsv --out <scratch>\refwork
    python tools/docs-convert/convert.py docbook <scratch>\refwork\*.xml --out <scratch>\refout --pages <scratch>\refwork\pages.tsv --legacy-html --legacy-map tools/docs-convert/reference-links.tsv --global-ids --match-heading-text --pandoc <pandoc>

- 341 pages split from 359 sections, 311 declaration blocks filled; 341 pages converted, 2,048 legacy links all with a target, **0 unresolved references**, no surviving placeholder, exactly one `#` heading per page.
- Both steps run twice over the same inputs give **byte-identical** output, before and after the review's changes (`diff -r`).
- `git status` after every run: no scratch file in the tree, no help-file dump, `legacy-links.tsv` byte-identical to the committed file.
- **A 341-file command line is about 25 KB.** It works from bash or PowerShell (the Windows process limit is 32 KB) but is over `cmd.exe`'s 8 KB limit, and it fails outright if the work folder's path is long - the first attempt in this review did, from a scratch path about 120 characters deep. Use a short work folder. Recorded here because the three downstream tickets type this command.

To rebuild `declarations.tsv` (not needed; it is committed so that a rerun needs neither the help file nor `hh.exe`):

## Review findings

The implement-stage diff (`ticket(implement): docs-reference-tooling`) was read before its handoff summary. Every numeric claim in that handoff was re-measured; all of them held. What follows is what the read and the runs turned up.

**Fixed in this pass.**

- **1,035 raw `<span class="code">` on 280 of the 341 pages.** The handoff named this and deferred it to `docs-reference-operators` on the grounds that the implement ticket's remit was one change to `convert.py`. That is a scope argument, not a technical one, and leaving a documentation tool that emits 1,035 broken inline-code spans is not finished tooling, so it is fixed here: `code_phrase` in `convert.py` turns a Span with a `code` class into a `Code` inline. The full run now reports 1,035 converted and the raw-HTML list is down to 20 `<sup>`. **The handoff's one-line description of the fix was wrong in a way that would have cost the next agent the finding:** 78 of those phrases in the reference sources are not plain text, so a bare stringify is not obviously safe. All 78 nest only `<emphasis role="bold">` around a D4 keyword, which a code span already says, so stringifying loses nothing - but a phrase holding a *link* cannot become a code span at all, so that case unwraps instead and is listed. One test pins both branches.
- **Two pages that flatten to the same work file name silently lost one of them.** `work_name` folds path separators to `-` and its docstring claimed two pages "can never collide"; they can, and `convert.py docbook --pages` keeps the last row for a repeated source, so the page would have vanished with nothing in the report. `check_work_names` makes it an error that writes nothing. No collision exists in today's table, but the three downstream tickets add new path shapes. One test.
- **A stale document in a reused work folder quietly becomes a published page.** The next command converts the folder's `*.xml`; a document whose page has left the map is not in `pages.tsv` either, so `convert.py` derives an output from its file name and writes it. `check_stale_documents` lists them. This is reachable the moment a downstream ticket renames a page and reuses its scratch folder - which the chain's own instruction to "rerun the conversion over every source landed so far" invites.
- **The `declarations.tsv` row of `README.md`'s *Inputs and tables* held a literal tab, carriage return and newline inside a Markdown table cell.** The newline split the row in two, so the table renders broken on GitHub. Rewritten to name the escape sequences in words. Also added the blank line missing before the following `##` heading.
- **`read_xml`'s docstring claimed "every source parses as it stands and only the predefined entities appear".** False for `Docs2.0/` as a whole: four book parts use `&nbsp;` and `DataphorSet.xml` / `DataphorSet2.xml` declare the set's file includes in the internal subset the function strips, so six files fail with a bare "undefined entity: line N". True for the seven *reference* sources, which is what the sentence meant. Narrowed, and the limitation is now stated in the docstring and the README - `docs-reference-chapters` names `D4LanguageGuide.xml` in its survey, and all four files it actually converts do parse.
- **Two small simplifications.** `extract_declarations` ended with `if report.errors: return 1`, unreachable because nothing in that mode reports an error (a bad row raises). `link_names` computed its preference by calling `rule_output("")` on the first sighting of a page, which reads as a bug; rewritten to the obvious form.
- **`AGENTS.md`'s `tools/` row** still described `docs-convert/` as the AsciiDoc converter only, so a future agent reading the layout would not know `reference_split.py` exists.

**Corrections to the handoff, recorded where the next ticket will meet them.** Appended to `docs-reference-operators` as *Corrections measured by the review*:

## Decisions the implement stage made that the review accepted

Each was re-derived rather than taken on trust.

- **Page-map outputs are docs-root-relative** (`reference/system-library/operators/System.Abs.md`), not the ticket's `operators/<Name>.md`. `Resolver.legacy()` makes a legacy target relative to the current page's own output and the built-in rule's targets are docs-root-relative, so the map and the rule have to share a root. Confirmed by resolving all 203 pending targets against the split's outputs.
- **An empty `output` means "not a page of its own"** - the section is rendered inside the page of its nearest enclosing section that is one. A top-level section with an empty output is still not converted and is listed. This is what will let `docs-reference-libraries` put a library chapter's Definition, Settings and Example sections on one page.
- **Section order within a page is the page map's row order**, not document order; a seeded table is in document order, so the default is document order and the freedom is what lets a merged page lead with the section carrying the signatures.
- **`reference-pages.tsv` carries `title` and `reason` columns** beyond the ticket's schema. `title` earns its place twice (four sections title themselves `iIndexerSystem.iIndexer (List)`, and merging needs the headings to tell sections apart); `reason` had to exist because `docs-reference-operators` already says the table "records with a reason" why `SystemLibraryReference.xml` is not converted.
- **The legacy-page gate is `\.html?$` case-insensitive**, wider than the ticket's "case-insensitive". The extra `.htm` covers one typo in `SQLDeviceSettings.xml`. Re-verified safe: `Documentation/` has 208 `.html` references and no `.htm` or `.HTML` ones, and a full AsciiDoc rerun in this review reproduced the committed pages.
- **Category link lists use the help-page name the built-in rule already sends to that page**, so 3 pages need a `--legacy-map` row rather than 21, and the split names those 3.
- **`O-System.SettIsolationLevel` is given the page `System.SetIsolationLevel.md`.** The section id misspells the operator, nothing links to that help page, and the split reports the override.
