# One version, signed everywhere — complete

Landed in `ticket(implement): build-version-and-signing`; reviewed in this pass with no code changes.

## What was done

- `Directory.Build.props` is the only version source: `VersionPrefix` 4.0.0, `VersionSuffix` preview, `FileVersion` 4.0.0.`$(DataphorBuildNumber)` (default 0, with a `NOTE:` for `installer-msi` about equal file versions in minor upgrades), company, product and copyright, generated assembly attributes (title and description stay in each `AssemblyInfo.cs`), `Deterministic` on, `ContinuousIntegrationBuild` under GitHub Actions, and unconditional signing with the root `Dataphor.snk`.
- The ten SDK-style projects' `AssemblyInfo.cs` files lost the version, identity, culture, configuration and key attributes and the template comments; `AssemblyTitle`, `AssemblyDescription`, `DAERegister`, `ComVisible` and `Guid` stay. AGENTS.md lists what to strip when converting the next project.
- Deviation from the plan: the D4 `System` library keeps version 3.1 (now a fixed `3.1.0.0` from `Engine.SystemLibraryVersion`), because `LibraryCoverage.d4` references `System` version 3 and application libraries can do the same. The catalog store writes that library version, not the assembly version, for `System` in `DAELibraryVersions` and `DAEServerInfo.Version`. The decision is in `tickets/blocked/system-library-version.md`, with "keep 3.1" as the recommended default.
- Migration notes: one entry for the 4.0.0.0 version and signing (public key token `5202040c6ce50aea`, the same `Dataphor.snk` the legacy Release builds used), one for the version-named settings folders moving `3\`→`4\` and `3.1\`→`4.0\`.
