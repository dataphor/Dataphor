## What landed

`ReferenceSignatureGoldenTest` gained one case, `EverySystemTableHasAGeneratedPage`, and `docs/reference/system-library/tables/` gained 56 generated files: one page per table variable a bare engine's catalog reports — 48 base tables and 7 views — plus a generated section index. The case compares every file in that folder, whole, with what the catalog generates for it, and holds the two recorded table-variable sets (`SystemTables`, `SystemViews`) against the catalog in both directions and against the kind it reports. `DATAPHOR_UPDATE_REFERENCE_GOLDENS=1` now also writes these pages and deletes the ones no table produces; it is the one update variable that writes under `docs/`.

A page carries the object's name, a framing sentence saying it is generated, the `create table` or `create view` statement the shipped `Script` operator emits, a **Built From** list of the other system tables a view's definition names (on 5 of the 7 view pages — `System.ListLogs` and `System.ViewLog` are built from an operator call), and a **See Also** line. No descriptions, because the catalog has none to report: no table or column of `src/engine/DAE/Schema/SystemCatalog.d4` carries a `Catalog.Comment` tag, against 17 in `DataTypes.d4`.

The implement stage also recorded, in the plan's *Design notes, the reference generator*, three premises of the original work-item row that the measuring corrected: `Script` on a table variable does **not** emit its references; there is **no `Columns` system table**; and `SystemCatalog.d4` declares 62 tables and views where the catalog reports 55 (six are inside a block comment, and `Generators` is created by `EnsureGenerators` in the calling library's own namespace).

The full account of what was built and why is `ticket(implement): docs-reference-generator` and the plan's WS8 section. This ticket records the review pass over it.

## Review findings

**Read first, in this order:** the implement diff with fresh eyes, then the handoff; then the generated pages themselves; then the claims each document makes, against the tree.

### Fixed in this pass

- **`docs/contributing/writing-docs.md` was the document this change should have touched and didn't.** It is the page that tells a contributor how to edit documentation, and it said flatly *"there is no build step, no generator and no toolchain to install. A page is a file; you edit it and commit it."* That became false for 56 pages the moment this ticket landed: a hand edit in `docs/reference/system-library/tables/` fails the test run and is reverted by the next update run, and nothing a contributor reads told them so. Corrected the claim and added a short section, *One folder is generated, and must not be edited by hand*, naming the folder, the fixture that enforces it, the update variable that reverts an edit, and where to read why. This was the most consequential finding: every other document the change touched was accurate.

- **The generated index made one factual claim about the catalog that nothing checked.** The index tells a reader `` `Script('System.TableVars_CatalogObjects')` `` will give a reference in full — a hardcoded catalog object name in published documentation, which a rename in `SystemCatalog.d4` would silently turn into advice to run something that fails. The name is correct today (verified: the case passes, and the reference is declared inline on `create table TableVars` at `src/engine/DAE/Schema/SystemCatalog.d4:1763`). Extracted it to `ExampleReferenceName` and held it against the `select References where Library_Name = 'System'` query the index's count already comes from, so the claim is now asserted rather than remembered. Verified in both directions: green as it stands, and pointed at a name the catalog does not have it reports *"the generated index tells a reader to script … and the System library has no reference of that name."*

- **`FirstDifference` could not report a difference in the new comparison.** It excerpted 200 characters from the *start* of the differing line. That was adequate for the goldens this fixture already compared — D4, which the emitter breaks into short lines — but the generated index carries paragraphs of 400–900 characters on one line, so a difference inside one printed the same 200 characters for both sides and said nothing. Measured, not inferred: a probe that changed one number in the index produced two identical-looking excerpts. It now reports the line **and the column** and a window centred on the difference; the same probe now reports *"line 9, column 385 … There are 58 of them … / There are 57 of them …"*. The window is also what a difference in a page's **Definition** block gets, where the emitted D4 lines are short enough that the whole line still prints.

- **The fixture's own class summary described only half of what it does.** It said the fixture compares every published signature with the catalog; it now also *writes* 56 documentation pages, which is a different job. Added two lines pointing at the new case, which carries its own full account.

- A stray double blank line before `#region Table pages`.

### Checked and found correct

- **The page shape and the one decision that departed from the ticket.** The ticket could be read as putting the 55-entry index inside the hand-written `docs/reference/system-library/README.md`; it landed as a generated `tables/README.md` with three sentences of hand-written prose linking it. Reviewed and agreed: the ticket's own rule for that folder is whole-file generation and whole-file comparison, and generating a region inside a hand-maintained README is the shape the ticket assigned to the *other* ticket in the chain. The hand-written section it replaced reads correctly and links the index.

- **`**Built From**`, the fifth page element the ticket did not ask for.** Kept. It is a qualified-identifier scan of the emitted text filtered against the catalog's table-variable names, it produces links and no verdict, and any name it finds is in the definition printed on the same page, so an incomplete scan costs a link and claims nothing false. The two views it produces nothing for are built from operator calls, which is correct.

- **Line endings, and the normalization the comparison depends on.** `core.autocrlf=true` is set in this clone, so a fresh checkout hands the working tree CRLF copies of these LF-committed pages; a comparison that did not normalize would fail on every page for everyone who cloned. Both sides are made LF before comparing, and an update run on a CRLF working tree therefore rewrites nothing. Confirmed by reading `.gitattributes` (no `text` rule for Markdown, deliberately) and by the no-op update run below.

- **Every failure path, exercised rather than assumed.** Appending a line to a page, deleting a page and dropping a `notes.txt` in the folder produced exactly three messages naming each; removing an entry from `SystemTables` produced both directions of the set check in one run (*"the System library has the table System.Users and it is not recorded in SystemTables"* and *"System.UsersNot is recorded in SystemTables and the System library does not have it"*), confirming that an update run repairs pages but never the recorded lists — which is the point of them. The tree was restored from a copy taken beforehand and verified byte-identical, not with git.

- **The documents' numbers.** 56 files in the folder; 55 table variables, 48 + 7; 0 `Catalog.Comment` tags in `SystemCatalog.d4` against 17 in `DataTypes.d4`; 62 `create table`/`create view` lines; `System.TableVars_CatalogObjects` present at the line the plan's note implies. `docs/README.md` needs no entry — it links the System library page and not its subsections, the same as for operators and types. No migration note is owed: no engine source, public member or file format changed.

### Parked as tripwires, not filed

Three `NOTE:` comments, all at their site in the fixture, each with the condition that would make it work:

- `ReadTablePage` uses `File.ReadAllText`, which drops a UTF-8 byte-order mark without saying so, so a page that acquired one would compare equal and keep it while the write path always writes none. Reachable only by a hand edit in a folder whose every page says not to edit it, and `ReadGolden` has had the same blind spot since the fixture was written.
- The column-aware `Excerpt`/`FirstDifference` pair is duplicated in `FrontendDerivationGoldenTest` and `DeviceTranslationGoldenTests`, which still carry the start-of-line form. Theirs compare D4 and XML with short lines, where it is adequate, so the three were left as three; a third caller needing the column is the point to unify them.
- The fixture is **1,506 lines** (`wc -l tests/DAE.Server.Tests/ReferenceSignatureGoldenTest.cs`) and holds two passes with different comparison rules. One coherent subject — what the reference says against what the catalog says — so it was left whole; the NOTE names the cut and the helpers that would move with it if a third pass arrives. The implement handoff reached the same conclusion; it is now recorded in the code rather than only in a handoff.

### Considered and not recorded, with the reason

- **The determinism case covers the table definitions and the view list but not the reference count that also feeds the index.** Left alone deliberately. That case exists for *emitted text*, where a hash-table iteration order or a timestamp could plausibly leak in; a row count over a catalog table on a server built the same way has no such degree of freedom, and asserting it would broaden the case's stated property without adding a plausible failure mode.

### Nothing filed

No ticket was filed, and the reason is not "looks good": every finding either had a one-line fix in this pass (five of them) or is genuinely conditional and belongs at its site (three `NOTE:` comments). Nothing reached the filing bar — no finding named a class-level invariant, and no latent defect was found. The three premises the implement stage corrected were corrected in the plan rather than left as debt.

## Known gaps, stated plainly

- **The pages carry no prose about what each table is for**, and there is no source to write it from. That is the decision, with its measurement; the index says so and points at the Developer's Guide. A reviewer who wants a sentence per table is asking for new material, not for this generator to change.
- **No per-table reference list.** `Script` does not emit a table's references and `System.References` does not say which two tables one connects, so pairing the 57 System references with their tables means parsing emitted `create reference` text. The index points a reader at `Script` of a reference's own name instead, and that name is now held against the catalog.
- **Two table variable names differing only in case would share one page.** Recorded as a `NOTE:` at the claim set by the implement stage, with the measurement that the 55 names are case-insensitively distinct today. The claim set is case-insensitive because it is held against names a Windows filesystem gives back.
- **Nothing enforces that a reviewer reads an update run's diff** beyond the run always failing and saying so. 56 files was a large first commit; from here a change to a system table is a one-page diff.
