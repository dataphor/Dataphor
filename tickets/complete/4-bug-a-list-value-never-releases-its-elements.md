## What landed

One rule, applied at every site: **a list owns its elements, copies what it is given, and releases what it holds.** `ListValue` had no `Dispose(bool)` at all, so every element of every list of `Binary` or `Graphic` was held for the life of the session - no loop was needed, evaluating a list and discarding it cost one stream per element - and it took a plain native element as it stood while the call that handed it over released it, so `Add` and `Insert` left the list pointing at a released stream and reading the element back raised `StreamID (n) not found`.

`ListValue` now mirrors `Row`: a `Dispose(bool)` that clears the elements when `ValuesOwned`, the flag set explicitly in all three constructors (`false` for the one taking a `NativeList`, which is the window every `DataValue.FromNative*` builds; `true` for the other two), and `Add`, `Insert` and the element setter copying a plain native element with `DataValue.CopyNative`. `NativeMarshal.NativeValueToDataValue` sets the flag on the list it does own and disposes each element the list has copied. The callers that hand a value to a list release it after the add - the list selector, both branches of `ToList`, and the return expression of a `foreach` - and the three `foreach` list branches (`ForEachNode`, `ListForEachNode`, `TableForEachNode`) null the loop variable's slot in the `finally` that pops it and release the list they evaluated on every exit path.

**The one D4-visible consequence**: `var LB : Binary; foreach LB in LL do ...` leaves `LB` nil, where it used to hold the last element, so the list branch now agrees with the cursor branch, which has always nulled its slot. Only that form can observe it. `docs/migration-notes.md` carries it, with a second entry for custom C# extensions, and the container section of `docs/architecture/value-lifetime.md` is rewritten to what is now true. `TableValue` keeps its lack of disposal deliberately, recorded in a `NOTE:` at the class with the measurement behind it, and the `NOTE:` at `Program.Stop` now names the three leaks that still block a `DEBUG` stream-count check there.

Two defects were met at `Distinct` along the way. One was fixed here because the change would otherwise have shipped a regression: the `NativeSet` the operator builds releases every element it holds when it is dropped, and it was being given the source list's own elements, so `LL.Distinct()` over a `list(Binary)` raised `StreamID (n) not found` once a list released its elements (before, the same code produced a result whose elements were released streams - a silent wrong answer, which is why nothing caught it). The other was filed: `Distinct` does not in fact remove duplicates from a list of `Binary`, `Graphic`, rows or lists, because the set hashes a value by where it is stored rather than by what it contains - `bug-distinct-leaves-duplicate-pictures-in-a-list`, with a `NOTE:` at the comparer recording the measurement.

Tests: a new C# fixture `ContainerValueOwnershipTest` asserting the `ValuesOwned` contract over the value classes directly, in both directions, and a list section in the `StreamValues.d4` coverage script covering the measured shapes, the `Add`/`Insert` read-back, the nil loop variable, `Distinct`, and the two error paths the review added. The implementation is in `ticket(implement): bug-a-list-value-never-releases-its-elements`.

## Review findings

The implement-stage diff was read before the handoff, and the ownership rule traced through every caller of `ListValue.Add`, `Insert` and the element setter in `src/` and `libraries/`, every `ListValue` constructor call site, `DataValue.CopyValue`/`CopyNative`/`DisposeNative` for each element kind, `NativeSet`, and the three `foreach` branches. The change is sound and the measurements behind it hold up.

**Fixed in this pass.**

- **A list part way built leaked its elements when something raised.** The implementation gave the list selector a `catch { list.Dispose(); throw; }` and left the same shape unguarded in `ListForEachNode` (both branches) and in both branches of `ToListNode`: a raise part way through left a list holding copies that nothing would release. Not a regression - before the change those elements leaked on every path, success included - but an incomplete application of the rule the commit states, and reachable from an ordinary D4 error. All three now dispose the partial list and rethrow. `ListForEachNode.InternalExecute` had its iteration extracted into a private `Iterate(Program, ListValue)` so that the guard reads as three lines rather than reindenting forty.
- **Both error paths now have a reproduction**, which is what the handoff said nothing measured: two blocks in `StreamValues.d4` over a new `TestRaiseOn` operator - a list selector whose second element raises, and a `foreach` whose return expression raises on the second element - each asserting the count comes back and that the source list's elements survive. Checked against the defect in both directions: with the selector's dispose removed the first block fails with "A list selector whose element raised left 1 stream(s) behind", and with the `foreach` dispose removed the second fails the same way. `ToList`'s two branches are left uncovered and the block says so: a cursor that raises part way through its own iteration is not something a D4 script can arrange.
- **`StreamCount()` was duplicated verbatim** in `AssignmentValueOwnershipTest` and the new `ContainerValueOwnershipTest`; it is now a `protected` member of `InProcessTestFixture`, beside the `ExecuteScript` helpers that were already shared there, and both copies are gone.

**Recorded as tripwires rather than tickets** - both are the open questions the handoff asked the reviewer to settle.

- **`ListValue.DisposeValueAt` releases the element whether or not the list owns it**, where `Row.ClearValue` checks `ValuesOwned` first. A `NOTE:` at the method now states why the asymmetry is deliberate: every caller - `Clear`, `RemoveAt`, the element setter, the `AsNative` setter - also takes the element out of the `NativeList`, which on a window would strip a list another owner holds, so these are mutators of an owned list and a guard would only make the wrong call quieter; disposal itself is guarded. No D4 path reaches them on a window, because the mutating operators all take a `var` operand, which only a stack reference satisfies, and a slot owns its list. The note says that refusing the mutation, not skipping the release, is the fix if a window ever does reach one.
- **The row and table branches of `NativeMarshal.NativeValueToDataValue` still hand each value they build straight to a setter that copies it and never dispose the intermediate.** The handoff's reasoning is right - a value arriving over the native call interface is never stream-backed, since a `Binary` comes over as a byte array and the `Scalar` built for it is native, so each discarded intermediate is plain managed memory - but it lived only in the handoff. It is now a `NOTE:` at the two branches, naming what would turn them into leaks of one stream per value.

**Appended as arms to open tickets** rather than filed fresh; the site-claim grep over `tickets/backlog`, `fix`, `plan`, `implement` and `review` found both.

- **`bug-distinct-leaves-duplicate-pictures-in-a-list`**: over a list whose element type is not scalar, `Distinct` does not return a wrong answer - it raises. Reading such an element gives back a host value (`DataValue.FromNativeList` builds a `Row` or a `ListValue`), and that is what goes into the set, but the set releases through `DataValue.DisposeNative`, which casts its argument to the native structure, so dropping the set throws `InvalidCastException`. Static, pre-existing, and it resolves where the hash does: what the set holds has to be settled before how it hashes can be.
- **`bug-a-loop-variable-stays-borrowed-after-the-loop`**: all three `foreach` branches lend the slot with the raw `Stack.Poke`, which does not release what it displaces, so a loop over a variable that already has a value orphans that value as the loop starts - one stream per such loop, on the cursor branch too. Static, pre-existing, unchanged by this ticket, and the same slot and construct that ticket already owns. The arm also notes that the list branch is written out three times across two files, so whoever changes how a loop borrows its variable pays for the duplication three times over and may want to extract the shell first.

**Checked and found nothing.** The other `ListValue.Add` callers outside the diff: `DistinctListNode` passes the source list's own element, which the list copies and the source still owns, correctly; `StringNodes` (`Split`, `ReadUnicode`) and `LibraryNodes` pass strings, integers and `Clone`d managed objects, where the extra copy `Add` now takes is garbage-collected rather than a held stream; `ListValue.ReadFromPhysical` writes the native list directly and does not go through `Add`. The `ReturnsByReference` guards the change leans on are sound - `StackReferenceNode` and `StackColumnReferenceNode` copy exactly when they answer false. `ListValue.Dispose(bool)` matches `Row.Dispose(bool)` line for line, including the double-disposal guard. `DataValue.DisposeNative` sets `ValuesOwned` before disposing the window it builds, which is what makes the new `false` in the `NativeList` constructor safe for a list element of a list and a list column of a row. The new C# fixture's arithmetic was checked case by case against what each container copies; nothing in it restates the implementation or verifies a mock, and no case was cut. The documentation was read in full rather than skimmed: `docs/architecture/value-lifetime.md` and `docs/migration-notes.md` describe the new reality, no other page or ticket reference to this defect is left stale, and every ticket slug named in a `NOTE:` is live on the board.

**Nothing was declined and nothing conditional was left unrecorded.** No accepted-tradeoff `NOTE:` was found at any site the diff touches, so nothing was re-filed over a decision a human had already made.

## Still open, by design

- A stream-backed value written into a table is not given back until the table is dropped - `bug-a-stored-binary-is-never-given-back`, whose numbers this change improves without finishing.
- `TableValue` has no disposal, settled with the `NOTE:` at the class.
- The compiler leaves a loop variable marked borrowed after its loop, and the loop orphans whatever that variable already held - `bug-a-loop-variable-stays-borrowed-after-the-loop`, which depended on this landing and now has both arms.
- `Distinct` does not deduplicate a list of values the engine does not keep inline, and raises over a non-scalar element type - `bug-distinct-leaves-duplicate-pictures-in-a-list`.
- `ToList` over a `Dynamic` (JSON) value now deep-clones each element, because `JToken` is `ICloneable`. Correct by the ownership rule and cheap at JSON sizes, but `ToList(Dynamic)` has no test anywhere in the tree, so that is reasoning rather than a measurement - as the handoff said.
