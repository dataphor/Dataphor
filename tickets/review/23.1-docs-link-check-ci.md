## How to check it

**The command, exactly as the workflow runs it:**

```
python tools/docs-link-check/check_links.py docs --pending tools/docs-convert/legacy-links.tsv
```

Expected: `90 files scanned, 1079 links checked, 0 errors, 203 pending, 12 external`, exit 0. That is what it printed here, matching the measurement the ticket recorded at commit `e414e316`.

**Confirm the step actually fails.** Done and verified: a link to a non-existent page was appended to `docs/architecture.md`, the command reported `docs/architecture.md:78: error: missing file: no-such-page-xyz.md` with `1 errors` and exit 1, and the edit was then reverted. `git status` and `git diff` are clean of it - nothing was left behind, and no test file was committed for this (the ticket says none is owed, and the checker's own 14 unit tests already exist).

**The other things run, for the record** (all green here, none of them changed by this ticket): `python tools/docs-size-check/check_size.py` → `13 files checked, 0 over the limit`; `python -m unittest discover -s tools/docs-link-check` → `Ran 14 tests ... OK`.

**The workflow file parses and has the steps in the right order** - `yaml.safe_load` gives `['Architecture page size', 'Architecture page size checker tests', 'Documentation links']` and both path lists as `['docs/**', 'tools/docs-size-check/**', 'tools/docs-link-check/**', '.github/workflows/docs.yml']`.

No `dotnet build` or `dotnet test` was run: the diff is two workflow files and three Markdown files, with no C#, no project file and no test touched, so there is nothing for the compiler or the test suite to have an opinion about. CI will build anyway on the push - though note that this very change's path filters mean the *Docs* workflow runs for it (it touches `docs/**` and `.github/workflows/docs.yml`) while *Build and test* is skipped for the Markdown-only part.

## What a reviewer should look at hardest

- **The `--pending` argument is a decision with an expiry.** The ticket argued it at length and the reasoning is unchanged: without it the check fails with 203 errors today, so gating everything-but-the-203 beats gating nothing until `docs-convert-legacy-reference` lands. The removal is owned by `docs-remove-old-sources`, which takes this ticket as a `prereq:` and deletes `tools/docs-convert/` including the list. Worth confirming that ticket still says so - if it ever loses the clause, the next CI run after that deletion exits 2 on a missing `--pending` file.
- **Case sensitivity cuts both ways.** This check has never run on Linux. The local run above was on Windows, where the checker's own per-component case comparison is what catches wrong-case links - it passed, so there should be no surprise, but the first real CI run is the first time the file system itself is case-sensitive. If it fails there on letter case, the fix is the link, not the checker.
- **Not added, on purpose:** a `python3 -m unittest discover -s tools/docs-link-check` step. `debt-tool-tests-not-run-by-ci` in `tickets/backlog/` owns getting the Python tools' tests into CI by discovery rather than a hard-coded list, and adding the one step here would pre-empt exactly the shape that ticket exists to avoid.
