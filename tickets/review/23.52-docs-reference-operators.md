## The link checker found 27 errors the conversion report cannot see

This is the correction most worth carrying forward, because `docs-reference-libraries` and `docs-reference-chapters` will meet it again.

The conversion reported **0 unresolved references** and "2037 legacy links, 2037 with a target" on the first full run into `docs`. The link checker then reported **27 errors**. Both are right: `convert.py` only knows whether a *rule or a map row produced a target*, not whether that target names a page that exists. Seventeen legacy page names resolved by the built-in `O-<Name>.html` rule to pages nothing in this chain will ever create. "All with a target" is not a completeness claim, and the acceptance gate has to be the link checker.

The 17 are three kinds, and each got a `reference-links.tsv` row:

- **Misspellings in the 2007 source links**, where the section and so the page is spelled right: `O-System.ConCat`, `O-System.ReguiredLibraries`, `O-System.Diagnostics.GetErrorDecsription`, `O-System.Diagnostics.GetDetailedErrorDecsription`, `O-System.DefaultSetMaxCallDepth` and `O-System.DefaultSetMaxStackDepth` (the last two scramble the word order of `SetDefaultMaxCallDepth`). Retargeted to the real page; the `reason` column names the misspelling in each case. Same treatment the committed table already gave `O-System.SettIsolationLevel`.
- **Names the 2007 reference documents as a scalar type, linked as if they were operators**: `O-System.Guid`, `O-System.TimeSpan`, `O-System.VersionNumber`. Retargeted to `types/`.
- **Things the product dropped**: the group-based security operators `System.CreateGroup`, `System.DropGroup` and `System.GroupExists` (declared in `src/engine/DAE/Schema/SystemCatalog.d4` with `DAE.IsDeprecated = "True"`, and undocumented since 2007), and the pre-3.0 string types `System.String.ASCII`, `System.String.UTF8` and `System.String.Unicode` (no such type in the engine schema at all). Unlinked - the text stays, the link goes.

One more row was added for the one link out of the core library, `O-Frontend.ExecuteScript.html`, unlinked with a reason naming `docs-reference-libraries` - the ticket asked for 12 rows and the tooling review had already corrected that to one page with 12 occurrences; the run confirms 5 occurrences on 5 pages after merging, all unlinked. And **three rows that pointed at `reference/libraries/` pages were emptied** (`DRMSSQLDeviceLibrary-Example`, `DRMSSQLDeviceLibrary-Settings`, `DRSimpleDeviceLibrary-Schema`): they named pages that do not exist yet, which is exactly the error class above. `docs-reference-libraries` fills all four of those rows in and reruns, as its own ticket already says it will.

**Do not delete the 11 rows the report lists as matching no link.** They serve the library and chapter sources that the next two tickets convert.

## The one tooling change, and why it was needed

`legacy/Documentation/DocBookManuals/OperatorDocs/System.iXor.xml` - the only source for `System.iXor` anywhere - has **no `id` attribute on its root `<sect2>`, nor anywhere in the file** (none of the 275 files in that folder has one). The splitter keys its page map on section ids, so there was nothing to address the file with, and an id-less section is reported and left unconverted.

A blanket repair would have been wrong: `SystemOperators.xml`'s own root `<section>` has no id either, and it must stay unconverted - it is the wrapper holding the 339 operator sections. So the mechanism is **opt-in by row**: a page-map row whose `id` names a source file (`System.iXor.xml`) gives that file's root section the file's name as its id, and the split reports it under `root-sections-addressed-by-their-file-name`. No DocBook id in the sources ends in `.xml`, so the two shapes cannot be confused.

Two consequences, both handled: `legacy_name` returns `None` for such a key (there is no help page of that name - the 2004 files were never published), and the `pages-needing-a-legacy-map-row` check skips a page with no help-page name. That check skipping is safe for a structural reason worth checking in review: a file's root section has no enclosing section, so no category can ever cut it out, so no generated navigation list can ever link it. The report still lists the same 3 pages it listed before this change.

## Tests

It pins both halves of the new branch: with the row, the file's root becomes a page with the map's title and the report names it; without the row, the same root is **not** a page, that is not an error, and it is listed as having no id. ## Editorial decisions this ticket owns

The tooling review left four content calls to this ticket. Three changed something; one did not.

- **A merged page's sub-section heading no longer repeats the page title.** Six did (`System.Concat`, `System.iAddition`, `System.iIn` twice, `System.iExtend`, `System.iRemove`, `System.iRename`), so a reader met the same operator name as `#` and again as `##`, and GitHub anchored the second as `…-1`. Each now carries the parenthesised qualifier its seven siblings already carried: `System.Concat (Aggregate)`, `System.iIn (Row)` and so on. `System.iJoin (row)` became `(Row)` for the same consistency. Eight `title` cells in `reference-pages.tsv`; the rerun changed exactly 7 pages and nothing else.
- **`System.IndexOf.md` and `System.LastIndexOf.md` keep a page title of `System.IndexOf (List)` and `System.LastIndexOf (List)`.** This was the call flagged for this ticket, and the answer is to leave it. Those two pages merge two independent overload sections with no general section above them; the lead section *is* the list overload and its *Declarations* block is the list signature, so retitling the heading to the bare operator name would mislabel the content under it. Reordering so a stub leads would put a self-referential "See System.IndexOf" at the top of the page. Both alternatives are worse than a slightly over-specific title. Say so if you disagree - it is one `title` cell.
- **The 16 cross-reference stub sections read as self-references and are kept.** A stub says "See [System.iIndexer](System.iIndexer.md)" from inside `System.iIndexer.md`. That is the source's own text, and the merge is what the links require. Dropping a section would mean inventing an editorial policy that deletes published content; the honest fix is a hand-edit pass after `docs-remove-old-sources` deletes the sources and these become ordinary documents.
- **No code-block table is committed, and this is a judgement to check.** The tooling review recommended seeding `--code-table` and reviewing it. The run tags 858 blocks, 639 `d4` and 219 `text`. A seeded table was produced in scratch and sampled: the `text` blocks are result grids and program output, and the `d4` blocks are D4 statements and calls, with roughly six wrong (three result grids read as D4, a version number, and two lines of mathematical prose inside a listing). **GitHub highlights neither `d4` nor `text`**, so none of the six makes a visible difference, and an 858-row table that nobody has genuinely read is false assurance rather than a check. The decision and its revisit condition are parked as a `NOTE:` in `tools/docs-convert/README.md`: if a `d4` highlighter is ever added to the documentation build, seed the table and review it before trusting the tags.

## The signature sweep: one genuine disagreement, and it predates the port

Operator signatures are a compatibility surface, so the published declarations were compared against the engine's own catalog script (`src/engine/DAE/Schema/SystemCatalog.d4`) rather than eyeballed. Of the 282 operator names that appear in both, **262 have identical parameter lists** once two spellings of the same thing are normalised (the help file printed `generic list`/`row`/`cursor` where the script writes the bare type). Of the rest, 12 are operators where the script declares overloads the 2007 help file never listed (`Abs(Money)`, `Ceiling(Money)`, `Avg(Long)` and so on) and 8 are signatures the help file carries that the script does not declare.

Seven of those 8 are selectors and comparison operators that a scalar type's `representation` generates rather than a script declaring them - their parameter names have no `A` prefix, which is the tell (`Date(const Year, const Month, const Day)`, `UserID(const Value : String)`, `iEqual(UserID, UserID)`).

The eighth is real: **`System.Execute(const AScript : String)` is published but no such overload exists.** The script declares `Execute(AScript, AInParams)`, `Execute(AScript, AInParams, AOutParams)`, `Execute(AProcessID, AScript)` and three more, but not the one-argument form. `git show 361ebd83:Dataphor/DAE/Schema/SystemCatalog.d4` - the 2008 open-source import - already lacks it, and this modernization has not touched that part of the file, so the gap is a 3.x fact, not a port regression. Per the ticket, it is reported, not edited: `docs/reference/system-library/operators/System.Execute.md` still shows what shipped in the published reference. `docs-reference-generator` is the work item that resolves this class by emitting signatures from a running server.

This sweep cannot prove the absence of other disagreements - many operators are registered in C# rather than in the catalog script - so treat it as what it is: a measured spot-check over the 282 names the script also declares.

## Known gaps, honestly

- **Eleven of the twelve operators documented only in `legacy/Documentation/DocBookManuals/OperatorDocs/` are still not converted**, and this ticket decided not to: `System.ConstraintType`, `System.DayOfMonth`, `System.Diagnostics.LoadCatalog`, `System.Diagnostics.SaveCatalog`, `System.RealSQLToD4`, `System.SetLanguage`, `System.String.ASCII`, `System.String.UTF8`, `System.String.Unicode`, `System.iBetween` and `System.iRedefine`. The ticket's own table asked for `System.iXor` only, and the evidence supports it: nothing links to the other eleven from `docs/`, the 2007 edition dropped their sections deliberately, and three of them (`System.String.*`) name types the engine schema no longer has. The mechanism is now proven, so converting any of them is a page-map row and a rerun. Worth revisiting only for one that is current, live, and linked - which is exactly how `System.iXor` qualified.
- **The system tables reference does not exist and this ticket did not invent it.** `docs/reference/system-library/README.md` says so in its own section and names `docs-reference-generator`. No empty `tables.md` was created. The two `SystemTables.xml` sources were read to confirm they are four-line stubs.
- **Twenty `<sup>` elements survive as raw HTML on 14 pages**, from `<superscript>` in exponent prose (`2<sup>96</sup>-1`). GitHub renders them; nothing to do. The report's raw-HTML section lists exactly these and nothing else.
- **Source warts in the converted prose are left alone**, because a hand-edit to a converted page is lost on the next rerun. Two examples seen while reading: `System.iXor.md`'s first sentence is garbled in the 2004 source ("is the parser recognized symbol for this operator is ."), and `System.ActualDate.md`'s example output shows a time under a column named `ActualDate`. These are the class of thing a hand-edit pass can fix once `docs-remove-old-sources` deletes the sources.
- **`docs/reference/README.md` was not touched**, so the new section is reachable only by a direct link today. `docs-convert-legacy-reference` rewrites that index and lists the system library in it; that is its ticket, not this one.
