## What landed

`DataphorServiceHost.Start()` starts a .NET 10 Dataphor server and serves all three of its contracts on CoreWCF, at the addresses and ports the 3.1 server published, from the same instance configuration, through the entry points the console host, the Windows service and `DAE.Client`'s non-embedded in-process alias already call. The four questions the CoreWCF proof left open were answered by the plan ticket and are now implemented; three of the four are also covered by tests, and the fourth was re-measured by hand (below).

## Tests

Twelve cases in `tests/DAE.Server.Tests/CoreWcfProtocolTest.cs`, about 17 s in total. The fixture hosts one instance on free loopback ports through `DataphorServiceHost.Start(ServerConfiguration)`, so nothing reads or writes this machine's `ServerConfigurations.config` (the old out-of-process fixture's worst habit, K18). Two cases start a second host of their own and hand the process-wide object-id counter back afterwards.

| Case | What it verifies |
|---|---|
| `TestNativeCliAnswersOnItsNestedAddress` | **New.** The native CLI client reaches `…/<instance>/service/native`, a path *below* the main endpoint on the same port, starts a session and executes a statement; a main-service call on that port still answers afterwards. This is the address compatibility surface and the nested-dispatch question the proof could not test. |
| `TestNativeCliErrorArrivesAsTheTypedException` | **New.** A statement that fails in the engine, called through the native CLI, arrives as `NativeCLIException` carrying the engine's own error code — not as a communication failure. The one behaviour the `using CoreWCF;` change in `NativeCLIService.cs` exists for. |
| `TestStreamContentCrossesTheWire` | **New.** 64 KB + 7 bytes written through a non-native `Binary` scalar, inserted through an updatable cursor (which flushes the client's deferred-write cache through `EnsureOverflowReleased` → `LocalStreamManager.Release`) and read back byte for byte through a fresh cursor. The row body carries the stream *handle* (`AsPhysical` does not expand streams), so the bytes can only have reached the server through the flush — the proof's unproven path. |
| `TestTheListenerPortBeingTakenDoesNotStopTheServer` | **New.** With another socket holding the listener port, the server starts, its own endpoint answers, and `IsListening` is false. |
| `TestShouldListenFalseHostsNoListener` | **New.** An instance configured not to listen serves its endpoint and nothing is listening on its listener port. |
| `TestListensOnlyOnTheReservedPorts` | Adapted: the ports that started listening while the host was started are exactly the instance port and the listener port — so Kestrel opened no HTTP endpoint of its own — and neither is 8060 or 8061. |
| `TestHostBindingMatchesTheClientBinding` | Adapted: compares `DataphorServiceHostBinding.Build()` with `DataphorServiceUtility.GetBinding()` on element list and order, the four size limits, both timeouts, the transfer mode and the message version. The binding is declared twice against unrelated type hierarchies; this is what stops a one-sided edit. |
| `TestWholeSessionOverTheWire`, `TestLargeMessageInBothDirections`, `TestServerErrorArrivesAsTypedFault`, `TestListenerAnswersOnItsOwnPort`, `TestOneServiceInstanceServesEveryConnection` | Carried over from the proof, now against the real host. |

## Three members beyond what the ticket specified

The ticket named two additions to `DataphorServiceHost` (`HostName`, `Start(ServerConfiguration)`). Three landed instead of two, and the reviewer should weigh both extras:

- **`IsListening`** (read-only). The ticket requires a test that "the host reports the listener as not started"; the only other way to read that is the server's log file, which would mean turning logging on. It is also what a future host needs in order to report discovery status.
- **`LoggingEnabled`** (settable while inactive, default `true` — today's behaviour). `DataphorServiceHost` creates the `Server` itself, so a test cannot reach it before it starts, and `Engine.LoggingEnabled` defaults to true: without this property the new fixture would make an elevated process create and write the Windows event-log source `Dataphor Server`, which the root `AGENTS.md` says the default suite run never does. `TestServerInstance` has exactly the same line for the same reason.

Both are in `docs/migration-notes.md`. If the reviewer would rather not add `LoggingEnabled`, the alternative is a logging setting on `ServerConfiguration`, which changes a BOP-serialized compatibility surface and belongs to `host-instance-configuration`.

## Known gaps and judgement calls

- **Not covered by any test, by design:** the machine-name listen address (measured by hand, above; the fixture uses the loopback literal so no test opens a port another machine can reach), the infinite send and receive timeouts (a test that finishes cannot show them), shutdown with a client channel still open (a timing test), `Start()` or `Stop()` called twice, and a `Start()` failure between the engine server starting and the host starting. The last four are by inspection; `Stop()` is written to tolerate every half-built state and now also captures a failure from either host stop and rethrows it only after the engine server is stopped, so a host that will not stop cannot leave the server running.
- **`DAE.Client` now pulls the hosting assembly in,** and with it `NU1902` and the ASP.NET Core shared-runtime requirement, because `src/client/DAE.Client/ServerConnection.cs` creates a `DataphorServiceHost` for a non-embedded in-process alias. None of those projects is in `Dataphor.slnx`, so the solution build and restore stay clean. `ui-client-layering` owns breaking the dependency; `security-dependency-audit` owns the other way out (transitive package pinning). Both are written up in the plan.
- **The runtime layout's `bin/` now holds two generations of the `Microsoft.AspNetCore.*` assemblies** — the 2.3.10 packages, which `Server.csproj` still copies through `CoreWCF.Primitives` with no framework reference, and the in-box ones the hosting project substitutes. Nothing runs from `bin/` until `host-generic-host` builds the first host there, which is when the choice has to be made. Recorded in the plan's hand-on list.
- **`RequireSecureConnection` and `RequireSecureListenerConnection` are deliberately still unused.** The listener setting is passed to a constructor parameter nobody reads (the parameter's doc comment says so and why); `DataphorServiceHost` still never reads the instance one. `protocol-transport-security` needs the evidence intact.
- **`ServerLink` stays a `known-failure` in `tests/DAE.Server.Tests/coverage-manifest.json`,** untouched. What this ticket changes for it: the native endpoint a server link goes out through is now hosted and reachable. What it still needs is a second hosted instance to link to, which is `test-client-server`'s.
- **The two secondary-host cases depend on an open defect.** Starting a second `Server` in the process resets the process-wide `Schema.Object` object-id counter from its own catalog (`bug-object-id-counter-is-process-wide`), so `WithASecondHost` saves and restores it, as the client wrapper already did. When that defect is fixed, both workarounds should go.
- **`src/hosts/DAEService/app.config` was checked and left alone:** it declares no `<system.serviceModel>` section, so this ticket orphans nothing in it. `host-generic-host` replaces the file (K12).
- **`tickets/.garden-report.md` is modified in the working tree and is not this ticket's change** — a concurrent board edit. Left untouched.
