## Two places where my measurement differs from the implement ticket

Both are the implement ticket's own prose, not the codebase, and both are recorded as measured in what I wrote:

- **The `CA2200` set is nine sites in six files, not eight.** The implement ticket said "eight sites" but then enumerated nine: `Compiler.cs` (3), `Parser.cs` (2), `PlanNode.cs`, `ServerTransaction.cs`, `LibraryUtility.cs`, `LocalServer.cs`. The build reports nine distinct `CA2200` sites. The `NOTE:` I added says nine.
- **The implement ticket's warning tally was log lines, not two configurations.** It gave CA1416 x122, CA2022 x40 and so on, "both configurations, hence the doubling". A single-configuration build produces exactly those numbers as log *lines* and exactly half of each as distinct sites; MSBuild's own summary (143) counts the distinct ones. Nothing is wrong with the figures, only the explanation, so the document got the distinct counts and the 143.

I also looked at all nine `CA2200` sites rather than trusting the characterization, and the implement ticket's claim that "in every case the exception is a `CompilerException` or `SyntaxException`" is too narrow: that holds for the five in `Compiler.cs` and `Parser.cs`, but `PlanNode.cs:687` rethrows a `ControlError`, `ServerTransaction.cs:136` rethrows whatever failed before a rollback, `LibraryUtility.cs:660` whatever `SetLibraryOwner` threw, and `LocalServer.cs:304` whatever it just logged. The *conclusion* survives and is what the `NOTE:` states: in all nine the exception object, its error code and its message are unchanged, so no user-facing error text differs - only the trace below the rethrow point is lost. And `LocalServer` logs before rethrowing, so even there the original trace survives in the log.
