## What was wrong

When a process is joined to an application transaction (AT), each table node in a statement carries a *populate node*: the same expression compiled against the real tables, which runs before the node executes and copies the real rows into the AT's copy of the table. `TableNode.DeterminePotentialDevice` ran device determination on the populate node, but `BaseTableVarNode` and `OnNode` overrode that method without calling base, so for a bare table reference (`select Test;`, `cursor(Test …)`) the populate node's inner `BaseTableVarNode` had no potential device, was flagged `NoDevice`, and threw 104137 ("Device "<no device>" does not support retrieval…") when it ran. A restricted read (`Test where ID = 1`) worked because the outer `RestrictNode` inherits the `TableNode` method. This was a defect in 3.1 as shipped (commit 423f8bc7), not a porting defect.

## What changed

- `TableNode.DeterminePotentialDevice` is now `sealed override`. It calls a new `protected virtual void InternalDeterminePotentialDevice(Plan plan)` (default: `base.DeterminePotentialDevice(plan)`, i.e. `PlanNode`'s child-device logic) and then always runs `_populateNode.DeterminePotentialDevice(plan)`. A short comment above it says why it is sealed.
- `BaseTableVarNode` and `OnNode` (`TableNodes.cs`) override `InternalDeterminePotentialDevice` instead; their bodies are unchanged. Within the repository these were the only table-node overrides (`grep -rln "override void DeterminePotentialDevice" --include=*.cs src libraries samples tests` now lists `DDLNodes.cs`, which is not a table node, and `TableNode.cs`).
- `coverage-manifest.json`: `ApplicationTransactions` stays `known-failure`, re-pointed to `engine-at-leave-rolls-back-open-work` with error `Application Transaction read is not repeatable` (the script now gets past line 20 and fails at line 41 on that separate cause).
- `docs/migration-notes.md`: a `done` row under "D4, catalog and libraries" (bare-name reads inside a joined AT no longer raise 104137), and a `done` row under "Custom C# extensions" (the method is sealed; a custom `TableNode` subclass renames its override to `InternalDeterminePotentialDevice` and its `base.` call to `base.InternalDeterminePotentialDevice`).

Both edited `.cs` files keep CRLF and no byte-order mark (the fix ticket said `TableNodes.cs` had one; it does not, and still does not).

## For the reviewer

- Sealing is a compatibility surface for custom C# extensions only (a `TableNode` subclass outside the repository that overrides `DeterminePotentialDevice` no longer compiles); that is what the migration note covers. The alternative the fix ticket allowed (one-line fix in both overrides plus a `NOTE:`) was not taken.
- A subclass that keeps calling `base.DeterminePotentialDevice(plan)` from inside its new `InternalDeterminePotentialDevice` override would recurse forever (the sealed method calls the virtual one); the migration note tells extension authors to switch to `base.InternalDeterminePotentialDevice`. Nothing in the repository does this.
- `TableNode.BindingTraversal` pushes the global context around its populate-node pass; `DeterminePotentialDevice` never did, and still does not. Not changed here; the bare `select Test` case and the whole AT script past line 20 work without it.
- The bare `select Test;` form from the fix ticket's snippet is not exercised by a coverage script on its own; the cursor form at line 20 of `ApplicationTransactions` goes through the same code path.
