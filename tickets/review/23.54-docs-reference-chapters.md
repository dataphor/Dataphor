## Findings - things noticed and deliberately not changed

- **Source typos are preserved, as the project rules require.** In `realsql.md`: "separataed", "langauge", and `<expression> ::= <binary expression> <between clause>` where the between clause is in fact optional. In `d4-programming-topics.md`: an unterminated quote in the `System.String` definition (`} class "System.SystemStringUTF8Node,` - the source has it at `ProgrammingTopics.xml:43`), "ommitted", "Repeates", a `DateTime` selector example passing seven arguments to a six-property representation, and the prose saying the `DateTime` representation "has seven properties" above a list of six.
- **Two class names in the published `System.String` definition lack the `Node` suffix the engine uses.** The chapter writes `read class "System.ScalarReadAccessor"` and `write class "System.ScalarWriteAccessor"`; `src/engine/DAE/Schema/DataTypes.d4` writes `System.ScalarReadAccessorNode` and `System.ScalarWriteAccessorNode`. Every other class name in the block matches. Not corrected, because the page is a converted document that a rerun rewrites; a reviewer who wants it right should say so and it becomes a converter or source question, not a hand edit.
- **`realsql.md` names four D4 Language Guide sections in prose without linking them** - *Data Management Differences*, *Syntactic Conventions*, *Lexical Elements* and *Table Expressions*. `RealSQLLanguageGuide.xml` contains no link markup at all (`grep -cE 'url=|linkend=' ` on it is zero): its cross-references were typeset as plain text. A hand-added link would be lost on the next rerun. Recorded as a `NOTE:` in `tools/docs-convert/README.md`.
- **`pages-needing-a-legacy-map-row` now reports eight entries, two of them new** (`developers-guide/realsql.md` and `developers-guide/d4-programming-topics.md`). Neither needs a row, for the same reason the README already records for `reference/libraries/ODBCConnection.md` and `Security.md`: the check asks whether the built-in rule sends the page's primary section's help-page name to that page, and it matters only for pages a generated navigation list links by name. Adding rows would move the noise to *rows that matched no link*. The README NOTE was extended to say so.
- **One statement on the RealSQL page is contradicted by the parser.** Its *Operator Invocation* section says "operators which take variable arguments may not be invoked, because RealSQL has no imperative mechanism for declaring a variable". `ActualParameter` in `src/engine/DAE/Language.RealSQL/RealSQLParser.cs:1023` reads an optional `var` keyword and builds `new ParameterExpression(Modifier.Var, …)`, and `var` is in `RealSQLKeywords.cs`. Not edited, for the reason `bug-reference-prose-names-unshipped-devices` already gives at length - a hand edit to a generated page is thrown away by the next rerun - so it is **filed as an arm on that ticket**, which is the sweep that runs after `docs-remove-old-sources` deletes the tooling. Whoever takes it has to decide which side is wrong; if the sentence describes an intent the parser never enforced, the engine is the thing to question.
- **The page's grammar is a simplified one, and does not say so.** Its `<binary expression>`/`<arithmetic expression>` productions stand in for the nine precedence levels the parser implements. Same arm.
- **Nothing links into the RealSQL page from a converted source.** The two `DDGP1RealSQLLanguage.html` references in the corpus are both in `legacy/Documentation/DocBookManuals/`, which is not a conversion source; so are the ones for `RealSQLLanguageRef.html` and `SLRSystem.RealSQL.ToD4.html`. `D4LGProgrammingTopics-UsingGenerators.html` (one reference, in `SystemOperators.xml`) stays unlinked: there is no *Using Generators* section anywhere under `docs/`, and that section lives in `D4LanguageGuide.xml`, not in the chapter converted here.

## Bugs fixed along the way

**`docs/users-guide/tutorials.md`: the last three rows of the *EDITING* shortcut table were nonsense, and are now right.** They read:

```
| Undo | Ctrl+Z or Alt+BkSp | Delete |
| Undoes the last keystroke. | Redo | Ctrl+Y |
| Delete | Repeates the last keystroke. | Split Window |
```

The cause is in both legacy sources, not in the conversion: the *Undo* and *Redo* rows each carry a spurious fourth cell in a three-column table (`<entry colname="col02"><keycap>Delete</keycap></entry>` repeated after the real shortcut cell - `Keys.xml:144-156`, and `|Undo |Ctrl+Z or Alt+BkSp |Delete |Undoes the last keystroke.` at `Documentation/UsersGuide/Tutorials.adoc:80`). AsciiDoc tables fill rows from a stream of cells, so two extra cells shifted everything after them by two and pushed the *Split Window* shortcut and description off the end of the table, where they were dropped.

The published page was fixed, not the sources - they are the record of what was published, and the same defect is in both of them, so nothing is lost when they go. **This is a hand edit to a page the AsciiDoc conversion generates**, so an `--out docs` rerun of *that* conversion would overwrite it; the same is true of the index block added to `docs/developers-guide/README.md`. Both are recorded in a `NOTE:` in `tools/docs-convert/README.md`. Neither path is written by the two commands this ticket documents, which is why the reproduction run below leaves them alone.
