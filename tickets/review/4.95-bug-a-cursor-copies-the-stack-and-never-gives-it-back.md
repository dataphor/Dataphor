## What was wrong, in one paragraph

Opening a cursor takes a private copy of the whole current stack window (`Cursor.SnapshotContext`) and swaps that copy in as the program's stack around every cursor operation, so that the cursor's plan can still read the variables it was compiled against after the scope that opened it has gone. The copy has to be a copy - a cursor outlives its scope, and the scope releases its own variables on the way out - but `Cursor.Dispose` threw the copy away without releasing it: it set `_context = null` and nothing else. A copy of a `Binary` or a `Graphic`, or of a row or list holding one, is a new managed stream that something has to release, so every cursor a script opened held one stream for the life of the session per stream-backed variable then in scope. Every cursor paid it, the implicit one a `foreach` over a table opens as much as an explicit `cursor(...)`.

Releasing the copy is only half the fix, and the second half is what makes the first safe. The releases run through the process's own value and stream managers, but the cursors live in a `CursorManager` on the **session**, which the session disposes *after* its processes (`ServerSession.Dispose` drains `_processes` in an inner `finally` and disposes `_cursorManager` in the one outside it) - and `ServerProcess.InternalDispose` ends by nulling `_serverSession`, `_valueManager` and `_streamManager`. So a cursor the script never closed used to be disposed with its process already torn down, and releasing its copy there dereferenced the nulled session. That is measured, not reasoned: with the release alone, a script that opens a cursor and never closes it turns the fixture's teardown into a `NullReferenceException` out of `Engine.Disconnect` (`src/engine/DAE/Server/Engine.cs:901`).

## What changed

**`src/engine/DAE/Runtime.Data/CursorValue.cs`** - three things.

- `SnapshotContext` keeps `program.ValueManager` in a new `private IValueManager _contextValueManager` beside `_context`, and `Dispose` releases the snapshot through it with `_context.ReleaseAbove(0, _contextValueManager)` before nulling `_context`. Capturing the manager is what makes the release independent of the existing dispose order: `_table` is already disposed by the time control reaches that `finally`, so `_table.Program` is not reachable for it. `ReleaseAbove` rather than a loop, because it nulls each slot before disposing its value, so a dispose that throws cannot leave a disposed value reachable and a second pass releases nothing.
- `SnapshotContext` is now `private` (it was `public`). Nothing outside the constructor called it, and a second call would orphan the first snapshot outright, so narrowing it makes that unrepresentable. This is a public member of a public type and has a migration-notes line.
- `CursorManager` gains `public void CloseProcessCursors(ServerProcess process)`, which walks `_cursors` backwards (because `Cursors` is a `DisposableList` that disowns a member that disposes itself) and disposes each cursor whose `Table.Program.ServerProcess` is that process.

**`src/engine/DAE/Server/ServerSession.cs`** - a new `internal void CloseProcessCursors(ServerProcess)` that forwards to `_cursorManager` *only if there is one*. Deliberately not through the `CursorManager` property, which creates a manager when there is none: a process being disposed must not create one.

**`src/engine/DAE/Server/ServerProcess.cs`** - `InternalDispose` calls it, in the same `finally` that disposes each plan's `ActiveCursor`. That runs after the transaction rollback and before `CloseDeviceSessions`, so the cursor's table is closed against device sessions that are still open, and the process's own managers are still alive for the release. Guarded on `_serverSession != null`.

**`src/engine/DAE/Runtime/Program.cs`** - no behaviour change; the long `NOTE:` above `Program.Stop` named this defect and `bug-ifnil-leaks-the-value-it-copies` as the two leaks blocking a DEBUG-only stream-count check. Both have landed, so the note was rewritten: the one remaining blocker is `bug-row-equality-leaks-the-rows-it-compares` (open in `fix/`), and the three that are fixed are listed as fixed. Left stale it would have read as this defect still being open.

## Tripwire parked

`CursorManager.Dispose` is still the session-end fallback, and it releases each cursor's snapshot through the manager that cursor captured - which is only safe while every cursor reaching it belongs to a live process. `CloseProcessCursors` is what keeps that true. A `NOTE:` at `CursorManager.Dispose` says so, and names the symptom (a null dereference inside the release at disconnect) that a future path disposing a process without reaching `InternalDispose` would bring back.

## For the reviewer

- **The one judgement call worth a second opinion** is *where* arm two's call sits. It is in the `finally` that disposes each plan's `ActiveCursor` - after the rollback, before `CloseDeviceSessions` - and the argument for that spot is that the cursor's `_table.Dispose()` wants open device sessions while the release wants live managers, and only that window has both. The alternatives considered and rejected: reordering `ServerSession.Dispose` to dispose the cursor manager before the processes, which does not help because a process is usually stopped before its session is disconnected and is already gone by then; and releasing through a longer-lived manager, which does not exist, because a `Row` or `ListValue` in the snapshot carries the process's own manager inside itself.
- **`AssignmentValueOwnershipTest.cs` is now 1,378 lines** against the roughly-1,500 threshold its own `NOTE:` sets for splitting. Two sibling ownership tickets still have cases in flight against it (`bug-a-var-parameter-written-in-the-body-can-release-a-callers-loop-value` and `bug-row-equality-leaks-the-rows-it-compares`, both in `fix/`), which is what that `NOTE:` defers the split for; the next ticket to add to the file may well be the one that has to do it. The new case went in at the very end, after `AnAggregateLeftByARaiseReleasesTheResultItAssigned`, which is where a merge conflict would land.
- **The tests cover `Binary` only, not `Graphic`.** Same code path through the value manager, and the whole fixture is `Binary` for the same reason, but it is a gap rather than a decision.
- **Not covered: a cursor held across a process boundary in the same session.** `CloseProcessCursors` filters on `Table.Program.ServerProcess`, so a cursor opened by process A is left alone when process B is disposed. That is checked by reading (`TableValue._program` is set in the constructor and never nulled, so the filter is stable for the life of the cursor) rather than by a test, because the fixture is one process per test.
- **The `SnapshotContext` visibility arm is the one piece a reviewer might reasonably undo.** It is a compatibility surface - a `public` member of a `public` type whose constructor is `protected internal`, so an external subclass is possible in principle - traded for making a double snapshot unrepresentable. `protected` is the middle option the ticket named; leaving it `public` with a `NOTE:` is the third.
- **Source hygiene held**: `CursorValue.cs` still tabs, CRLF, no byte-order mark and no trailing newline; the three other `.cs` files still tabs, CRLF, UTF-8 byte-order mark; both docs still CRLF, no byte-order mark. `git diff --check` reports the CR of every added line as trailing whitespace, which is what it does for every commit in this repo (25 such reports in `3593336a`), not something introduced here.
