## What landed

`src/engine/DAE/REST/RESTResult.cs` and `src/engine/Server/REST/RESTMarshal.cs` are deleted, along with their `Compile` entries in `DAE.csproj` and `Server.csproj`. Both `REST` folders are gone from the index and from disk — `find src/engine -type d -name REST` returns nothing.

`Server.csproj` no longer carries `<PackageReference Include="Newtonsoft.Json" />`, and the sentence `Newtonsoft.Json: REST\RESTMarshal.cs.` is removed from the comment above the package group. The rest of that comment — the CoreWCF/`System.ServiceModel` pairing, the SQL Server client and its measured closure, the ASP.NET Core framework reference — is untouched. One side effect worth a reviewer's eye: that sentence was the start of a wrapped line, so the line it was on is now short (`Microsoft.Data.SqlClient: Connection\MSSQL*.cs, and Server\Server.cs, which`) and the paragraph reads slightly ragged. I deliberately did not rewrap the surrounding lines, because that would have touched comment text this ticket has no business changing; if a reviewer prefers an even paragraph, joining that line with the next is the whole fix.

`Newtonsoft.Json` stays in `Directory.Packages.props`, unchanged. The excluded entry for the two REST paths is dropped from `tools/coverage-report/areas.json`; the other two excluded entries (generated source under `artifacts/`, and the three dead compiled files owned by `hygiene-remove-dead-compiled-files`) are untouched, including that second entry's stale `"ticket": "debt-ws12-hygiene-remainder"` — repointing it belongs to the ticket that removes those files, not this one.

Documentation:

- `docs/coverage-report.md`: the REST row in *Excluded from the area rollup* now says the removal landed under `hygiene-remove-rest-leftovers` and that the exclusion is gone from the map, so a later instrumented run will neither count those lines nor print the row. **The ticket expected two places to repoint and there was only one.** The *What this pass found* section never mentioned the REST paths — its dead-code paragraph is about `IndexList`, `TemporaryStream` and `CopyOnWriteStream`, and the `GenericDotNetConnection` sentence below it names the umbrella for a file this ticket does not touch. Both of those stay with `hygiene-remove-dead-compiled-files`. Verified by grepping the file for `REST`: line 207 was the only hit.
- `docs/architecture/what-is-alive.md`: a clause added to the *Removed by the port* row naming both types as deleted with no replacement. `python tools/docs-size-check/check_size.py` reports 13 files checked, 0 over the limit.
- `docs/migration-notes.md`: a new `done` row at the end of *Custom C# extensions* giving both full type names and their assemblies, saying nothing in the product replaces them and nothing an application or deployment script can see changes, and telling an extension that marshalled engine results to JSON to use its own code and its own package reference. **One edit beyond the ticket's list:** the existing Newtonsoft.Json-13 row claimed the package is referenced by "the native client interface, the server and the System.Internet library", which this change makes false. I corrected the parenthetical rather than leave a note that misstates which assemblies carry the reference. That is the only unticketed change in the diff.
- `docs/modernization-plan.md`: the WS12 `hygiene-remove-rest-leftovers` row is marked **Done** with what landed.

## Tests

**No test added.** Nothing called either type, so no behaviour changes and there is nothing to characterize — the build is the evidence that the deletion is invisible to the product, and the JSON library's continued presence is already pinned by existing tests (below). The project's "a ticket that changes a subsystem's behaviour owes a characterization test" rule does not bite on a removal of code with no callers.
