## What was wrong, in one paragraph

`IfNil(AValue, AReplacement)` returns its first argument unless that argument is nil, in which case it returns the second. It returned a *copy* of whichever argument it chose and never released the original. Where that original was a value the call owned - anything computed for the call rather than read out of a variable: a selector, a conversion, another call - nothing else named it and it was orphaned. For a `Binary` or a `Graphic`, the two types the engine keeps in a managed stream, that is one stream held for the life of the session per call.

The rule the engine already has for this - whether a call owns the value handed to a `const` operand is a property of the plan node that produced the argument, not of the modifier - lives in `InstructionNodeBase.CleanupOperand`. `IfNilNode` never reached it, because it overrides `InternalExecute(Program)` itself. The fix applies the same rule at the site by hand.

## What changed

**`src/engine/DAE/Runtime.Instructions/SystemNodes.cs`, `IfNilNode.InternalExecute`** - keep the node whose value was chosen, copy the value, and release the original where that node answers `ReturnsByReference` false:

```csharp
PlanNode chosen = Nodes[0];
object result = chosen.Execute(program);
if (result == null)
{
    chosen = Nodes[1];
    result = chosen.Execute(program);
}
object copy = DataValue.CopyValue(program.ValueManager, result);
if (!chosen.ReturnsByReference)
    DataValue.DisposeValue(program.ValueManager, result);
return copy;
```

Commented with the three load-bearing points the ticket named: copy before release (the other order leaves the copy reading a stream the manager has forgotten, which reports as `StreamID (n) not found`); the node read is the one left in `Nodes[index]` at run time rather than the one `base.DetermineDataType` asked, because `DetermineDataType` may replace either with a conversion; and `CopyValue`/`DisposeValue` both fall through for a null, so `IfNil(nil, nil)` needs no special case. The `NOTE:` tripwire for the rejected alternative - returning a lent value as it stands - is at the same site, stating why it is not done (it would make this node's own ownership per-execution where `ReturnsByReference` is settled at compile time) and the revisit condition.

The node's allocation count is unchanged from before the fix, and what the caller receives is unchanged.

**`tests/DAE.Server.Tests/AssignmentValueOwnershipTest.cs`** - two cases plus a sentence in the class `<summary>`. See *Tests* below.

**`docs/architecture/operand-ownership.md`** - a paragraph recording that a node overriding `InternalExecute(Program)` directly is never reached by `CleanupOperand` and owes the operand rule itself, naming the four nodes of that shape (`ExistsNode`, `TableToListNode`, `TableNode`, `IfNilNode`). 866 words of the 1,500 limit; `python tools/docs-size-check/check_size.py` reports 13 files checked, 0 over.

**`docs/migration-notes.md`** - one entry at the end of *Custom C# extensions*, beside the three sibling ownership entries. Nothing changes for a D4 script; a custom C# node that passes a value to `IfNil` and reads that same value afterwards must copy it first.

## Tests

| Test | What it verifies |
|---|---|
| `IfNilReleasesTheValueComputedForIt` | The release, in both shapes that leaked - a computed first argument (`IfNil(Binary('0001'), Binary('0002'))`) and a nil first argument with a computed replacement - each over `AssignmentCount` calls, asserting the stream count balances *and* that the result is readable each iteration. |
| `IfNilGivenAVariableLeavesTheCallersValueAlone` | The loan, which the wrong fix breaks: a variable as the chosen argument, asserting the count balances and the caller's variable is still readable afterwards. Passed before the fix as well. |

Both were checked against a deliberately broken engine, which is the part worth re-reading if you want to trust them:

- Guard forced to never release (`if (false)`): `IfNilReleasesTheValueComputedForIt` fails on both shapes ("the script left streams behind"), `IfNilGivenAVariableLeavesTheCallersValueAlone` passes. That is the pre-fix behaviour.
- Guard forced to always release (`if (true)`): `IfNilGivenAVariableLeavesTheCallersValueAlone` fails, `IfNilReleasesTheValueComputedForIt` passes. That is the rejected fix.

So each case fails for exactly one of the two ways to get this wrong, and the guard was restored afterwards (`src/engine/DAE/Runtime.Instructions/SystemNodes.cs:968`).

No generalised test was added, and the ticket's reasoning for that was re-checked rather than taken on trust: only four types bypass `CleanupOperand` by overriding `InternalExecute(Program)`, and the other three were read and each disposes what it opens. The class is closed, so the fact that overriding the execution opts a node out of the rule went into the architecture page instead of a test.

## For the reviewer

- **The one judgement call worth a second opinion** is which node's `ReturnsByReference` is read. The code reads it off whatever is in `Nodes[0]`/`Nodes[1]` at run time, which is after `IfNilNode.DetermineDataType` has possibly replaced either with `Compiler.ConvertNode`'s wrapper. The argument that this is correct is in the comment at the site, and it rests on a conversion node answering `ReturnsByReference` false and its own `const` cleanup leaving the lent value alone. `Compiler.Upcast` is a no-op today (`USETYPEINHERITANCE` off, `src/engine/DAE/Compiling/Compiler.cs:12044`), so the conversion path is the only one that actually rewrites a node - and no test exercises it, because no conversion between two stream-backed types exists to reach it. A reviewer who can construct one would be adding real coverage.
- **The tests do not cover `Graphic`**, only `Binary`. Both are the same code path through the value manager, and the fixture's existing cases are all `Binary` for the same reason, but it is a gap rather than a decision.
- **Three sibling tickets also add cases to `AssignmentValueOwnershipTest.cs`** (`bug-a-cursor-copies-the-stack-and-never-gives-it-back`, `bug-a-var-parameter-written-in-the-body-can-release-a-callers-loop-value`, `bug-a-loop-over-a-read-only-parameter-orphans-a-computed-argument`).
