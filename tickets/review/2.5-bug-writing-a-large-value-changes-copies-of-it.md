## What changed

The engine keeps values too large to carry inline - the D4 types `Binary` and `Graphic` - in a stream owned by the server, and copying such a value does not copy its bytes: the copy is a *reference* to the original's stream, and the two are meant to be given contents of their own the first time either is written. That separation only ran in one direction. `ServerStreamManager.Change` handled the case where the stream being written is itself a reference (write through the copy - correct), and did nothing when the stream being written is a *source* that has references outstanding, so the write landed in the provider's stream every copy was still reading through.

`Change` now has a second branch, `else if (header.References.Count > 0)`, which walks the source's outstanding references and gives each one a provider stream of its own holding the source's current contents, before the write lands. Two parts of it are not obvious and are commented at the site:

- **The position restore is load-bearing.** The copy reads the source to the end through a `CoverStream` over its `ServerStream`, and a cover sets its source's position before every read, so the stream the caller is about to write through comes out of the copy positioned at its end - the write would append past the old value instead of landing over it. `Change` saves the position before the loop and restores it after. Without it, `WritingASourceThatHasReferencesLeavesItReadingItsOwnNewValue` and the source arm of the three-value case fail with the source reading back its *old* value.
- **A reference that is not open is skipped, not crashed on.** The branch above it can assign `header.Stream.SourceStream` unconditionally because the stream being written is by definition open; a separated reference need not be, hence the `if (referenceHeader.Stream != null)` guard. Such a reference is already out of `_referencingHeaders` by then, so its next `InternalOpen` takes the non-referencing arm and opens the provider entry the loop created for it.

The re-parenting alternative (hand the provider entry to the references and give the source a fresh one, the way `Deallocate` does mid-chain) was rejected in the fix stage as the larger change on the more delicate path; the cost difference is recorded as a tripwire rather than paid now.

## How to validate

The behaviour is reachable from ordinary D4, in every shape a value gets copied:

```
var LA : Binary := Binary('ABEiM0RVZnc=');   // eight bytes
var LB : Binary := LA;                        // copy at declaration
LA.Value := 'qrvM3Q==';                       // four other bytes, written through the original
// LA.Value must now read back 'qrvM3Q==' and LB.Value must still read back 'ABEiM0RVZnc='
```

The same holds for a copy taken by a later assignment (`var LB : Binary; LB := LA;`) and into a row column (`var LR : row { B : Binary } := row { LA B };`), and for `Graphic` in place of `Binary`. All three shapes reach `ServerStreamManager.Reference` through `DataValue.CopyNative` (`src/engine/DAE/Runtime.Data/DataValue.cs:542`) and `DataValue.CopyValue` (`:657`), and the write reaches `Change` through the `Scalar.AsByteArray` setter, so one site governs all of them.

## Known gaps, honestly

- **The copy shapes other than declaration are not covered by an automated test.** The fix stage confirmed all three (declaration, later assignment, row column) reproduce before and pass after, with a throwaway fixture that is not in the tree; this stage re-verified only the declaration shape, through the new case, and the single-site argument above for the rest. A reviewer who wants the other two can extend the new case's script - the ticket's reasoning was explicitly that one case suffices, so adding a case per shape would be re-litigating that, not closing a gap.
- **The open-count bookkeeping is still off, by design-for-now.** Repointing a reference's `SourceStream` drops the cover stream it held over the source without closing it and without the matching `InternalClose`, so the source header's open count stays one high per reference separated. This is exactly what the branch above it already does and what the two `// TODO: Shouldn't this close the old stream?` comments in `MoveReferences` and `Deallocate` are about. It is inert today - `MemoryStreamProvider.Close` is a no-op and `Deallocate` removes a header whatever its count, which is why the fixture's `Count()` assertions still read zero - and becomes real only if the file-backed provider is switched on. Recorded as a tripwire, not fixed here.
- **Nothing was measured.** The cost claims below are counts of copies read off the code, not timings.
- **Concurrency is unexamined.** Every public method of `ServerStreamManager` is `lock (this)` and the new branch runs inside that lock; the one re-entrant call it makes (`stream.Position` can call back into `Change`, which is then a no-op) is safe on the same thread. Nothing here says anything about contention.

## Tripwires recorded

Both are `NOTE:` comments in the new branch of `ServerStreamManager.Change` - no tickets:

- The cost: one copy of the value per outstanding reference on the first write to a source, where the re-parenting shape would cost one copy however many there are; and because a representation write truncates before it writes (`SetLength` then `Write`, each calling `Change`), the separating copy happens on the `SetLength` and copies contents the write then replaces in full. `Change` is idempotent, so the second call is a dictionary lookup. If copying a large value many times before writing the original ever shows up as slow, the re-parenting shape and a check for a `SetLength` to zero are the two things to reach for.
- The bookkeeping leak described under known gaps, with `UseFileStreamProvider` named as the condition that makes it real.

## Compatibility

No D4 syntax, operator signature, registered class name, file format, error code, contract shape, port or on-disk layout changes. The visible behaviour change - a copy of a `Binary` or `Graphic` now keeps the value it was taken from when the original is written, where before it followed the original - is a row added to the `## D4, catalog and libraries` section of `docs/migration-notes.md`, status `done`, with "nothing to do unless an application relied on the old behaviour to see a write through a copy taken earlier".
