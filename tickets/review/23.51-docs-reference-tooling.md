## What landed

The tooling and tables the four remaining tickets of the legacy-reference chain read. **No page under `docs/` was published**; the only `docs/` change is the plan's new WS8 design notes. The link checker still reports 0 errors, 203 pending, 12 external, which is what CI expects.

- **`tools/docs-convert/reference_split.py`** (new, 733 lines) with two modes. `declarations` reads the decompiled help file's `O-*.html` and `T-*.html` pages and writes the signature table. `split` reads the reference DocBook, fills in or removes the generated-content placeholders, groups sections onto pages, and writes one DocBook document per page plus the `pages.tsv` that `convert.py docbook --pages` reads; `--seed-pages` writes a seeded page map instead.
- **`tools/docs-convert/convert.py`**: `--legacy-map TSV`, consulted in `Resolver.legacy()` before the built-in rules; a hit supplies the target (which may carry a `#fragment`), an empty target unlinks and keeps the text, a miss falls through. The legacy-page gate is now `\.html?$` matched case-insensitively. Two new report sections list rows that matched nothing and rows that override a built-in rule.
- **`tools/docs-convert/declarations.tsv`** — 360 rows, read from 411 help pages. Every row is a D4 `create operator` or `create aggregate` statement; no other content, no non-ASCII byte (checked before committing, as the ticket asked).
- **`tools/docs-convert/reference-pages.tsv`** — 360 rows covering every section of `SystemOperators.xml` and `SystemTypes.xml`, with the 13 merges applied.
- **`tools/docs-convert/reference-links.tsv`** — 115 rows: 87 with a verified heading anchor, 15 naming a whole page, 8 deliberately empty, and 5 retargeting reference pages the built-in rule would place wrongly.
- **`tools/docs-convert/README.md`** gains a *The legacy reference: reference_split.py* section (both modes, every rule, the decompile-to-scratch warning), three rows in *Inputs and tables*, the `--legacy-map` option row, and the extended legacy-link rules.

## Tests added, and what each verifies

`tools/docs-convert/test_reference_split.py` (new, 8 cases):

- *several sections become one document in row order* — the `<article>` root, its id and title from the page's first row, the second section kept as a body section with the map's title. The merge mechanism, which is the whole reason this script exists.
- *declaration is substituted and a missing one drops its block* — a `D4Field Declaration` with a row becomes the signature script; one without a row removes its whole `formalpara`, heading included, and is reported.
- *a generated table is removed with its heading* — the prune rule for a table whose only row was a placeholder and whose column headings are hand-written. The one branch where "empty" is not the same as "no text".
- *a category page lists the pages cut out of it* — the generated navigation, one link per page (not per section) and by the help-page name the built-in rule resolves.
- *urls are normalised* — whitespace stripped, a missing `.html` suffix restored.
- *a section id with no row is an error* — and nothing is written.
- *a surviving placeholder is an error* — the guard that nothing in the split can leave one behind; a placeholder rendered as literal text would read as published documentation.
- *escaping round-trips a multi-line value* — plus tabs, backslashes, CRLF and a trailing backslash. This is the one thing that can silently corrupt a signature.
- two further cases pin `declaration_of` against the help file's markup: the block is every `<pre>` from the *Declarations* marker to the next heading (and not the *Type Declaration* block above it, nor the listing after the next heading), and a page with no such block yields none.
- *a seeded row keeps the source spelling of its page* — `page_name`'s kebab-case rule is not used; `System.Abs` stays `System.Abs`.

`tools/docs-convert/test_convert.py` (4 cases added): a `--legacy-map` hit with a fragment (only the path is made relative), a hit on an uppercase `.HTML` name, an empty target unlinking and keeping the text, and a miss falling through to `LEGACY_RULES`.

No test asserts a page count or that a particular page exists.

## Deviations from the ticket, each with its reason

Please check these first; they are the judgement calls.

- **Page-map outputs are docs-root-relative** (`reference/system-library/operators/System.Abs.md`), where the ticket's seed rule said `operators/<Name>.md`. `Resolver.legacy()` makes a legacy target relative to the current page's own output, and the built-in rule's targets are docs-root-relative, so the page map and the rule must share a root or every cross-page link comes out wrong. With this choice the seeded map agrees with the rule by construction, and all 203 pending targets under `docs/` name a real page except the two the ticket predicted (`System.SecurityOperartors.md`, a misspelling, and `System.iXor.md`). The already-written `docs-reference-operators` ticket assumes exactly these paths (`docs/reference/system-library/operators/<Name>.md` with `--out docs`), so this is the form the chain was going to need anyway.
- **`reference-pages.tsv` has a fourth column, `reason`**, seeded empty and ignored by the script. `docs-reference-operators` says the table "records with a reason" that `SystemLibraryReference.xml` is not converted, so the column had to exist or that ticket would have met the wrong schema. It is filled in here for the 20 merges, the one rename, the four corrected titles and the one index section.
- **An empty `output` means "not a page of its own"**, not simply "dropped": such a section is rendered inside the page of its nearest enclosing section that is one. A top-level section with an empty output is still not converted, as the ticket said, and is listed. The wider rule is what lets `docs-reference-libraries` put a library chapter's Definition, Settings and Example sections on one page.
- **Section order within a page is the page map's row order**, not document order. A seeded table is in document order, so the default is exactly what the ticket described; the extra freedom is what lets a merged page lead with the section that carries the signatures instead of with a one-line cross-reference stub.
- **`reference-pages.tsv` has a third column, `title`**, which sets the section's heading and (on a page's first row) the page title. It is seeded with the source title, so it changes nothing by default. It earns its place twice: four sections title themselves `iIndexerSystem.iIndexer (List)` and so on - the operator name is duplicated ahead of itself in the source - and merging needs the headings to tell the sections apart.
- **The legacy-page gate is `\.html?$` case-insensitive**, where the ticket asked only for case-insensitivity. The extra `.htm` covers `DDGP2BasicConnectivity.htm`, a typo in `SQLDeviceSettings.xml` for a page the help file has as `.html`. Measured safe for the already-landed AsciiDoc conversion: `Documentation/` has 208 `.html` references and no `.htm` or `.HTML` ones, and a full AsciiDoc rerun produced a `legacy-links.tsv` identical to the committed one (compared after newline normalisation; the file was then restored byte for byte).
- **`reference-links.tsv` has 115 rows, not the ticket's estimated 116.** The count fell out of the actual sources.
- **Category link lists use the help-page name the built-in rule sends to that page**, so only 3 pages need a `--legacy-map` row rather than 21. The split reports those 3 by name under *pages-needing-a-legacy-map-row*; 5 rows are in the table (3 for navigation, plus `O-System.StringIndexOf.html` and `O-System.StringLastIndexOf.html`, which the sources link directly).
- **`O-System.SettIsolationLevel` is given the page `System.SetIsolationLevel.md`.** The section id misspells the operator; nothing links to that help page, so the rename is free, and the split reports the override.

## Known gaps, for the tickets that publish the pages

None of these is a defect in this ticket's tooling; they are what the sample run shows about the content, measured over all 341 pages of the scratch conversion.

- **1035 raw `<span class="code" role="code">` on 280 of the 341 pages**, from the sources' 1038 `<phrase role="code">`. GitHub renders them, but inline code is what was meant. The fix is one rule in `convert.py`'s `transform_blocks` - unwrap a `Span` with class `code` into a `Code` inline - and it is reference-only in effect: `Documentation/` has no `role="code"` and no page under `docs/` carries such a span today. Left out because this ticket's remit was one change to `convert.py`; it belongs with the ticket that reviews the operator pages.
- **`Remarks`, `Example` and `See Also` are `<bridgehead>`**, which pandoc renders as bold paragraphs rather than headings. That is why every page has exactly one `#` heading, as the ticket wanted, but those sections get no anchors. Whether to promote them to `##` is an editorial call for `docs-reference-operators`.
- **The 16 cross-reference stub sections read as self-references once merged** - `## System.iIn (Row)` followed by "See System.iIn" on the `System.iIn` page itself. The ticket's decision was to merge all sections of one name and no content is dropped, so they are all there to be edited.
- **`System.IndexOf.md` and `System.LastIndexOf.md` take their page title from a `(List)` variant**: neither has a section whose own title is the bare operator name.
- **Two index sections are not converted** and are listed: the untitled-id `Operators` root of `SystemOperators.xml` and `DRSystemLibrary-ScalarTypes`. Each is a title plus one sentence ("The following sections describe ..."). `docs-reference-operators` may want an index page for them.
- **A section's signatures become one fenced `d4` block** where the help file showed one `<pre>` per overload. The printed page showed them adjacent; one block is better Markdown. Named here because it is a visible difference from the published page.
- **`T-System.GroupName` has no published declaration**, alongside the six operators the ticket named. It is a pre-3.0 security type.
- **The language of each code block is the heuristic's guess** (the sample came out 38 `d4`, 14 `text`). The real runs should pass `--code-table` and review it, as `docs-convert-asciidoc` did.

## Tripwire parked in the code

`substitute_placeholders` in `reference_split.py` re-derives the chunk's parent map once per placeholder; a `NOTE:` at that site says the largest chunk here has about 36 and what to do if a future source brings hundreds into one section.
