## What landed

`samples/Sample.Shipping/Source/Shipping.csproj` is now an SDK-style project, so the build compiles `Alphora.Shipping.dll` and the layout assembles the sample library again. Nine files changed; no line of `Coordinate.cs`, `Domains.cs` or `Register.cs` was touched.

- **The project file**, rewritten the way `AGENTS.md` *Converting another project* describes: `AssemblyName` `Alphora.Shipping`, `RootNamespace` `Shipping`, `OutputType` `Library`, `AllowUnsafeBlocks` kept (the legacy project had it, and `Coordinate.cs` has three `unsafe` members - its conveyor reads and writes the row buffer through pointers), `DefineConstants` `TRACE` in both configurations plus `DEBUG;TRACE` in Debug (legacy Release was `TRACE;SIGNASSEMBLIES`), explicit `Compile` items for the four source files in legacy order, and the five project references the legacy file had (Base, DAE, Server, `DAE.Connection`, `DAE.Device.SQL`). No `.resx` and no package references, so none of the resource-naming care other conversions needed applies. The `None` items for `Shipping.d4`, `Shipping.tsql` and `CoverageRoles/*.d4` went with the rest of the legacy boilerplate; those files are untouched on disk and nothing compiles them.
- **`Properties/AssemblyInfo.cs`** trimmed to `AssemblyTitle`, `AssemblyDescription` and `DAERegister`, like every converted project's. Version, company, product, copyright and signing come from `Directory.Build.props`.
- **Wiring**: a `/samples/` folder in `Dataphor.slnx` holding the project; the project in `tools/layout/Layout.csproj`'s Library list with the `DataphorD4Library Remove` line for `Sample.Shipping.d4l` deleted; `Alphora.Shipping` added to the `reported` list in `tools/coverage-report/areas.json` (AGENTS.md requires an entry for every new assembly - see *Judgement calls* below).
- **The two test lists the conversion falsifies**: the `Sample.Shipping` entry in `SamplesCorpusTest` moved from `NotInTheRuntimeLayout` to `NeedsADatabaseServer` with the reason the two entries beside it use, and `NotInTheRuntimeLayout` is now an empty dictionary with a `<remarks>` saying why it is kept. `FormCustomizationTest.LibrariesNotCarried`'s reason for the sample is now "requires a SQL Server device", the same wording as its `Sample.Forum` neighbour.
- **Docs**: AGENTS.md (the converted list, the sample-corpus paragraph's three lists, and the runtime-layout paragraph, which now leaves out two libraries rather than three) and `docs/modernization-plan.md` (the WS7 table has a `library-sample-shipping-convert` row marked Done, plus the WS3 `test-samples-corpus` row's list description and the `build-runtime-layout` item's exclusion sentence).

## How to check it

- **Build**: `dotnet build Dataphor.slnx -c Debug` and `-c Release`, both 0 errors, 144 warnings (the same count as before this change). `artifacts/layout/debug/Libraries/Sample.Shipping/` and the release one each hold `Sample.Shipping.d4l`, `Documents/` and `Alphora.Shipping.dll` with its `.pdb`.
- **The layout check is the interlock.** Removing the `DataphorD4Library Remove` line without adding the project to the Library list fails the build on `Sample.Shipping.d4l`'s `Alphora.Shipping.dll`; adding the project without removing the exclusion fails on "builds library Sample.Shipping, which the DataphorD4Library list leaves out". Either half alone is a build error, which is what makes the two agree.
- **Targeted tests run** (Debug, `--no-build`): `dotnet test tests/DAE.Server.Tests --no-build --filter "FullyQualifiedName~SamplesCorpusTest|FullyQualifiedName~FormCustomizationTest|FullyQualifiedName~FormDocumentCorpusTest|FullyQualifiedName~HostProgramTest"` - 119 of 119 passed in 47 s, with `Sample.Forum`, `Sample.Pubs` and `Sample.Shipping` reported Inconclusive for the database-server reason and `EverySampleIsAccountedFor` green. That last case is the whole verification of the list edits: it holds the lists against the tree in both directions, so it fails if `Sample.Shipping` is in the wrong list, in two lists, or in none.

## Known gaps - please probe these

- **The sample's own registration is unproved on .NET 10.** Nothing in the suite can register it: `Sample.Shipping.d4l` requires `MSSQLDevice` and `Documents/Schema.MSSQLDevice.d4` creates a SQL Server device against `'ServerName'='.'` with database `Shipping`, which no machine in CI or here has. So "the assembly builds, ships and sits in the layout" is what landed; "the library registers and derives forms" is still owed, and `test-device-live` owns it. The `NeedsADatabaseServer` accepted-tradeoff `NOTE:` was widened to say three samples sit there now, and it still attributes the 54.6 s only to the two that were measured.
- **`Register.cs` was read, not tested.** `DAERegister.GetClasses()` builds its aliases as `"Shipping." + Schema.Object.Unqualify(type.Name)` by reflecting over the assembly's types, so the alias strings the sample's `.d4` documents name in `class "..."` follow from the type names, and no type name changed. Verified by inspection only - nothing in the suite registers this sample, which is the gap above.
- **No new test, deliberately.** The conversion ports no behaviour (the project rules' characterization-test requirement is for a subsystem being ported or re-hosted), and the two list edits are exactly what the existing `EverySampleIsAccountedFor` and `FormCustomizationTest` assertions already demand: the suite fails without them and passes with them.
- **No migration note.** Checked: no public type or member changed, no file format, no class name, no port. The assembly simply ships again, at 4.0.0.0 like every other converted assembly, which `docs/migration-notes.md` already records for the set ("the rest follow as they are converted").

## Judgement calls worth a second opinion

- **`Alphora.Shipping` on the coverage report's `reported` list.** The ticket did not mention `tools/coverage-report/areas.json`, but AGENTS.md says every new assembly goes on one of the three lists or a collected run that loads it makes the report suppress itself and exit 1. `ignored` is defined as "anything whose source is under `tests/`", which a sample is not, so it went on `reported` - the first sample assembly there. It is absent from every run today (the sample never registers), and `reported` entries are rolled up but never gated, so the entry is inert either way. If a reviewer would rather samples were their own group or ignored, that is a one-line change plus a sentence in that tool's README.
- **Where the empty `NotInTheRuntimeLayout` list is explained.** Kept as an empty dictionary with a `<remarks>`, as the ticket directed, because the list is asserted against the tree in both directions and a future unconverted sample belongs in it.
- **The `/samples/` solution folder** is new in `Dataphor.slnx`; the alternative was putting the project under `/libraries/`, which would have misdescribed it.
