## What landed

Two nodes in `src/engine/DAE/Runtime.Instructions/RowComparisonNodes.cs` joined the const-operand rule that `docs/architecture/operand-ownership.md` describes, and a reflection test now holds the list of nodes that owe that rule by hand.

**`RowEqualNode`** - what `=` and `<>` between two rows compile to, and therefore what a transition constraint, a key comparison and `in` over a row-valued list compile to:

- `DetermineDataType` calls `base.DetermineDataType(plan)` instead of `DetermineModifiers(plan)`. That is the only path that reaches the `const` branch of `InstructionNodeBase.DetermineDataType`, which is the only place that asks an argument node to lend the value it already holds (`PlanNode.SetByReference`). Everything after that line is unchanged.
- `InternalExecute(Program)` is now an ownership wrapper: evaluate the left, evaluate the right inside a `try` whose `catch` releases the left where this node owns it, then compare inside a `try` whose `finally` releases each side where `Nodes[index].ReturnsByReference` is false. The comparison itself - nil propagation, the `_comparisonNode` stack push, the run-time branch - moved into a private `InternalCompare(Program, object, object)`.
- The run-time branch (either operand's type a generic `row`, which `operator F(const A : row, const B : row)` produces) builds its inner `RowEqualNode` over a new private `BorrowedValueNode` rather than `ValueNode`, so the inner node leaves alone the two values the outer one still owns. A `NOTE:` at that class records the wider answer deliberately not taken here - a `SetByReference` on `ValueNode` itself, which would be cheaper and is probably right, but whose blast radius is every call in the engine with a literal argument.

**`CompoundScalarEqualNode`** - the equality the compiler generates for a scalar type whose single representation has more than one property (`Compiler.CompileComparisonOperator`, which declares both operands `const`; verified in `Compiler.cs`): the same two halves, with the nil propagation moved inside the `try` so a nil on one side still releases the other, and each `DataValue.FromNative` wrapper now held as `IDataValue`, cleared of `ValuesOwned` and disposed in a `finally`.

**The guard.** `tests/DAE.Server.Tests/OperandOwnershipShapeTest.cs` reflects over the engine assembly for every non-`TableNode` subclass of `InstructionNodeBase` that declares `InternalExecute(Program)` itself, and compares the set with a checked-in list of eighteen names. It matched exactly on the first run - the five argument shapes plus the thirteen reviewed nodes, as the architecture page says. Its two failure messages tell a node's author what to do: apply the rule and add the node to the list, or remove a node that no longer has the shape. No server and no base class.

`docs/architecture/operand-ownership.md` and `docs/migration-notes.md` are updated.

## Tests added, and what each verifies

- `AssignmentValueOwnershipTest.RowEqualityReleasesTheRowsItCompares` - four shapes through `AssertShapeLeavesNoStreams`, each naming itself. The computed rows verify the release half; the row variable verifies the asking half (either half alone fixes only one of the two); the two-column row verifies the per-column arithmetic; the generic `row` operand, through a `ZGenericRowsEqual(const ALeft : row, const ARight : row)` the case creates, verifies the run-time branch and so `BorrowedValueNode`. Each shape also reads its own result, so a comparison that silently stopped happening cannot pass vacuously.
- `AssignmentValueOwnershipTest.RowEqualityGivenVariablesLeavesTheCallersRowsAlone` - the loan, which the count cannot see: lending without releasing and releasing without copying both balance the count. Two row variables, so each argument node is a separate loan; asserts the comparison answered true every time and that both rows' columns are still readable after the loop. Modelled on `IfNilGivenAVariableLeavesTheCallersValueAlone`.
- `AssignmentValueOwnershipTest.CompoundScalarEqualityReleasesTheValuesItCompares` - a `ZCompoundBinary` type with a `Binary` and an `Integer` property, compared as computed values and from a variable, with the result read both times and the variable's property read afterwards. `tests/libraries/TestFramework.Coverage.Scripts/Documents/Types.CompoundEquality.d4` is left untouched: it is all-`Integer` and cannot see a stream leak at all.
- `OperandOwnershipShapeTest.TheNodesOutsideOperandCleanupAreTheOnesReviewedForIt` - the class guard above.

No other tests were added. The `<>` shape routes through the same node as `=` and the existing coverage scripts exercise it.

## Known gaps, honestly

- **The architecture page was trimmed to fit its cap, not only added to.** It was 1,417 words and the additions took it to 1,597, over the 1,500-word limit. Rather than split a page whose subject is one subject, existing prose was condensed: the thirteen node names with their file names became three names plus a sentence (the test now owns that list, so the page no longer needs to enumerate it), and the lend-or-compute restatement in the first section lost a sentence that the "How a node says it is lending" section states in full. No fact was dropped, and the page is now 1,498 words - which is six words of headroom, so **the next ticket to add to this page will have to split it.** Worth a reviewer's eye on whether anything another ticket wanted recorded went with the trim.
- **`ValuesOwned = false` on the two `FromNative` wrappers is belt and braces, not load-bearing.** The implement ticket said `FromNative` returns a wrapper with `ValuesOwned` true; it does not - `Row`'s `NativeRow` constructor clears the flag itself (`src/engine/DAE/Runtime.Data/RowValue.cs`). The clear is kept because it is the flag the new `Dispose` reads and the invariant deserves saying, and the comment says so rather than repeating the ticket's claim. A reviewer may reasonably judge it redundant.
- **`BorrowedValueNode` has no parameterless constructor**, so `PlanNode.Clone()` - which is `Activator.CreateInstance(GetType())` - would throw on one. It is built inside `InternalExecute` and discarded, never stored in a plan, so nothing clones it; that is an argument from inspection, not a guarantee the type system makes.
- **The reflection test compares simple type names**, not full names. Two engine types sharing a simple name would collide in the list. There are none today - the set matched the eighteen exactly - but a reviewer could prefer `FullName`.
- **The 1,769-line fixture was not split**, deliberately: a reorganisation that size does not belong in a leak fix, and two backlog tickets already anticipate it. Its head `NOTE:` was corrected, as the implement ticket asked, to name `bug-a-cursor-loop-variable-stays-stale-once-written` and `bug-a-loop-over-a-read-only-parameter-orphans-a-computed-argument` as the tickets still holding the split open, instead of this one.
- **Not widened to the `CallNode` operand seam.** `bug-a-loop-over-a-read-only-parameter-orphans-a-computed-argument` (backlog) is at that seam; this change is two nodes that never joined the rule, plus the guard.
