## What changed

A scalar type with one multi-property representation and no equality operator of its own gets a generated `iEqual` implemented by `System.CompoundScalarEqualNode`. Its `DetermineDataType` (`src/engine/DAE/Runtime.Instructions/RowComparisonNodes.cs`, the `USENAMEDROWVARIABLES` branch around line 261) pushed the right operand's row under an empty name, while the row-equality expression it compiles refers to `right.<property>`, so compilation failed with `Unknown identifier "right.Degrees"`. It now pushes `Keywords.Right`, matching the left side, the class's own `InternalBindingTraversal`, and the sibling `RowEqualNode`. One line changed; the file keeps CRLF, tabs and no byte-order mark.

This never worked on 3.1 (tag `v3.1` has the same line); the fix only makes previously rejected code compile, so no migration note.

Its manifest entry flipped from `known-failure` to `pass`.
