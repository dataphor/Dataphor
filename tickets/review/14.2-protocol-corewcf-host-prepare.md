## The one test

`tests/DAE.Server.Tests/InstanceConfigurationTest.cs` — `LoadReadsAFileCarryingSettingsThatNoLongerExist`.

It writes a literal `ServerConfigurations.config` as an earlier release would have written it — one instance element carrying name, port number, both listener settings, both secure-connection settings, instance directory, two library directories, catalog store class name and connection string, **plus** `useserviceconfiguration`, `allowsilverlightclients` and an invented `neverexisted` attribute — loads it through `InstanceConfiguration.Load`, and asserts the instance is there and every one of its surviving settings holds the value in the file.

Why it is worth its run time: it is the only compatibility claim this ticket makes, and it is the rule for every later removal from that file (`host-instance-configuration` says so explicitly). The invented third attribute is deliberate — the claim is about any attribute the class does not declare, not about the two just removed. The file content is a literal rather than something the serializer produces, so that a future drift in BOP's element or attribute naming fails this test instead of hiding behind a round trip; the literal was taken from a real `InstanceConfiguration.Save` of an equivalent configuration, so it is the genuine on-disk shape.

What it does *not* test, deliberately: that the two properties are gone (the compiler says so), the checkboxes, or the file moves.

**The mechanism behind the claim, since the test asserts the outcome and not the path:** `Deserializer.ReadObject` catches the "member not found" error per attribute, adds it to the deserializer's `Errors` list and carries on; `InstanceConfiguration.Load` never looks at `Errors`. The attribute disappears from the file the next time the instance list is saved, because the serializer writes properties and there is no longer one — by inspection, not tested, since that is the serializer's defined behaviour and not this change's.

## How to exercise it

```
dotnet build Dataphor.slnx
dotnet test tests/DAE.Server.Tests --no-build --filter Name=LoadReadsAFileCarryingSettingsThatNoLongerExist --logger "console;verbosity=normal"
```

10 ms. No server, no ports, no machine-wide state: it writes one file under this process's folder in `%TEMP%\Dataphor.Tests\` and deletes the folder afterwards.

To see it fail, break the claim from the other side: make `InstanceConfiguration.Load` throw when the deserializer's `Errors` list is non-empty, and the case fails on the invented attribute.
