No hit anywhere in `libraries/`, `samples/` or `tests/`.

**No D4 class name disappears.** Read both `DAERegister.GetClasses()` methods (`src/engine/DAE/Register.cs:20`, `src/engine/Server/Register.cs:20`). Both still register exactly the subclasses of five base types: `PlanNode`, `Schema.Device`, `Conveyor`, `Schema.DeviceOperator`, `Schema.DeviceScalarType`. Traced each deleted class's declared base, by declaration and not by file name: `IndexList` has no base; `TemporaryStream : Stream` (the framework stream); `CopyOnWriteStream : StreamBase`, and `StreamBase : Stream` at `src/engine/Base/StreamUtility.cs:228` — a `Stream`, not a `Conveyor` (`Conveyor : IConveyor`, `src/engine/DAE/Streams/Conveyor.cs:29`); `DebugContext` has no base and `DebugContexts : Stack<DebugContext>`; `GenericDotNetConnection : DotNetConnection : SQLConnection : Disposable`. None of the five is a subclass of a registered base type, so no `create device … class "…"` and no device `ConnectionClass` setting could ever have named one.

`DotNetConnection`, `DotNetCommand` and `DotNetCursor` — what a custom connection actually derives from — are untouched and still in `src/engine/Server/Connection/`.
