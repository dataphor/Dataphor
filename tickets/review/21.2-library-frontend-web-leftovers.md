## What was checked before deleting

- **The two reference greps, over the whole tree with `legacy/` excluded.** `LinkTable` appears only in `Application.cs` and in `LinkTable.cs` itself (plus this ticket's own text and its run log). `FrontendUtility` and its one constant `CXmlContentType` appear only in `Customizer.cs` and in `FrontendUtility.cs` itself. So the two files that did not use `System.Web` were reachable only from the seven that did, and the set of nine is closed.
- **No project compiled any of the nine.** `Frontend.Server.csproj` listed 17 `Compile` entries and none named one of them; a grep of every `.csproj` and the `.slnx` for each of the nine basenames found no entry for any (the `Application` hits are MSBuild properties like `ApplicationVersion` and unrelated files named `ApplicationForm.cs`, `ApplicationTransaction.cs`, `ApplicationNode.cs`, `ApplicationListForm.cs`). After the deletion the project's compile list and the `.cs` files beside it agree exactly: 17 and 17.

## No migration note is owed, and why

All nine declared public types in `Alphora.Dataphor.Frontend.Server` and `Alphora.Dataphor.Frontend.Server.Customization`, and the assembly they would have belonged to, `Alphora.Dataphor.Frontend.Server`, does ship. But they were in no compile list, so none of those types was in the built assembly before this change either - the compile-list parity check above is the proof. No public surface a customer's C# extension could have bound to changed, so `docs/migration-notes.md` has no entry. This is the one claim in this ticket worth re-checking, because "we deleted nine files of public classes from a shipped library" reads like something that should carry a note.

## What was deliberately left alone

- **`Source/app.config` and `Source/EveryNode.dil`.** `app.config` names `.NETFramework,Version=v4.5.2` and nothing reads it; `EveryNode.dil` is a form-document fragment nothing in the tree references. Both are strays rather than web leftovers, and `build-globbing-cleanup` owns strays. Their survival is not a judgment that they are needed - the `build-globbing-cleanup` bullet in `tickets/backlog/debt-ws12-hygiene-remainder.md` now names them so that arm picks them up.
- **`libraries/Frontend/Documents/Web.NodeTypes.dnt`.** A published `.dnt` document, which is a compatibility surface, and `hygiene-retire-web-silverlight-client-types` in the same backlog ticket already owns it together with the `ClientTypes` rows in `Register.d4`. It should go, but with those rows and with the migration-notes line that arm already specifies - not here, where the blast radius is different.
- **`docs/architecture/frontend.md`.** The page is nine lines and says nothing about the web leftovers, so nothing in it became untrue and nothing was added: a page does not need a sentence about files that no longer exist. The docs size check was run anyway (`13 files checked, 0 over the limit`).
