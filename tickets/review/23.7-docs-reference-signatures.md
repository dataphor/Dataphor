## What landed

`ReferenceSignatureGoldenTest` (new, in `tests/DAE.Server.Tests`) starts an in-process server with **no library at all** — empty `Libraries`, empty `LibrariesToRegister`, so the System set is a function of the engine — asks it for every System operator's and scalar type's D4 declaration through the shipped `System.Script` operator, compares each with a checked-in file under `tests/goldens/reference/system-library/`, and then compares that file with the matching block of the published 3.x reference page.

- **331 golden files**: 311 operator declarations (297 operator pages plus the 14 type names that are not also operator pages), 19 scalar type declarations, and `operator-inventory.txt` — 598 lines, one per System operator name, with its overload count and whether a page documents it.
- **`DATAPHOR_UPDATE_REFERENCE_GOLDENS=1`** writes them, deletes what nothing produces, and then fails the run anyway, like the two existing update variables.
- **Three cases**, all green: `EveryPublishedSignatureAgreesWithTheCatalog` (0.8 s), `TheSameCatalogAlwaysGeneratesTheSameDeclarations` (3 s), `ScriptingAScalarTypeWithNoSpecialsReturnsItsDeclaration` (11 ms). The class name starts with R, so it lands in the first of the five suite parts (the whole-solution one).

**An engine defect fixed along the way.** `Script` on a scalar type with no special values threw a `NullReferenceException` from inside `Schema/Catalog.cs`: `EmitChildren` passed the type's null `IsSpecialOperator` straight to `EmitDependencies`, which dereferences what it is given. `Script('System.Boolean')` and `Script('System.Scalar')` were both affected, and so was any script of a library or catalog containing such a type. Guarded at the site; the same unguarded call is at `418a5d45`, so the defect is older than this port. Reproduction: `ScriptingAScalarTypeWithNoSpecialsReturnsItsDeclaration`. Entry added to `docs/migration-notes.md`.

**One page corrected.** `docs/reference/system-library/operators/System.RequiredObjects.md` carried `System.RequiredLibraries`' two declarations — a conversion error, not a product difference. Replaced with `RequiredObjects`' four, written in the same published style as its sibling `System.DependentObjects`.

**Documentation.** `docs/modernization-plan.md` gains *Design notes, the reference generator* (six paragraphs: the decision, the evidence, what is given up, the corrected premise, what the comparison found, why the pages stay the 3.x record) and its WS8 design-notes sentence about the parked library getting a Markdown emitter is corrected. `docs/reference/README.md` and `docs/reference/system-library/README.md` lose the "`docs-reference-generator` will emit signatures from a running server" promises; the latter gains a *What the running product says* section telling a reader which pages are current and which to read the golden for instead. `AGENTS.md` gains the fixture and the variable (and its "four other variables" becomes five; the parser corpus count 387 becomes 696). `docs/contributing/build-and-test.md` gains a *Rewriting the checked-in comparison files* section covering all three update variables, none of which it documented before.

**`.gitattributes`.** The goldens tree is pinned `text eol=lf`; these files are the emitter's own output and `TextEmitter.NewLine` writes CRLF, so `tests/goldens/reference/** text eol=crlf` is added after it, with the reason. Verified with `git check-attr text eol`.

## The finding

Of the 290 operator pages with a declarations block, **214 agree** with a bare 4.0 catalog after normalization and 76 do not; of the 19 type pages with a declarations block, 15 agree; all 19 published *type declarations* differ.

Every one of those differences was traced to a change that had already landed by `418a5d45`, the commit this branch starts from. **No documented System operator signature was changed by this port.** The measurements behind that, each re-checkable:

- `src/engine/DAE/Schema/DataTypes.d4` is **byte-identical** to `418a5d45` (`diff` against `git show 418a5d45:Dataphor/DAE/Schema/DataTypes.d4`).
- `SystemCatalog.d4` differs from `418a5d45` **only** by the two `iRedefine` operators `debt-unreachable-redefine-nodes` removed. Neither has a reference page (checked), and both are already in `docs/migration-notes.md`.
- `D4Emitter.EmitListTypeSpecifier`, which writes `list` where the 2007 tool wrote `generic list`, is byte-identical at `418a5d45`. `Parser.ListTypeSpecifier` accepts both spellings and builds the same specifier with `IsGeneric` set, so the two denote the same type.
- `System.Date` carries all three of its static tags in the 2008 open-source import (`361ebd83`) where its page shows one; `System.ToByte(String)` gained `DAE.IsUniquePreserving` between `361ebd83` and `418a5d45`. So the pages' tag lists are older than the product, not different from it.
- `System.GroupName`'s `create type` is inside a block comment in `SystemCatalog.d4`, and equally commented out at `418a5d45` — the type has not existed since before 3.1.

The 76 fall into five families, each defined once on `ReferenceDifferenceFamily` with its measurement: tags older than the product (46 entries), the untyped-list spelling (13), an operator body emitted as stored source text rather than as the compiled tree (7), overloads the 2007 help file did not list (13 — the `Money` and `Long` arms of the arithmetic and aggregate operators, the `String` arms of `IndexOf`/`LastIndexOf`, one extra arm of `ToList`), and the copy-script shape of a type declaration (19). Some entries carry two families.

## Deviations from the implement ticket — read these first

The ticket was unusually specific and three of its premises turned out to be wrong when measured. The central decision it made (a test fixture in `DAE.Server.Tests`; `legacy/libraries/Documentation` stays parked) is unaffected and was implemented as written. These are the places where the work departed from the text, each a judgement a reviewer may want to overturn:

1. **`Script` is not "exactly, line for line" what the parked library did.** The ticket said `DocOperator.WriteDocbookDeclarations` calls `program.Catalog.EmitStatement(..., ForCopy, ...)` like `SystemScriptNode`. It does not: it calls `objectValue.EmitStatement(EmitMode.ForCopy)` — the object's own emit, not the catalog's (`legacy/libraries/Documentation/Source/Samples.cs:439-467`). For an operator the two give the same text; for a scalar type neither reproduces the published shape. The parked library also writes no statement terminator, where every published block has one, so the published blocks were produced by the 2007 publishing tool and not by that library at all. The plan text records the corrected version.

2. **`Operators.Name` is not the signature-qualified name.** The ticket said it is, and that it is "the name `Script` needs". It is the catalog's own mangled object name — `System.Abs0000000643`. `Script(Name)` does resolve it (the `Name` overload goes through `ResolveCatalogIdentifier`, which resolves exactly that), so the query the ticket wrote is correct, for a different reason than it gave. The signature is in the separate `Signature` column (`(System.Decimal)`), which would have to be concatenated with `OperatorName` to build a specifier for the `String` overload. Measured in a throwaway probe before the fixture was written.

3. **A fifth verdict, `PreThreeOne`, was added, and this is the biggest call in the ticket.** The ticket's four verdicts are `Stale` ("no catalog has ever had this"), `Changed` ("the signature changed between 3.x and this port"), `Defect` and `Unread`. 75 of the 76 differences are none of those: the page is *faithful to 2007* and the product moved on during 3.x, before this port began. Forcing them into `Stale` would have meant rewriting about 45 pages to add computed metadata tags — and `Changed` would have meant 45 migration-note entries for changes this release did not make. `PreThreeOne` says what is true and is the verdict that carries the compatibility conclusion. **If a reviewer rejects the fifth verdict, the consequence is item 4, not a different measurement.**

4. **The pages were not rewritten.** The ticket says "For `Stale`, correct the page", and only `System.RequiredObjects` was corrected. The reasoning, which is the ticket's own: *"overwriting all 290 blocks with generated text would compare 4.0 against 4.0 on the next run and prove nothing"*, and the plan is explicit that the published signatures are the baseline this work item measures against. Two sub-cases are worth a second opinion:
   - The **13 pages that omit overloads** (`Abs`, `Avg`, `Ceiling`, `Floor`, `Frac`, `Max`, `Min`, `Sum`, `Truncate`, `iDivision`, `IndexOf`, `LastIndexOf`, `ToList`) are the ones where a reader is actively misinformed — they will not see that `Abs(Money)` exists. Instead of editing them, `docs/reference/system-library/README.md` now names those thirteen and says to read the golden. **A reviewer could reasonably decide the overloads should be added to the pages instead.** The counter-argument is mixed-vintage pages and a partly erased baseline.
   - The **46 tag-family pages** are a weaker case for editing: adding the engine's computed `DAE.*` tags makes the reference noisier for no compatibility gain.

5. **One test case, not ~310.** The ticket asked for "one case per documented name". `FrontendDerivationGoldenTest` is the precedent and its reasoning applies unchanged (the set comparisons need every page's answer, and a case that needed its siblings to have run first would give the wrong answer under the name filters `AGENTS.md` runs the suite with). The cost is that a failure names pages in its message rather than in the test name; the report lists up to 40.

6. **The type declarations are compared, but all 19 differ, and no structural comparison was built.** The ticket asked me to "check that a type's emitted `create type` matches the shape of the pages' type-declaration block". It does not, for a measured reason that is about the emitter rather than any type: `Catalog.EmitChildren` moves a representation out of the `create type` into an `alter type` of its own when it has external dependencies, which every System type's representations have (their properties are other System types). `ScalarType.EmitStatement(ForCopy)` drops them for the same reason, so **no shipped surface emits the published shape.** The 19 are recorded as `CopyScriptShape` entries rather than left as 19 unexplained differences, and the fixture fails the day one does agree. The alternative — a comparator that extracts `(representation, properties, selector class)` triples from both texts and compares those — would make the type half a real comparison and was judged out of scope; say so if you disagree.

7. **The goldens are in `ParserRoundTripCorpusTest`'s corpus** (387 cases → 696), because they carry the `.d4` extension and that pass walks the tree for `*.d4`. All 330 parse and round-trip. This was kept deliberately — it asks whether the catalog copy script the product generates can be read back, which is the property an administrator depends on — and both fixtures' remarks say so. The alternative is adding `tests/goldens` to that fixture's `ExcludedRelativeDirectories`, which is a two-line change if a reviewer prefers the passes uncoupled. Note the precedent on the other side: `FrontendDerivationGoldenTest` chose `.xml` over `.dfd` specifically to stay out of the `.dfd` walk.

8. **`operator-inventory.txt` has three columns**, not the ticket's two: name, overload count, and `documented`/`undocumented`. The third is what makes the 308 undocumented names greppable from the file itself.

9. **`System.iXor` is in the no-declarations list, making it eight pages, not the ticket's "seven operator pages and one type page".** The ticket named six operators plus `iXor` plus `GroupName`, which is eight; its prose said seven. The measured set is exactly those eight (`grep -L '^\*\*Declarations\*\*'` over both folders, minus the 25 category pages).

### Things worth trying by hand

- **The update path.** `DATAPHOR_UPDATE_REFERENCE_GOLDENS=1 dotnet test tests/DAE.Server.Tests --no-build --filter "Name=EveryPublishedSignatureAgreesWithTheCatalog"` must write 0 files, delete 0, and still fail. Delete a golden first and it must write exactly 1.
- **Each direction of each recorded set.** Five sets are asserted both ways and each is worth breaking on purpose: add a bogus entry to `Differences` (must fail: "matches no block of any page"); delete an entry for a page that differs (must fail with the first difference); add a page to `PagesWithNoDeclarations` that has a block (must fail); take `System.Scalar` out of `CatalogTypesWithNoPage` (must fail); delete a golden (must fail with the file name).
- **A new page cannot escape.** Drop a file into `docs/reference/system-library/operators/` named after a real operator with no declarations block and confirm the run fails rather than ignoring it. The category pages are read from the README's own link list, not from a hand-written list, so a new page that is not linked there is treated as an object.
- **The strictness of the page reader.** Break a page's fence (`**Declarations**` with no ` ```d4 ` under it) and confirm the run throws with the page name rather than comparing an empty block.
- **`Script` by hand**, to see what an administrator sees: `select Operators where Library_Name = 'System' add { Script(Name) Declaration } over { OperatorName, Name, Declaration } order by { OperatorName, Name }`. ## Tests added, and what each one verifies

| Test | What it verifies | Why it earns its place |
|---|---|---|
| `EveryPublishedSignatureAgreesWithTheCatalog` | Generated text equals its golden exactly; the golden equals the page's block after normalization unless a verdict records otherwise; and the five recorded sets agree with the tree in both directions. | This *is* the ticket. It is also the characterization test the project's testing rule asks for: the behaviour being re-hosted is the 3.x publishing tool's declaration generation, pinned against the one small fixed catalog of a bare engine. |
| `TheSameCatalogAlwaysGeneratesTheSameDeclarations` | Asking the same catalog twice, and a second independently built instance once, gives identical text. | The property every golden rests on, and it holds by measurement rather than by construction. A change that introduced a timestamp or made a tag collection iterate a hash table fails here rather than as a mismatch on all 331 files at once. |
| `ScriptingAScalarTypeWithNoSpecialsReturnsItsDeclaration` | `Script` returns a `create type` statement for `System.Boolean` and `System.Scalar` instead of throwing. | The reproduction of the defect this ticket fixed, at the lowest layer that shows it (a D4 expression on an in-process engine). It names the two types rather than relying on the corpus case failing, so it survives a redesign of the generation. |

No test was written for the goldens tree existing, for the update variable writing files, or for the normalizer in isolation — the first two are wiring and the third is exercised by all 330 comparisons.

## Known gaps and tripwires

Parked as tripwires, not tickets — each is recorded where a reader will meet it:

- **The 19 type-declaration entries** are the thing to revisit if a shipped surface ever emits the published inline shape, or if the reference is refreshed to 4.0. Recorded in the fixture's class remarks and in `ReferenceDifferenceFamily.CopyScriptShape`.
- **Whether the reference should track the product or stay the 3.x record** is a documentation-policy question nobody has needed to answer. Recorded in the plan's new design-notes block and in the fixture's remarks; the goldens are the text to answer it with.
- **The coupling to the parser corpus** is recorded in `ParserRoundTripCorpusTest`'s remarks.

Filed as a ticket: **`tickets/backlog/debt-misspelled-metadata-tags-are-silently-ignored.md`**. The classification turned up three misspelled `DAE.*` tag names in our own shipped D4, each of which the engine therefore ignores: `DAE.Functional` on `Insert`/`Remove`/`RemoveAt` and `DAE.IsRemotabe` on `Evaluate`/`EvaluateOn` (both in `SystemCatalog.d4`), and `DAE.IsFuntional` on `libraries/SimpleDevice/Documents/Register.d4:11`. Measured by listing every `DAE.*` name the shipped `.d4`/`.d4l` declare against every such name the C# reads; each correct spelling *is* read, which is what makes these misspellings rather than private tags. Filed at the **class** rather than as three point fixes, because the root cause is that nothing checks these names — which is also why they survived twenty years. Two caveats recorded on the ticket: **the impact is not measured** (`repro: static`; what the compiler actually decides differently for these five operators was not established, and that decides whether correcting them is safe at all), and a literal search also finds no reader for `DAE.IsBuiltin` and `DAE.Translate`, which the ticket must resolve — note that `DAE.AsString` and `DAE.AsDisplayString` are read through a name composed at run time (`ScalarType.cs:1504`, `String.Format("DAE.{0}", nativeAccessor.Name)`), so a check built on string literals will have false positives.

Left undone, deliberately:

- **No page was written for any of the 308 undocumented operator names.** `operator-inventory.txt` is the whole of what this ticket owes them; the reference admitting its own incompleteness is the deliverable.
- **The four undocumented scalar types** (`System.FileReference`, `System.LibraryDescriptor`, `System.LibraryReference`, `System.Scalar`) are a recorded list with a reason, not pages.
- **The system tables reference** is `docs-reference-generator`'s (the sibling ticket, which has this one as its `prereq`). Its `files:` already name `tests/goldens/reference/` and `docs/reference/system-library/README.md`; the generator machinery here — the strict page reader, the normalizer, the recorded-set-in-both-directions shape, the update variable — is what it builds on, and the golden tree's `reference/system-library/` prefix leaves room for a `tables/` folder beside `operators/` and `types/`.
