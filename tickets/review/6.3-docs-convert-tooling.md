## What was built

`tools/docs-convert/` converts `Documentation/` (75 AsciiDoc files) into Markdown laid out as `docs/`: Asciidoctor.js (DocBook 5 backend) → pandoc 3.14's DocBook reader → a Python pass over pandoc's JSON syntax tree (`convert.py`) → pandoc's `gfm` writer. `tools/docs-convert/README.md` documents prerequisites, commands, every transform, the report and the tables; read it first. Nothing under `Documentation/`, `legacy/Documentation/`, `book.json` or `docs/` was touched; the only edit outside `tools/docs-convert/` is the `AGENTS.md` `tools/` row.

- `package.json` + `package-lock.json` pin `@asciidoctor/cli` 4.0.0, `@asciidoctor/core` 3.0.4, `@asciidoctor/docbook-converter` 3.0.0 (`npm ci --prefix tools/docs-convert` verified). `requirements.txt` pins Pillow 13.0.0. pandoc 3.14 is not an npm package; on this machine it came from the portable zip (`--pandoc PATH`).
- `convert.py` (about 1,400 lines, standard library plus Pillow, imports `heading_slugs` and `extract_links` from `tools/docs-link-check/check_links.py`). Two entry points: the AsciiDoc route (`convert.py --out DIR`) and the standalone DocBook stage (`convert.py docbook FILE.xml … --out DIR`, resolution rules as options: `--pages`, `--base`, `--match-heading-text`, `--global-ids`, `--xref-fixes`, `--code-table`, `--legacy-html`).
- `pages.tsv` (75 rows, rule-seeded plus the ticket's hand-set rows), `xref-fixes.tsv` (9 rows settling 10 links), `code-blocks.tsv` (761 rows, seeded, all unreviewed), `legacy-links.tsv` (204 rows, generated), `index-extra.md` (the `## Project documents` section).

- Links: 660 resolved to pages, 10 external, 204 legacy (all with a target), **10 unresolved**. - Code blocks: 761 (seed tags: bnf 150, d4 468, text 138, xml 5, sql 0 — the SQL side of the D4-versus-SQL comparisons is written in lower case, so it seeds as `d4`).

## Numbers that differ from the ticket's survey, and why

- **204 legacy links, not 206; 203 pending, not 205.** Two of the 206 `.html` occurrences sit in broken markup in the operator-precedence table of `DevelopersGuide/D4LanguageElements.adoc`: `link:O-System.iIn.html[link:O-System.iIn.html[iIn]]` is one link, and a `||` cell (bitwise or, unescaped) shifts every later cell so the `iCompare` row is dropped. `docs-convert-asciidoc` (now in `implement/`) and the plan's `docs-convert-legacy-reference` row still say 205/206.
- **97 images converted and 10 unreferenced, not 98 and 9.** `UsersGuide/Aliases.adoc` line 45 has `image::../Images/DataphorServerLogin.bmp[…]` on the line straight after a paragraph, so AsciiDoc reads it as paragraph text (GitBook showed it as text too). The report's "AsciiDoc markup left as text" section lists it.
- **102 image macros reach pandoc, not 103** — the same line.

## Choices beyond the ticket's text (reviewer: accept or revert)

- `-a outfilesuffix=.adoc` is not passed: with the DocBook converter it has no effect (cross-references come out `File.xml#id` either way, verified), so the resolver reads `.xml` and `.adoc` alike. `-a reproducible` is passed so the DocBook carries no date.
- Asciidoctor writes image sizes as `contentwidth`/`contentdepth`, which pandoc's DocBook reader ignores; `read_docbook` renames them to `width`/`depth` before pandoc, which is what keeps the 48×48 status icons in `dataphor-service.md` sized.
- The 18 `[horizontal]` labelled lists come out of the DocBook backend as two-column tables (the `README.adoc` one as an HTML table); they are turned back into definition lists (pandoc table attribute `custom-style=horizontal`). This took the pages with HTML tables from 9 to 5 and is how `docs/README.md` gets the definition list the ticket expected.
- Definition-list terms are made bold: pandoc's gfm writer emits "term, hard line break, definition", which on GitHub is indistinguishable from prose otherwise.
- Sidebars (3) become block quotes instead of raw `<div class="sidebar">`. Table titles (4) become a bold paragraph before the table, like block titles; pandoc otherwise writes a pipe table's caption as a plain paragraph after it and an HTML table's as `<caption>`.
- Lists whose items are single paragraphs (with optional sub-lists) are written tight; pandoc otherwise writes every DocBook list loose.
- Zero-width spaces (Asciidoctor puts one after each `…`) are removed; index-term spans (1) are dropped.
- Nothing is written when the run has errors (an unresolved reference without `--allow-unresolved`, a code-table mismatch, an unreviewed row with `--require-reviewed`): exit 1, report only. Setup problems exit 2 with a one-line message.
- Unresolved links are written in the source's `File.adoc#Fragment` form (what the report prints), not Asciidoctor's `.xml`.
- A `--work DIR` the user names is never deleted.
- Report additions for `docs-convert-asciidoc`'s review: candidate replacements for each unresolved reference (in `xref-fixes.tsv` form), admonitions nested in list items (2; GitHub does not render those as alerts), AsciiDoc macros left as text (2), arrows Asciidoctor substituted for `<=`/`=>`/`->` in prose (5, on 2 pages), references matched only case-insensitively (1), repeated lines collapsed with `(xN)`.

## Known gaps

- No automated test, as the ticket decided: the converter's check is the link checker over its output plus the spot checks above. The functions most worth a test if it is ever rerun often: `page_name`, `guess_language`, `Resolver.find_heading`.
- The standalone `docbook` stage has only been run on Asciidoctor's DocBook 5, not on the legacy DocBook 4.3 (that is `docs-convert-legacy-reference`); pandoc's handling of 4.3 `xref`/`link linkend`, `refentry` roots and ids on non-heading elements is unexercised. Its default heading base (title in metadata → body shifted by one; title in the body → no shift) is the same rule as the AsciiDoc route.
- Fragment rule (b) normalises only ’ ‘ “ ” to ASCII quotes; other punctuation in a GitBook `Heading_Text` fragment must match exactly (no instance failed for that reason in this corpus).
- `legacy-links.tsv` line numbers come from the link checker's `extract_links` over the rendered page; a `NOTE:` at `legacy_rows` records the footnote-ordering caveat.
- The version check compares major.minor of pandoc and of each pinned npm package as installed; Node's own version is printed, not checked.
- An escape-sequence slip was caught during the work: an early version of `convert.py` held literal no-break and zero-width characters instead of `\u` escapes; the file is now ASCII-only (checked), and the characters it handles are written as escapes.
